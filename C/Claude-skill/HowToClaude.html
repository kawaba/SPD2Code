Claudeの"スキル"を使ってCコードを生成する方法

構造化プログラム設計図（SPD：Structured Programming Diagram）を読み込ませ、C言語入門者向けのソースコードを生成するスキルを、Claude（ウェブ版の claude.ai）に登録して使う方法を解説します。

SPDを貼らない依頼（コードの提案、要件定義からの仕様書作成）にも、同じスキルで対応します。どちらの使い方になるかは、入力にSPD記号（│ ├─ └─ ◇ ↻）が含まれるかどうかで、AIが判定します。

スキルは、無料プランでも使えます。登録する前に、下の「2. 準備」の設定をしてください。

1. スキルファイルの構成

スキルは、1つの zip ファイル spd-to-c-generator.zip にまとめてあります。こちらから spd-to-c-generator.zip をダウンロードしてください。SPD2Code-main.zip をダウンロードして解凍した場合は、その中の C/Claude-skill フォルダにあります。

zip ファイルは解凍せずに、そのまま登録します。 zip の中身は次のとおりです。

spd-to-c-generator
├─SKILL.md                # 全体の制御と、いつも使うルールを定義する指示書
└─references              # 必要なときだけ読むルール（節ごとに分けたファイル）
    ├─08-libraries.md     # 利用可能な外部ライブラリ（CP932の変換・utf8proc・raylib）
    ├─14-…〜18-…md        # SPDの変換ルール（制御構造・構造体・関数定義・Cコード生成規約・変換例・複数ファイル構成）
    └─21-normal-mode.md   # 通常モード（コードの提案・仕様書のテンプレート）

各ファイルの役割

  • SKILL.md:
    　AIがいつ・どのようにこのスキルを起動し、どのファイルを参照してコードを生成すべきかを指示する中心的な台本です。SPDの未記入部分は生成しないという最優先ルール、全モード共通のルール（回答スタイル、コーディングスタイル、入出力、メモリとポインタ、エラー処理など）、SPDの記号一覧と読み方、生成時のチェックリストもここにあります。
  • references フォルダ:
    　その他のルールを、節ごとのファイルに分けたものです。AIは、SPDや依頼の内容に合わせて、必要なファイルだけを読みます。1回に読む量が少なくなるので、使用量の上限に達しにくくなります。

2. 準備（最初に1回だけ）

スキルは「コード実行とファイル作成」の機能を使って動きます。この機能をオンにしておきます。

  1. claude.ai にログインし、左下のアカウント名から Settings（設定） を開きます。
  2. Capabilities（機能） を開き、Code execution and file creation（コード実行とファイル作成） をオンにします。

コードが崩れて表示されるとき（Edge）

生成されたコードの改行がつながったり、return が「帰還」、printf が「印刷f」のように変わって表示されたりする場合は、ブラウザーの翻訳機能がページを機械翻訳しています。コピーボタンでコピーしたコードは正しいので、コード自体には問題ありません。Edge では、次の手順で英語のページを自動で翻訳しないようにします。

  1. アドレスバーに edge://settings/languages と入力して開きます。
  2. 「常に翻訳する言語」などの一覧に「英語」（「英語 (米国)」なども）があれば、すべて削除します。

3. スキルの登録手順

  1. Customize（カスタマイズ） の Skills（スキル） を開きます。
  2. ＋ を押し、Create skill（スキルを作成） → Upload a skill（スキルをアップロード） を選びます。
  3. ダウンロードした spd-to-c-generator.zip を選びます。
  4. スキルの一覧に spd-to-c-generator が表示され、オンになっていれば登録完了です。

画面の項目名は、表示の言語や画面の変更によって、上と少し違うことがあります。

スキルを新しくするとき

変換ルールが新しくなったときは、一覧から古い spd-to-c-generator を削除してから、新しい zip を登録します。

4. スキルの利用方法

基本的な使い方

  • SPDモード（主な使い方）：チャットに、SPDのテキスト、または先頭のブロックコメント（/* ... */）にSPDを書いたCファイルを貼り付け（または添付し）、コードの生成を依頼します。main 用と関数用など、複数のSPDをまとめて貼り付けてもかまいません。
  • 通常モード：SPDを含まない依頼（C言語でのコードの提案、質問、要件定義からの仕様書作成）も、同じスキルで扱えます。

AIは依頼の内容を見て、自動でスキルを使います。確実に使わせたいときは、依頼文の中でスキルの名前を挙げます。

プロンプト例：
「（SPDを貼り付けた後、）このSPDをもとに、Cのソースコードを生成してください」
「（要件定義を書いた後、）spd-to-c-generator スキルを使って、この要件定義からC言語の仕様書を作成してください」

期待される動作

  1. AIが SKILL.md の指示を読み、入力にSPD記号があるかどうかで、SPDモードと通常モードを切り替えます。依頼の内容に合わせて、references フォルダの必要なファイルを読みます。
  2. SPDモードでは、コードを書く前に 未記入判定: の1行（◇ があれば ◇判定: の1行も）を出力します。SPDに未記入の部分があれば、その関数は生成せず、コメント1行で知らせます。SPDはファイル先頭のブロックコメントに原文のまま残し、その下にCコードを出力します。
  3. 入力には scanf ではなく input.h の関数を使い、コンソールに出力するプログラムでは main 関数の最後に wait_enter(); を入れます。
  4. 識別子の誤記や見つからない名前があれば、コードの後の「生成後の報告」で知らせます。

注意点

  1. 一回に1つのSPDから1つのコードを生成してください。
  2. ただし、コード生成に必要な他のファイル（ヘッダファイルや、別の .c ファイルなど）がある場合は、チャット欄にそれらを先にアップロードしておきます。
  3. Python のスキルも登録している場合、要件定義から仕様書を作る依頼では、Python のスキルが選ばれることがあります。依頼文に「C言語の」と書くか、スキルの名前を挙げてください。
  4. 無料プランでは、使用量に上限があります。1つの会話が長くなるほど使用量が増えるので、別の作業に移るときは新しいチャットを始め、必要なファイルをアップロードし直してください。
