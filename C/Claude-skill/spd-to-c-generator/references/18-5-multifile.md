### 18.5 複数ファイル構成での #include とヘッダファイル生成

ポーカーのように、**複数の `.c` と `.h` に分かれたプロジェクト**では、SPDに `#include` を書く規定がない。
そのため `#include` 文は生成側が**ソースを読んで決める**。さらにヘッダファイル（`.h`）では、
対応する `.c` のプロトタイプ宣言も生成する。判断は推測ではなく、以下の決まったルールで機械的に行う。

#### 18.5.1 基本原則：使うものだけをインクルードする（IWYU）

そのファイルが**自分で定義していないのに使っている識別子**（型・関数・マクロ・列挙子）を
一つずつ拾い、それを宣言しているヘッダだけを `#include` する。
推移的に得られるものは書かない（直接使うものだけを書く）。

> 例: `game.c` が `game.h` を include すれば、`game.h` 経由で `deck.h`/`hand.h`/`card.h` も入る。
> そのため `Deck` 型や `clearHand` のために改めて `deck.h`/`hand.h` を書かない。

#### 18.5.2 `.c` ファイルの `#include` 生成規則

次の順で並べる（この順にするとヘッダの過不足チェックにもなる）。

1. **同名ヘッダを最初に書く**。`card.c` → `#include "card.h"`。
   （対応するヘッダがある場合は必ず先頭に置く。）
2. **標準ライブラリ**。実装本体で使う関数から逆引きする（下表）。
3. **他モジュールのヘッダ**。実装内で呼ぶ関数・使う型のうち、同名ヘッダに含まれないもの。
   例: `game.c` は `evaluateHand` を呼ぶ → `#include "poker.h"`。

#### 18.5.3 標準ライブラリの逆引き表

| 使っている関数・機能 | 補うヘッダ |
|---|---|
| `printf` / `sprintf` / `fprintf` / `fopen` / `fgets` など | `<stdio.h>` |
| `malloc` / `calloc` / `free` / `rand` / `srand` / `qsort` / `atoi` | `<stdlib.h>` |
| `strcpy` / `strcat` / `strcmp` / `strlen` / `memcpy` | `<string.h>` |
| `bool` / `true` / `false` | `<stdbool.h>` |
| `sqrt` / `round` / `pow` など | `<math.h>` |
| `time` / `clock` | `<time.h>` |

#### 18.5.4 ヘッダファイル（`.h`）の構成

ヘッダは次の**3ブロック**で生成する。

1. **インクルードガード**：ファイル名から生成する（`card.h` → `CARD_H`）。
   ```c
   #ifndef CARD_H
   #define CARD_H
   /* ... */
   #endif /* CARD_H */
   ```
2. **型・マクロ・列挙の定義部**：これは**SPDに書かれた内容をそのまま採用する**（手書き部分）。
   構造体・`enum`・`#define` などのデータ設計は設計意図そのものなので、自動で増減させない。
3. **プロトタイプ宣言部**：**対応する `.c` から自動生成する**。
   `.c` 内の `static` が付かない（＝外部公開する）関数定義のシグネチャを抜き出し、
   末尾を `;` にして並べる。関数の直前には1行の説明コメントを付ける（セクション2準拠）。
   **セクション0.5で未完成と判定した関数は `.c` に定義が生成されないので、プロトタイプ宣言も出さない。**

#### 18.5.5 ヘッダの `#include` 判定（self-contained）

ヘッダの `#include` は、**そのヘッダ自身の「型定義部」と「プロトタイプ宣言部」で使う型**から決める
（`.c` の実装内部の都合は見ない）。判断基準は **「このヘッダ単独で `#include` してコンパイルが通るか」**。

- `hand.h`：メンバ `Card cards[HAND_SIZE]` と引数 `Card` を使う → `#include "card.h"`。
- `game.h`：`Player` が `Hand` を持ち、シグネチャに `Deck *`/`Hand *` を使う → `#include "deck.h"` と `#include "hand.h"`。

補足:
- ポインタ（`Deck *` など）しか使わない場合は前方宣言（`struct Deck;`）で済むが、
  入門者向けには分かりやすさを優先し、**素直に `#include` する**方針とする。
- A.h と B.h が互いの型を必要とする**循環依存**は `#include` では解けない。
  これは設計（SPD）の層構造（`card` → `hand`/`deck` → `poker`/`game`）を崩さないことで回避する。

#### 18.5.6 生成例（ポーカープロジェクト）

| ファイル | 生成される `#include` | 根拠（使用シンボル） |
|---|---|---|
| `card.h` | なし | 外部依存なし（最下層） |
| `hand.h` | `"card.h"` | `Card`, `HAND_SIZE` |
| `deck.h` | `"card.h"` | `Card`, `DECK_SIZE` |
| `poker.h` | `"hand.h"` | `Hand` |
| `game.h` | `"deck.h"`, `"hand.h"` | `Deck`, `Hand` |
| `card.c` | `<stdio.h>`, `"card.h"` | `sprintf` → stdio／同名ヘッダ |
| `game.c` | `"game.h"`, `"poker.h"` | 自分の宣言＋`evaluateHand` |

#### 18.5.7 生成後の検証

`#include` の最終判断はコンパイルが真実である。生成後は `gcc -c` で各ファイルが
単独でコンパイルできることを確認する（特にヘッダが self-contained かを確かめる）。
