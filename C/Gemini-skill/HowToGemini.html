Geminiの"スキル"を使ってCコードを生成する方法

構造化プログラム設計図（SPD：Structured Programming Diagram）を読み込ませ、C言語入門者向けのソースコードを生成するカスタムスキルを作成する方法を解説します。

SPDを貼らない依頼（コードの提案、要件定義からの仕様書作成）にも、同じスキルで対応します。どちらの使い方になるかは、入力にSPD記号（│ ├─ └─ ◇ ↻）が含まれるかどうかで、AIが判定します。

1. スキルフォルダの構成

本スキルは、AIへの指示をまとめた指示書（SKILL.md）1つで構成されます。知識ファイルは使いません。

SKILL.md          # 変換ルールと生成手順をすべて定義する指示書

ファイルの役割

  • SKILL.md:
    　SPDの未記入部分は生成しないという最優先ルール、全モード共通のルール（回答スタイル、コーディングスタイル、入出力、メモリとポインタ、エラー処理、利用できる外部ライブラリなど）、SPDモードのルール（記号一覧、読解の基本ルール、制御構造・構造体・列挙型・関数定義のパターン、#include とヘッダファイルの生成、チェックリスト）、通常モードのルール（提案時のテンプレート、仕様書のテンプレート）をまとめた台本です。

2. スキルの作成・登録手順

SKILL.md をAI環境に登録し、カスタムスキルとして保存します。

  1. AI環境へのアップロード AIのチャット画面に、SKILL.md をドラッグ＆ドロップ（または添付）します。
  2. 登録の指示 チャット欄に以下のように入力して実行します。

    「アップロードした SKILL.md を使って、SPDからCのコードを生成するスキルを作成・保存してください。」

  3. 保存完了 AI側でシステムツールが実行され、いつでも呼び出し可能なカスタムスキルとして登録されます。

3. スキルの利用方法

作成したスキルは、日常の学習・開発作業の中で次のように呼び出して利用できます。

基本的な使い方

  • SPDモード（主な使い方）：チャットに、SPDのテキスト、または先頭のブロックコメント（/* ... */）にSPDを書いたCファイルを貼り付け（または添付し）、スキルを呼び出します。
  • 通常モード：SPDを含まない依頼（コードの提案、質問、要件定義からの仕様書作成）も、同じスキルで扱えます。

プロンプト例：
「（SPDを貼り付けた後、）このSPDをもとに、Cのソースコードを生成してください」
「（要件定義を書いた後、）この要件定義から仕様書を作成してください」

期待される動作

  1. AIが自動的に SKILL.md の指示を参照し、入力にSPD記号（│ ├─ └─ ◇ ↻）があるかどうかで、SPDモードと通常モードを切り替えます。
  2. SPDモードでは、SPDの未記入部分は生成せず、コメント1行で知らせます。SPDはファイル先頭のブロックコメントに原文のまま残し、その下にCコードを出力します。
  3. 入力には scanf ではなく input.h の関数を使い、コンソールに出力するプログラムでは main 関数の最後に wait_enter(); を入れます。
  4. 「何をするコードか」を1〜2文で説明してから、関数プロトタイプ宣言とコメントの付いた、入門者向けのコードを示します。
