SpringBoot用のSPDの書き方

Spring Boot のアプリケーション（エンティティ・フォーム・リポジトリ・サービス・コントローラー）を SPD で設計するための入門書です。 規約（springboot-java.instructions.md）のうち、初めて書くときに知っておきたいことだけを選んで説明します。 細かい規則や例外は省いていますので、迷ったときは規約を参照してください。

各節では、SPD の例と、そこから生成される Java のコードを対にして示します。 処理 の中の書き方（◇・↻ などの記号や、「〜を返す」といった文）は、Java 用の SPD と同じです。 画面（テンプレート）の書き方は、別の入門書「SPDによるテンプレートの書き方」で説明しています。

第1章 全体像

1.1 5種類のSPDと層

Spring Boot のアプリケーションは、役割の違う部品（層）に分けて作ります。SPD も、部品ごとに次の5種類を書きます。

コントローラー  →  サービス  →  リポジトリ  →  （データベース）
                      ↓
              エンティティ／フォーム
SPD のタイトル 役割 生成されるもの
エンティティ： データベースの表の1行を表すクラス @Entity のクラス
フォーム： 画面の入力項目と、その検証 入力用のクラス
リポジトリ： データベースの読み書き JpaRepository を継承したインタフェース
サービス： 業務の処理 @Service のクラス
コントローラー： 画面からの要求を受け、画面を選ぶ @Controller のクラス
  • 呼び出しは上から下への一方向だけです。 コントローラーはサービスを呼び、サービスはリポジトリを呼びます。
  • コントローラーからリポジトリを直接呼んではいけません。 データベースの操作は、必ずサービスを通します。
  • サービスは画面のことを知りません。Model などの画面用の型は、コントローラーだけで使います。

1.2 共通の書き方

どの SPD も、タイトル・目的・部品ごとの項目を、木の形で書きます。

※jp.kwebs.bookshop.entity
エンティティ：Book
├─目的：書籍を表すエンティティ
…

/*
※jp.kwebs.bookshop.entity
エンティティ：Book
├─目的：書籍を表すエンティティ
…
*/

package jp.kwebs.bookshop.entity;

…（import 文）…

// 書籍を表すエンティティ
@Entity
public class Book {
  • パッケージ名は、タイトルの前の行に ※ を付けて書きます。 そのまま package 文になります。
  • 目的 は、クラスの直前のコメントになります。
  • SPD 全体が、Java ファイルの先頭（package 文より前）にコメントとして残ります。
  • @主キー・@検証 のような @ で始まる指定をマーカーと呼びます。@ は全角の ＠ でも構いません。
  • import 文は自動で決まるので、SPD に書く必要はありません。

1.3 書く順番

ほかの SPD の名前を使うので、使われる側から書くと迷いません。

  1. エンティティ（データの形を決める）
  2. フォーム（画面で入力する項目を決める）
  3. リポジトリ（エンティティを読み書きする）
  4. サービス（リポジトリを使って処理する）
  5. コントローラー（サービスを使い、テンプレートを選ぶ）
  6. テンプレート（コントローラーから受け取って表示する）

第2章 エンティティ

2.1 基本の形

エンティティは、データベースの表と対応するクラスです。フィールド に表の列を、自動生成 に作ってほしいメソッドを書きます。

エンティティ：Member
├─目的：会員を表すエンティティ
├─テーブル：members
├─フィールド
│  ├─番号：@主キー @自動採番 Long id
│  ├─名前：@必須 @桁数(20) String name
│  └─入会日：LocalDate joinedOn
└─自動生成
     ├─コンストラクタ：引数なし
     ├─ゲッター
     └─セッター

// 会員を表すエンティティ
@Entity
@Table(name = "members")
public class Member {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id; // 番号

    @Column(nullable = false, length = 20)
    private String name; // 名前

    private LocalDate joinedOn; // 入会日

    // 自動生成：コンストラクタ：引数なし
    public Member() {
    }

    // 自動生成：ゲッター
    public Long getId() {
        return id;
    }
    …（ほかのゲッターとセッター）…
}
  • フィールドは <説明>：<マーカー> <型> <変数名> と書きます。説明は行末のコメントになります。
  • テーブル を書くと、表の名前を指定できます。省略すると、クラス名から決まります。
  • 引数なしのコンストラクタは JPA に必須なので、書き忘れても補われます。

2.2 フィールドのマーカー

マーカー 意味 生成されるアノテーション
@主キー 行を見分ける番号（必ず1つ） @Id
@自動採番 番号を自動で振る @GeneratedValue(strategy = GenerationType.IDENTITY)
@必須 空にできない @Column(nullable = false)
@一意 同じ値を入れられない @Column(unique = true)
@桁数(N) 文字数の上限 @Column(length = N)
@列名(x) 列の名前を指定する @Column(name = "x")
@値コレクション 文字列などのリスト・セット @ElementCollection
  • マーカーは型の前に書きます。 複数のマーカーは、1つの @Column にまとめられます。
  • @主キー が無いエンティティは作れません。
  • 日付・時刻は LocalDate・LocalDateTime・LocalTime で書きます。 古い Date・Calendar は使えません。

2.3 関連

ほかのエンティティとのつながりは、関連 に <説明>：<種類> <型> <変数名> と書きます。

├─関連
│  └─所属：多対一 Department department

@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "department_id")
private Department department; // 所属
種類 意味
多対一 多くの会員が1つの部署に属する（いちばんよく使う）
一対多 1つの部署に多くの会員がいる
一対一 1対1で対応する
多対多 互いに複数と対応する
  • 関連が無いときは 関連：なし と書くか、関連 の枝を省きます。

第3章 フォーム

3.1 基本の形

フォームは、画面で入力された値を受け取るクラスです。エンティティと似ていますが、入力の検証を書けるところが違います。

フォーム：BookForm
├─目的：書籍の入力フォーム
├─フィールド
│    ├─主キー：Long id
│    ├─表題：String title　　　＠必須("表題を入力してください")、＠20文字以内
│    ├─発行日：LocalDate issuedOn　＠過去の日付
│    └─価格：Integer price
│              ＠必須("価格を入力してください")
│              ＠正の数("価格は1円以上で入力してください")
└─自動生成
      ├─コンストラクタ：引数なし
      ├─ゲッター
      └─セッター

// 書籍の入力フォーム
public class BookForm {

    private Long id; // 主キー

    @NotBlank(message = "表題を入力してください")
    @Size(max = 20)
    private String title; // 表題

    @Past
    @DateTimeFormat(iso = DateTimeFormat.ISO.DATE)
    private LocalDate issuedOn; // 発行日

    @NotNull(message = "価格を入力してください")
    @Positive(message = "価格は1円以上で入力してください")
    private Integer price; // 価格

    …（コンストラクタ・ゲッター・セッター）…
}
  • 検証には、1つずつ @ を付けます（＠必須、＠20文字以内）。並べるときの区切りは 、 か空白です。
  • 検証は、フィールドの行の末尾か、そのすぐ下の行に書きます。 下の行には枝（├─・└─）を付けず、フィールドの枝より右から書きます。検証が多いときやメッセージが長いときは、下の行に1つずつ書くと読みやすくなります。
  • 1つのフィールドで、行の末尾と下の行の両方に書くことはできません。
  • 位置をそろえるために、@ の前に空白を入れて構いません。
  • エンティティのマーカーは型の前、フォームの検証は変数名の後です。取り違えに注意してください。
  • 日付・時刻のフィールドには、画面から送られた値を変換するための @DateTimeFormat が自動で付きます。
  • 更新画面で使うフォームには、エンティティの主キーと同じ名前・型のフィールド（ここでは id）を入れておきます（7.4）。

3.2 検証の書き方

SPD の書き方 意味 生成されるアノテーション
必須 入力が必要 文字列は @NotBlank、リストは @NotEmpty、それ以外は @NotNull
N文字以内・N文字以上 文字数 @Size(max = N)・@Size(min = N)
N以上・M以下 数の範囲 @Min(N)・@Max(M)（N・M が小数なら @DecimalMin("N")・@DecimalMax("M")）
N超（Nより大きい）・M未満 境の値を含まない数の範囲 @DecimalMin(value = "N", inclusive = false)・@DecimalMax(value = "M", inclusive = false)
整数N桁以内・整数N桁・小数M桁以内 数の桁数 @Digits(integer = N, fraction = 0)・@Digits(integer = N, fraction = M)
正の数・正の数または0 0より大きい・0以上 @Positive・@PositiveOrZero
負の数・負の数または0 0より小さい・0以下 @Negative・@NegativeOrZero
trueである・falseである チェックの有無 @AssertTrue・@AssertFalse
過去の日付・未来の日付 日付の範囲 @Past・@Future
今日以前の日付・今日以降の日付 今日を含む日付の範囲 @PastOrPresent・@FutureOrPresent
値なし 値が無いこと @Null
メール メールアドレス @Email
URL URL @URL
クレジットカード番号 クレジットカード番号 @CreditCardNumber
ISBN・ISBN-10 ISBN（13桁・10桁） @ISBN・@ISBN(type = ISBN.Type.ISBN_10)
"<正規表現>"に一致 形の決まった文字列 @Pattern(regexp = "…")
  • エラーメッセージは、検証の直後の ("…") に書きます（必須("表題を入力してください")）。書かなければ、標準のメッセージになります。
  • 範囲は組み合わせて書けます（N以上M以下・N以上M未満・N超M以下・N超M未満）。
  • チェックボックス（boolean）に 必須 を書いても、チェックは求められません。チェックしないと false が送られるからです。利用規約への同意などには trueである と書きます。
  • 値なし は、文字列（String）には使えません。空の入力欄は空の文字列（""）を送るからです。
  • 表に無い書き方は、検証として使えません。

第4章 リポジトリ

4.1 基本の形

リポジトリは、エンティティをデータベースに保存したり、読み出したりする部品です。 対象（エンティティ）と 主キー（主キーの型）を書くだけで、基本の操作が使えるようになります。

リポジトリ：MemberRepository
├─目的：会員の永続化を行う
├─対象：Member
├─主キー：Long
└─検索メソッド：なし

// 会員の永続化を行う
public interface MemberRepository extends JpaRepository<Member, Long> {
}
  • これだけで、findAll（全件）・findById（主キーで1件）・save（保存）・deleteById（削除）・count（件数）などが使えます。
  • メソッドの中身は Spring が自動で用意するので、リポジトリはインタフェースになります。

4.2 検索メソッド

条件を付けて検索したいときは、検索メソッド に <説明>：<メソッドの宣言> を並べます。 メソッド名を Spring Data の決まりに沿った名前にすると、名前から検索の内容が決まります。

├─検索メソッド
│    ├─表題で検索：List<Book> findByTitle(String title)
│    ├─表題の部分一致：List<Book> findByTitleContaining(String keyword)
│    └─価格の降順で全件：List<Book> findAllByOrderByPriceDesc()

List<Book> findByTitle(String title);               // 表題で検索
List<Book> findByTitleContaining(String keyword);   // 表題の部分一致
List<Book> findAllByOrderByPriceDesc();             // 価格の降順で全件
名前の部品 意味
findBy<フィールド> そのフィールドが等しいものを探す
…Containing 部分一致
…LessThanEqual・…GreaterThanEqual 以下・以上
…And…・…Or… 条件をつなぐ
…OrderBy<フィールド>Asc・Desc 並べ替え

4.3 JPQLで検索する

名前で表しにくい検索は、メソッド： を書き、処理 の代わりに JPQL に検索の内容を日本語で書きます。

└─メソッド：searchByPriceAndTitle
      ├─目的：価格と表題で検索する
      ├─引数
      │    ├─上限価格：@パラメータ Integer price
      │    └─表題のキーワード：@パラメータ String title
      ├─戻り値：List<Book>、書籍のリスト
      └─JPQL：価格がprice以下で表題にtitleを含む書籍を検索し、価格の昇順に並べて返す

// JPQL：価格がprice以下で表題にtitleを含む書籍を検索し、価格の昇順に並べて返す
@Query("SELECT b FROM Book b WHERE b.price <= :price AND b.title LIKE CONCAT('%', :title, '%') ORDER BY b.price ASC")
List<Book> searchByPriceAndTitle(@Param("price") Integer price, @Param("title") String title);
  • 引数の名前と型は、エンティティのフィールドと同じにします（price・title）。名前で条件を対応づけるためです。
  • 使える言い方は、以下・以上・より小さい・より大きい・と等しい・を含む・で始まる・で終わる・かつ・または・昇順・降順 などです。
  • JPQL の文を直接書きたいときは、JPQL："SELECT …" と引用符で囲みます。

第5章 サービス

5.1 基本の形

サービスは、業務の処理を書く部品です。使うリポジトリを インジェクション に書き、処理を メソッド： で書きます。

サービス：MemberService
├─目的：会員に関する業務処理を行う
├─インジェクション
│  └─会員リポジトリ：MemberRepository memberRepository
└─メソッド：create
     ├─目的：会員を登録する
     ├─トランザクション：更新あり
     ├─引数
     │    └─入力フォーム：MemberForm form
     ├─戻り値：なし
     └─処理
           ├─Memberのインスタンスを作って変数memberに代入する
           ├─formのnameをmemberのnameに設定する
           └─memberRepositoryのsaveをmemberを引数にして呼び出す

// 会員に関する業務処理を行う
@Service
public class MemberService {

    private final MemberRepository memberRepository; // 会員リポジトリ

    public MemberService(MemberRepository memberRepository) {
        this.memberRepository = memberRepository;
    }

    /**
     * 会員を登録する
     *
     * @param form 入力フォーム
     */
    @Transactional
    public void create(MemberForm form) {
        var member = new Member();
        member.setName(form.getName());
        memberRepository.save(member);
    }
}
  • インジェクション に書いた部品は、コンストラクタで受け取る形（コンストラクタインジェクション）で生成されます。コントローラーでも同じです。
  • トランザクション は、データベースを扱うメソッドに書きます。
書き方 意味 生成されるアノテーション
トランザクション：更新あり 書き込む @Transactional
トランザクション：参照のみ 読むだけ @Transactional(readOnly = true)
  • トランザクション を書かなければ、アノテーションは付きません。

5.2 自動生成

「リポジトリを呼ぶだけ」の決まりきったメソッドは、自動生成：<リポジトリ> に項目名を並べるだけで作れます。 ここでは、BookForm のフィールドが id・title・price で、Book にも同じ名前・型のフィールドがあるものとします。

サービス：BookService
├─目的：本のデータベース操作
├─インジェクション
│    └─本のリポジトリ：BookRepository bookRepository
└─自動生成：BookRepository
      ├─全件検索
      ├─主キーで検索
      ├─新規作成 ← BookForm
      ├─更新 ← BookForm
      └─削除

// 自動生成：全件検索
@Transactional(readOnly = true)
public List<Book> findAll() {
    return bookRepository.findAll();
}

// 自動生成：主キーで検索
@Transactional(readOnly = true)
public Book findById(Long id) {
    return bookRepository.findById(id).orElseThrow();
}

// 自動生成：新規作成
@Transactional
public Book create(BookForm bookForm) {
    var book = new Book();
    book.setTitle(bookForm.getTitle());
    book.setPrice(bookForm.getPrice());
    return bookRepository.save(book);
}

// 自動生成：更新
@Transactional
public Book update(BookForm bookForm) {
    var book = bookRepository.findById(bookForm.getId()).orElseThrow();
    book.setTitle(bookForm.getTitle());
    book.setPrice(bookForm.getPrice());
    return bookRepository.save(book);
}

// 自動生成：削除
@Transactional
public void deleteById(Long id) {
    bookRepository.deleteById(id);
}
項目 生成されるメソッド
全件検索 List<E> findAll()
主キーで検索 E findById(K id)
新規作成 ← F E create(F f)：フォームから新しいエンティティを作って保存
更新 ← F E update(F f)：主キーで読み出し、フォームの値で上書きして保存
削除 void deleteById(K id)
総件数 long countAll()
ページング Page<E> findAll(Pageable pageable)
検索メソッド リポジトリの検索メソッドを呼ぶだけのメソッド
詰め替え ← F・フォームに詰め替え → F 5.3 で説明します

（E はエンティティ、K は主キーの型、F はフォームの型です）

  • 書いた項目だけが作られます。
  • 新規作成・更新 は、フォームとエンティティで名前と型が同じフィールドを1つずつコピーします。 フォームにだけあるフィールドがあると作れないので、そのときは メソッド： で処理を書きます。
  • 自動生成： の後のリポジトリは、インジェクション に書いたものでなければなりません。

5.3 フォームとエンティティの詰め替え

編集画面では、データベースから読んだエンティティの値を、フォームに移して画面に出します。 このためのメソッドは、フォームに詰め替え → F で作ります。

└─自動生成：BookRepository
      ├─…
      ├─詰め替え ← BookForm
      └─フォームに詰め替え → BookForm

// 自動生成：詰め替え
private void copyFormToEntity(BookForm bookForm, Book book) {
    book.setTitle(bookForm.getTitle());
    book.setPrice(bookForm.getPrice());
}

// 自動生成：フォームに詰め替え
public void copyEntityToForm(Book book, BookForm bookForm) {
    bookForm.setId(book.getId());
    bookForm.setTitle(book.getTitle());
    bookForm.setPrice(book.getPrice());
}
項目 向き 使う場所
詰め替え ← F フォーム → エンティティ（主キーは除く） サービスの中（新規作成・更新 がこれを呼ぶようになる）
フォームに詰め替え → F エンティティ → フォーム（主キーも含む） コントローラーの編集画面（6.4・7.4）

第6章 コントローラー

6.1 基本の形

コントローラーは、ブラウザからの要求を受け取り、サービスを呼んで、表示するテンプレートを選ぶ部品です。 ベースパス に URL の共通部分を書き、要求ごとに メソッド： を書きます。 メソッドに マッピング を書くと、その URL への要求を受け取るメソッド（ハンドラーメソッド）になります。

コントローラー：MemberController
├─目的：会員の一覧・登録を扱う
├─ベースパス：/members
├─インジェクション
│  └─会員サービス：MemberService memberService
└─メソッド：list
   ├─目的：会員の一覧を表示する
   ├─マッピング：GET
   ├─引数
   │    └─モデル：Model model
   ├─戻り値：String、表示するテンプレート名
   └─処理
         ├─memberServiceを使って、全件を読み出した結果をmemberListとしてテンプレートに渡す
         └─"member/list"を返す

// 会員の一覧・登録を扱う
@Controller
@RequestMapping("/members")
public class MemberController {

    private final MemberService memberService; // 会員サービス

    public MemberController(MemberService memberService) {
        this.memberService = memberService;
    }

    /**
     * 会員の一覧を表示する
     *
     * @param model モデル
     * @return 表示するテンプレート名
     */
    @GetMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため
    public String list(Model model) {
        model.addAttribute("memberList", memberService.findAll());
        return "member/list";
    }
}
  • ハンドラーメソッドの戻り値は String です。表示するテンプレートの名前か、リダイレクト先を返します。
  • 処理 では、サービスの メソッド名を書かずに、何をするかを書けます（「全件を読み出した」→ findAll()）。 サービスにあるメソッドの中から、意味の合うものが選ばれます。

6.2 マッピング

マッピング：<HTTPメソッド> <パス> と書きます。パスは ベースパス からの続きです。

SPD 受け取る要求（ベースパスが /members のとき） 生成されるアノテーション
マッピング：GET GET /members @GetMapping({"", "/"})
マッピング：GET /new GET /members/new @GetMapping("/new")
マッピング：GET /{id}/edit GET /members/1/edit など @GetMapping("/{id}/edit")
マッピング：POST POST /members @PostMapping({"", "/"})
マッピング：POST /{id}/delete POST /members/1/delete など @PostMapping("/{id}/delete")
  • 画面を表示するときは GET、データを登録・更新・削除するときは POST を使います。
  • パスにベースパスを繰り返し書かないでください。 ベースパス：/members で マッピング：GET /members と書くと、URL は /members/members になります。
  • パスの {id} の部分は、引数の @パス変数 で受け取ります（6.3）。

6.3 引数とマーカー

引数は <説明>：<マーカー> <型> <変数名> と書きます。マーカーで、値をどこから受け取るかを決めます。

SPD 受け取るもの 生成される引数
入力内容：@検証 MemberForm memberForm フォームの入力（検証する） @Valid MemberForm memberForm
会員番号：@パス変数 Long id URL の {id} の部分 @PathVariable Long id
キーワード：@パラメータ String keyword URL の ?keyword=… やフォームの値 @RequestParam String keyword
キーワード：@パラメータ String keyword = "" 同上（無いときは ""） @RequestParam(defaultValue = "") String keyword
モデル：Model model テンプレートに値を渡す入れ物 Model model
  • String・Long のような単純な型には、必ず @パス変数 か @パラメータ を付けます。 付けないと、どこから受け取るか決められません。
  • Model・BindingResult・RedirectAttributes は、型で決まるのでマーカーは要りません。
  • 引数が1つだけなら、引数：会員番号：@パス変数 Long id のように1行で書けます。

6.4 処理の書き方

処理 には、Java 用の SPD と同じ書き方に加えて、コントローラーだけで使う言い方があります。

SPD の書き方 生成されるコード
"member/list"を返す return "member/list";（テンプレートを表示）
◇─検証結果にエラーがある if (result.hasErrors()) {（入力にエラーがあるか）
<名前>をテンプレートに渡す model.addAttribute("<名前>", <名前>);
<式>を<名前>としてテンプレートに渡す model.addAttribute("<名前>", <式>);
空のMemberFormを作ってテンプレートに渡す model.addAttribute("memberForm", new MemberForm());
ベースパスにリダイレクトする return "redirect:/members";
/members/{id}へリダイレクトする return "redirect:/members/" + id;
"登録しました"をフラッシュメッセージとして渡す redirectAttrs.addFlashAttribute("message", "登録しました");
memberをMemberForm型の変数memberFormに詰め替える var memberForm = new MemberForm(); ＋ memberService.copyEntityToForm(member, memberForm);
  • リダイレクトは、処理のあとで別の URL を開き直させることです。登録や削除のあとは、一覧へリダイレクトするのが基本です。
  • フラッシュメッセージは、リダイレクト先の画面に1回だけ渡すメッセージです。テンプレートでは message という名前で受け取ります。 必ずリダイレクトと組で使います。
  • 「詰め替える」には、サービスに フォームに詰め替え → MemberForm が必要です（5.3）。

6.5 補われる引数

次の引数は、引数 に書かなくても自動で補われます。

補われる引数 補われる条件
BindingResult result @検証 の引数がある
Model model 処理 に「テンプレートに渡す」がある
RedirectAttributes redirectAttrs 処理 に「フラッシュメッセージとして渡す」がある 
└─メソッド：create
     ├─目的：入力された会員を登録する
     ├─マッピング：POST
     ├─引数
     │    └─入力内容：@検証 MemberForm memberForm
     ├─戻り値：String、表示するテンプレート名またはリダイレクト先
     └─処理
           ├─◇─検証結果にエラーがある
           │  └─"member/form"を返す
           ├─memberServiceを使って、memberFormから会員を登録する
           ├─"登録しました"をフラッシュメッセージとして渡す
           └─ベースパスにリダイレクトする

// SPDに無いため BindingResult result を補った
// SPDに無いため RedirectAttributes redirectAttrs を補った
@PostMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため
public String create(@Valid MemberForm memberForm,
                     BindingResult result,
                     RedirectAttributes redirectAttrs) {
    if (result.hasErrors()) {
        return "member/form";
    }
    memberService.create(memberForm);
    redirectAttrs.addFlashAttribute("message", "登録しました");
    return "redirect:/members";
}
  • 補われる引数の名前は決まっています（result・model・redirectAttrs）。
  • 入力にエラーがあるかどうかは、検証結果にエラーがある と書きます。 変数名を知らなくても書けます。resultにエラーがある と書いても同じです。
  • 入力にエラーがあれば、同じ入力画面をもう一度表示します。入力した値とエラーメッセージは、そのまま画面に出ます。

第7章 コントローラーとテンプレートをつなぐ

コントローラーとテンプレートは、名前でつながっています。名前がずれると、コンパイルは通っても画面が正しく出ません。

7.1 テンプレート名

コントローラーの "…"を返す の文字列と、テンプレートの テンプレート：… のタイトルを同じにします。

コントローラー側                       テンプレート側
└─処理                                 テンプレート：member/list
      └─"member/list"を返す
  • ファイルは src/main/resources/templates/member/list.html になります。
  • .html は付けません。先頭に / も付けません（"/member/list" としない）。

7.2 テンプレートに渡す名前

コントローラーで 「テンプレートに渡す」と書いた名前を、テンプレートの 受け取り に同じ名前で書きます。

コントローラー側                                           テンプレート側
└─処理                                                     ├─受け取り
      └─…の結果をmemberListとしてテンプレートに渡す        │    └─会員リスト：List<Member> memberList
  • リストの名前は ～List にします（memberList・bookList）。members のような複数形にはしません。
  • フラッシュメッセージは message という名前で渡るので、テンプレートでは メッセージ：String message　※任意 と受け取ります。

7.3 フォームの名前

フォームの名前は、型名の先頭を小文字にしたものに統一します（MemberForm → memberForm）。

場所 書き方
コントローラーの引数 入力内容：@検証 MemberForm memberForm
コントローラーの処理 空のMemberFormを作ってテンプレートに渡す（名前は自動で memberForm）
テンプレートの受け取り 入力内容：MemberForm memberForm
テンプレートのフォーム ［フォーム］memberForm → POST /members
  • 引数を MemberForm form のように別の名前にすると、テンプレートとつながらなくなります。

7.4 登録・編集・削除の流れ

一覧・登録・編集・削除をそろえたコントローラーの例です。サービスには、自動生成 で 全件検索・主キーで検索・新規作成 ← MemberForm・更新 ← MemberForm・削除・フォームに詰め替え → MemberForm を書いておきます。

コントローラー：MemberController
├─目的：会員の一覧・登録・編集・削除を扱う
├─ベースパス：/members
├─インジェクション
│  └─会員サービス：MemberService memberService
│
├─メソッド：newForm
│  ├─目的：登録画面を表示する
│  ├─マッピング：GET /new
│  ├─引数：なし
│  ├─戻り値：String、表示するテンプレート名
│  └─処理
│        ├─空のMemberFormを作ってテンプレートに渡す
│        └─"member/form"を返す
│
├─メソッド：editForm
│  ├─目的：編集画面を表示する
│  ├─マッピング：GET /{id}/edit
│  ├─引数：会員番号：@パス変数 Long id
│  ├─戻り値：String、表示するテンプレート名
│  └─処理
│        ├─memberServiceを使って、idで会員を検索した結果を変数memberに代入する
│        ├─memberをMemberForm型の変数memberFormに詰め替える
│        ├─memberFormをテンプレートに渡す
│        └─"member/edit"を返す
│
├─メソッド：update
│  ├─目的：入力された内容で会員を更新する
│  ├─マッピング：POST /update
│  ├─引数：入力内容：@検証 MemberForm memberForm
│  ├─戻り値：String、表示するテンプレート名またはリダイレクト先
│  └─処理
│        ├─◇─検証結果にエラーがある
│        │  └─"member/edit"を返す
│        ├─memberServiceを使って、memberFormで会員を更新する
│        ├─"更新しました"をフラッシュメッセージとして渡す
│        └─ベースパスにリダイレクトする
│
└─メソッド：delete
   ├─目的：会員を削除する
   ├─マッピング：POST /{id}/delete
   ├─引数：会員番号：@パス変数 Long id
   ├─戻り値：String、リダイレクト先
   └─処理
         ├─memberServiceを使って、idで会員を削除する
         └─ベースパスにリダイレクトする

// SPDに無いため Model model を補った
@GetMapping("/new")
public String newForm(Model model) {
    model.addAttribute("memberForm", new MemberForm());
    return "member/form";
}

// SPDに無いため Model model を補った
@GetMapping("/{id}/edit")
public String editForm(@PathVariable Long id, Model model) {
    var member = memberService.findById(id);
    var memberForm = new MemberForm();
    memberService.copyEntityToForm(member, memberForm);
    model.addAttribute("memberForm", memberForm);
    return "member/edit";
}

// SPDに無いため BindingResult result を補った
// SPDに無いため RedirectAttributes redirectAttrs を補った
@PostMapping("/update")
public String update(@Valid MemberForm memberForm,
                     BindingResult result,
                     RedirectAttributes redirectAttrs) {
    if (result.hasErrors()) {
        return "member/edit";
    }
    memberService.update(memberForm);
    redirectAttrs.addFlashAttribute("message", "更新しました");
    return "redirect:/members";
}

@PostMapping("/{id}/delete")
public String delete(@PathVariable Long id) {
    memberService.deleteById(id);
    return "redirect:/members";
}

第8章 まとめ

8.1 よくある間違い

規約に合わない書き方は、推測で補われることはなく、生成されずに 【確認事項】として報告されます。よくある間違いを挙げます。

間違い 正しい書き方 理由
会員番号：Long id（ハンドラーメソッドの引数） 会員番号：@パス変数 Long id どこから受け取るか決められない
入力内容：MemberForm form 入力内容：@検証 MemberForm memberForm フォームの名前は型名の先頭を小文字にする
ベースパス：/members で マッピング：GET /members マッピング：GET パスはベースパスからの続き（/members/members になる）
"/member/list"を返す・"member/list.html"を返す "member/list"を返す / と .html は付けない
…をmembersとしてテンプレートに渡す …をmemberListとしてテンプレートに渡す リストの名前は ～List
コントローラーで memberRepository を使う サービスを通す コントローラーからリポジトリを呼ばない
エンティティで String name ＠必須 @必須 String name エンティティのマーカーは型の前
フォームで @必須 String name String name　＠必須 フォームの検証は変数名の後
フォームで String name　＠必須、20文字以内 String name　＠必須、＠20文字以内 検証ごとに @ を付ける
Date birthday LocalDate birthday 日付は java.time の型
「フラッシュメッセージとして渡す」の後に "member/list"を返す 後に 〜へリダイレクトする フラッシュメッセージはリダイレクトと組
