### 9.10 補足事項

* **SPDの保持（最重要ルール）：SPD全体を1つのブロックコメント（`/* ... */`）にまとめ、ソースの冒頭（`import` の直後・型定義またはmainメソッドを含むクラス定義の直前）に残し、その下にコードを書く。**分割・削除は禁止（配置は `## 9.8` を参照）。
* **残す位置はこの冒頭の1か所だけである。複数のSPD（クラス用とメソッド用など）がまとめて与えられた場合も、分割してそれぞれのクラス・メソッドの定義の直前に配ってはならない。** 与えられた順序のまま連結し、1つのブロックコメントとして冒頭に置く。これは、生成されたソースからSPD部分をまとめてコピーし、SPDエディタに取り込む操作を簡単にするためである。
* **SPDに書かれていない処理や構成要素を勝手に追加しないこと。設計の意図を忠実に反映する。**
* SPDの記述に曖昧さがある場合は、最も自然な解釈を採用し、コメントでその選択を明示する。
* 罫線のレイアウトの揺れ（全角／半角スペースの混在等）は無視してよい。意味のあるのは記号と階層構造である。
* SPDで `┬` が使われ、その下に `├─` `└─` が続く場合は、同一ブロック内の複数処理として解釈すること。
* `switch` 文の `case` に対する `┬` は、Javaコードでは `case ... -> { ... }` の複数文ブロックとして生成すること。
