#### ラムダ式（`λ`）

`λ(引数並び)：<本体>` でラムダ式を表す。コロンは全角・半角どちらでもよい（`## 9.2`）。

##### パターンA：式形式（本体が1つの式）
```
──λ(a):a の重さは300 以上
```

```java
a -> a.weight() >= 300
```

`：` の右が1つの式のときは、`->` の右にその式をそのまま置く。`{ }`・`return`・`;` は付けない。

##### パターンB：引数の書き方

| SPDの記述 | 生成する引数部 | 備考 |
| --- | --- | --- |
| `λ()` | `()` | 引数なし |
| `λ(a)` | `a` | 1つのときは括弧を付けない |
| `λ(a, b)` | `(a, b)` | 2つ以上は括弧で囲む |
| `λ(Item a)` | `(Item a)` | 型を明記したときは1つでも括弧が必要 |

```
──λ(): 乱数を生成して返す
──λ(a):a を表示する
──λ(a, b):aのb 乗を返す
```

```java
() -> Math.random()
a -> System.out.println(a)
(a, b) -> Math.pow(a, b)
```

（この3例は、いずれもパターンGによりメソッド参照に書き換える。後述）

##### パターンC：ブロック形式（`：┬`）

本体を複数の処理にするときは `：` の右に `┬` を置き、子ノード（`├─` `└─`）に処理を並べる。
```
──λ(a):┬
       ├─a の重さを表示する
       └─a の重さは300 以上を返す
```

```java
a -> {
    System.out.println(a.weight());
    return a.weight() >= 300;
}
```

* 子ノードを上から順に文として生成し、全体を `{ }` で囲む。
* **最後の子ノードが「〜を返す」なら `return` 文にする。** 値を返さない（void）ラムダでは `return` を書かない。
* 子ノードの中では `◇`（分岐）・`↻`（繰り返し）・`〇`（例外処理）を通常どおり使ってよい。

##### パターンD：本体の日本語の解釈

| SPDの記述 | 生成する式 |
| --- | --- |
| 「〜を返す」 | その値を表す式そのもの（式形式では `return` を書かない） |
| 「〜は…以上」「〜と…は同じ」などの判定 | `boolean` 式（`>=` / `equals` など） |
| 「〜を表示する」 | `System.out.println(...)`（戻り値なし） |

##### パターンE：外部変数の参照（キャプチャ）

ラムダより前（同じ親の兄ノード）で宣言された変数は、そのまま参照してよい。
```
┬─final な変数String colorに"red" を入れる
└─λ(a):a の色は変数color と同じ
```

```java
final String color = "red";
a -> a.color.equals(color)
```

* `final な変数` と書かれていれば `final` を付けて宣言する。
* 書かれていなくても、ラムダ内で参照する外部ローカル変数は再代入しない（実質的finalを壊さない）。

##### パターンF：ラムダの置かれ方

* `λ` ノードが単独で置かれている場合は、**ラムダ式だけ**を生成する。代入先の関数型インタフェース（`Predicate` 等）は、SPDに指定が無いかぎり勝手に補わない。
* `## 9.3` ルール4 の横連結でλが右に来る場合は、左の処理の**引数として**ラムダを渡す。
```
├─listを重さ順に並べ替える─λ(a, b):aとbの重さを比較した結果を返す
```

```java
list.sort((a, b) -> Integer.compare(a.weight(), b.weight()));
```

##### パターンG：メソッド参照への書き換え

生成したラムダ式が次のいずれかの形に**完全に一致する**ときは、メソッド参照に書き換える。一致しないものは**ラムダ式のまま**にする（迷った場合はラムダ式のまま残す＝安全側に倒す）。

| # | 種類 | ラムダ式の形 | メソッド参照 | 例 |
| --- | --- | --- | --- | --- |
| 1 | レシーバ束縛形 | `(a, …) -> 式.method(a, …)` | `式::method` | `a -> System.out.println(a)` → `System.out::println` |
| 2 | static形 | `(a, …) -> 型.method(a, …)` | `型::method` | `(a, b) -> Math.pow(a, b)` → `Math::pow` |
| 3 | 型::インスタンスメソッド | `(型 a, …) -> a.method(…)` | `型::method` | `(Item a) -> a.weight()` → `Item::weight` |
| 4 | コンストラクタ参照 | `(a, …) -> new 型(a, …)` | `型::new` | `() -> new ArrayList<>()` → `ArrayList::new` |

**書き換えてはならない場合**

* 本体がブロック形式（`：┬`、パターンC）
* ラムダの引数が、呼び出しの引数として**同じ順序で過不足なく**渡されていない（例：`a -> a.color.equals(color)` はレシーバが `a` ではなく `a.color` なので**書き換えない**）
* 本体に演算子・比較・条件式が含まれる（例：`a -> a.weight() >= 300`）
* 種類3で、ラムダの引数の型がSPDに書かれておらず、`型::メソッド` の `型` を確定できない（`λ(a):a の重さを返す` は型が不明なので書き換えない。`λ(Item a):…` なら `Item::weight`）

**SPDにメソッド参照を直接書く場合**

SPDのノードに `型::メソッド` の形が直接書かれていれば、そのままメソッド参照として生成する（`## 9.7 メソッド呼び出しの扱い` と同じ扱い。新しい記号は使わない）。パターンGの対象外の形をメソッド参照で書かせたいときは、この書き方を使う。
```
──Item::weight
```

```java
Item::weight
```
