## 最重要ルール（最初に確認）

* **`## 0.` の規則（SPDの未記入部分は生成しない）を、他のすべての規則に優先して適用すること。** SPDに未記入・未完成の部分があれば、その単位はコードを生成せずコメント1行に置き換え、`## 0.8` の報告を添える。
* **実装前に、`SKILL.md` の対応表で該当する節を特定し、そのファイルを確認すること**（特に `## 9. SPD記法からのコード生成`。規約のファイルをすべて読む必要はない）。
* **SPD（設計図）は消さず、全体を1つのブロックコメント（`/* ... */`）としてソースの冒頭（`import` 文の後・型定義の直前）に残し、その下に生成したコードを書くこと。**細切れに分割して小出しに書き込んではならない。
* **SPDの指示にない処理・クラス・メソッド・フィールドを勝手に予測して追加しないこと。**
* **パッケージ文（`package 〇〇;`）は勝手に追加しないこと。**
* キーボード入力は必ず `jp.kwebs.tools.Input` の static メソッドを使う（`## 4`）。
* 小数点以下の桁数を指定した四捨五入は必ず `jp.kwebs.tools.Tools.round`、整数への四捨五入（0桁）は `Math.round()` を使う。`BigDecimal`・`String.format` による丸めは使わない（`## 5`）。
* インポートが必要な場合は `## 9.7` のインポート処理方針に従う。
* **コードを書き始める前に、`未記入判定: 名前=記入済み 名前=未記入 …` の1行を出力すること**（`## 0.3.6`）。次の `◇判定:` の1行も出す場合は、`未記入判定:` を先、`◇判定:` を後にする。
* **SPDに `◇` が複数ある場合は、コードを書き始める前に、次の形式の1行だけを出力し、その直後にコードを生成すること。**
    * 形式：`◇判定: 1=if 2=elif 3=if …`（`◇` の出現順に通し番号を付け、`if` か `elif`（＝直上への `else if` 連結）かだけを並べる）
    * **この1行以外は出力しない。** 表・箇条書き・SPD行の引用・判定理由の説明を書いてはならない。
    * 分類は `## 9.4` の文字テスト（`◇` の左の最初の非空白文字が `│`／行頭なら `else if`、それ以外はすべて新しい `if`）だけで行い、桁位置は判定に使わない。この1行を確定させてからコードを生成する。SPDが長いほどこの手順を省略しない。

## 1. 対象範囲

このリポジトリ全体に適用する。
より下位ディレクトリに別ルールがある場合は、下位ルールを優先する。

## 2. 言語・説明方針

* 回答とコメントは原則日本語で記述する。
* コードは既存スタイルに合わせる。
* 不要に冗長な説明は避け、変更理由を短く明確に書く。

## 3. Java コーディング方針

* 既存パッケージ構成に従う。ただし、**新規コード生成時にパッケージ文（`package 〇〇;`）を勝手に追加しないこと。**
* 既存命名規則（クラス名、メソッド名、変数名）を優先する。
* 例外処理は握りつぶさず、必要に応じてメッセージを残す。
* 文字コードは既存設定に合わせる（不明な場合は UTF-8 を前提に確認する）。
* ローカル変数の宣言で、右辺がオブジェクトを返す式（`new` によるインスタンス生成、ファクトリメソッド、キャスト式など）の場合は、型名に `var` を積極的に使用すること。ただし配列を宣言と同時に要素で初期化する場合（`{ ... }` 初期化子）は `var` を使わず明示的な配列型で宣言し、`new` も使わないこと。
```java
// 推奨
var list  = new ArrayList<String>();   // new によるインスタンス生成
var names = List.of("Alice", "Bob");   // ファクトリメソッド
String[] fruits = { "apple", "banana", "orange" }; // 配列の即時初期化は明示型

// 非推奨（型が冗長 or プロジェクト方針に非準拠）
ArrayList<String> list = new ArrayList<String>();
List<String> names = List.of("Alice", "Bob");
var fruits = new String[] { "apple", "banana", "orange" };
```

* 繰り返し処理のfor文では、デフォルトで拡張for文（for-each）を使用すること。インデックスが必要な場合（要素の位置を使う、逆順、飛ばし処理など）と、明示的に「インデックスfor文を使う」と指示された場合に限り、通常のインデックスfor文を使用すること。
```java
// 推奨（拡張for文）
for (String name : names) { … }

// インデックスが必要な場合のみ許可
for (int i = 0; i < names.length; i++) { … }
```


## 6. 変更時のルール

* 依頼されていない大規模リファクタリングは行わない。
* 既存コードの意図を壊さない最小変更を優先する。
* 変更したファイル名・変更点・確認手順を簡潔に提示する。

## 7. テスト・確認

* 実行可能な変更では、可能な範囲でビルド/実行確認を行う。
* 確認できない場合は、未確認事項と確認コマンドを明記する。

## 8. 禁止事項

* 機密情報（APIキー、パスワード等）をハードコードしない。
* 著作権上問題のあるコードの貼り付けを行わない。
* 破壊的変更（削除・構成変更）は明示依頼がある場合のみ行う。
