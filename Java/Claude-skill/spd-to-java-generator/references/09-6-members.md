### 9.6 クラスメンバー定義のパターン

`## 9.5.1` のクラス定義および独立SPDで定義される各メンバーを生成する規約。
アクセス修飾子記号と既定値は `## 9.2` を参照する。

##### 9.6.1 クラス変数

クラス定義内の `クラス変数:` ノードでも、独立SPDでも定義できる。常に `static` を付け、修飾子省略時は `public`。`final` は記述があるときのみ付ける。`説明` はソース右側の行コメントにし、生成位置はクラスの先頭（インスタンスフィールドの前）とする。

```
├─クラス変数:                        ※クラス定義内のノード。子は <説明>: [修飾子] [final] <型> <変数名> [= 値]
│  └─会費: # final int FEE = 5000

クラス変数: # final int FEE = 5000    ※独立SPD。タイトルに宣言を書き、`説明` を子に持てる
└─説明: 会費
```

どちらの書き方でも生成コードは同じ：

```java
protected static final int FEE = 5000; // 会費
```

##### 9.6.2 フィールド

`<説明>: [修飾子] <型> <変数名>`
ノード名は `フィールド`。旧表記 `属性` も同義として黙って読み替える（`## 9.2` 別名表）。
修飾子省略時は `private`（型定義では既定が private）。
`<説明>` はソース右側の行コメントにする。
```
番号: int uid
```

```java
private int uid; // 番号
```

##### 9.6.3 コンストラクタの自動生成（`自動生成` 内の `コンストラクタ：…`）

`自動生成`（`## 9.6.4`）に書けるコンストラクタは次の2種類で、書いたものだけを生成する。

`[修飾子] コンストラクタ：全引数`

* 全フィールドを引数に取るコンストラクタを1つ生成する（引数の型・名はフィールド定義に従う）。
* **引数には継承フィールドを含める。** サブクラスではスーパークラスのソースを参照し、スーパークラス分の引数を `super(...)` に渡す。例：`Member(int uid, String name)` を継承し `LocalDate birthday` を持つ `SeniorMember`：

```java
public SeniorMember(int uid, String name, LocalDate birthday) {
    super(uid, name);
    this.birthday = birthday;
}
```

* `自動生成` に種別を書かず `コンストラクタ` とだけある場合（旧表記）は、`コンストラクタ：全引数` とみなす（`## 9.2`）。

`[修飾子] コンストラクタ：引数なし`

* 引数を持たず、本体で何もしないコンストラクタ（`public GeneralMember() {}` の形）を1つ生成する。
* **スーパークラスに引数なしコンストラクタが無い場合は、自動生成しない。** スーパークラスの初期化に使う値は設計判断であり、自動生成で決めてはならないためである。生成を省略したうえで、生成位置に次の警告を行コメントとして埋め込む：

```java
// 警告: スーパークラス Member に引数なしコンストラクタが無いため、引数なしコンストラクタを自動生成できません。
//       コンストラクタノード（9.6.5）で super(...) に渡す既定値を明示して定義してください。
```

* 判定はスーパークラスのソースを参照して行う（スーパークラスがコンストラクタを1つも定義していない場合は、既定コンストラクタがあるものとして自動生成してよい）。

共通

* 修飾子省略時は `public`。記述が無い種類は生成しない（`自動生成` が無ければコンストラクタは一切自動生成しない）。
* フィールドが0個のクラスでは両者が同一になるため、両方の記載があっても1つだけ生成する。
* `コンストラクタ` ノード（`## 9.6.5`）に同じ型の並びの定義がある場合は、自動生成側を生成せず、ノード定義側だけを生成する（`## 9.6.4`）。

##### 9.6.4 自動生成

クラスに自動生成するメンバーの一覧。ノード名は `自動生成`（旧表記 `自動生成のリスト`／`自動生成のパターン` も同義）。書けるのは次の7種類のみである。

| 記述 | 生成されるメンバー |
| --- | --- |
| `コンストラクタ：全引数` | 全フィールドを引数に取るコンストラクタ（`## 9.6.3`） |
| `コンストラクタ：引数なし` | 引数なし・本体なしのコンストラクタ（`## 9.6.3`） |
| `ゲッター` | フィールドの getter |
| `セッター` | フィールドの setter |
| `toString` | `toString()` |
| `等値判定` | `equals()` と `hashCode()` の両方 |
| `移譲メソッド` | 自作クラス型フィールドへの移譲メソッド（`## 9.6.8`） |

個別のメソッドはここには書かない。`メソッド:`（＝`インスタンスメソッド:`）ノード（`## 9.6.6`）で本体ごと定義する（上の7種類以外の名前があれば、不整合として指摘する）。

アクセス修飾子の指定

* **各行の先頭にアクセス修飾子記号（`+ # ~ -`）を書ける。** 省略時は `public`。例：`# コンストラクタ：全引数` → `protected` なコンストラクタ（抽象クラスなど。`## 9.5.4`）。
* `ゲッター`／`セッター`／`移譲メソッド` は、書かれた修飾子を生成する全メソッドに適用する。
* `toString`／`等値判定` は Objectクラスのオーバーライドで `public` より狭くできないため常に `public`（修飾子が書かれていたら不整合として指摘する）。

`ゲッター` `セッター` … `ゲッター ← uid, name` のように `←` で対象フィールドを指定できる（指定なし＝全フィールド）。防御的コピーが必要なフィールドは `←` で対象から外し、コピーを返すゲッターを `メソッド:` で個別定義する。
`toString` `等値判定` … Objectクラスのオーバーライドなので `@Override` を付ける。`等値判定 ← uid` の `←` の右は比較・ハッシュ対象のフィールド並びで、`equals`・`hashCode` の両方に同じ並びを適用する（省略時は全フィールド）。`equals` は `instanceof` のパターンマッチ、`hashCode` は `Objects.hash(...)` で実装する（`## 9.5.1` の生成例を参照）。旧表記 `equals ← …` `hashCode ← …` は黙って読み替える（別々のフィールド並びで書かれていた場合のみ指摘する）。
`移譲メソッド` … 自作クラス型フィールドへの移譲メソッドを自動生成する（`## 9.6.8`）。

ノード定義が優先される（自動生成の抑制）

* 自動生成されるメンバーと同じシグニチャー（コンストラクタは引数の型の並び、メソッドは名前＋引数の型の並び）の `コンストラクタ`（`## 9.6.5`）／`メソッド:`（`## 9.6.6`）定義がある場合は、**自動生成側を生成せず、ノード定義だけを生成する**（エラーにはしない）。全7種類が対象。例：`自動生成` に `ゲッター` があり `メソッド: getName`（引数なし）も定義されていれば、`getName()` はノード定義の本体で1つだけ生成する。
* ゲッター／セッターを自動生成から外すだけなら、`←` で対象フィールドを絞る方法も使える。
* ノード定義同士が同じシグニチャーで重複する場合は、この抑制は適用せず、エラーを報告する（`## 9.6.5`・`## 9.6.6`）。

`@Override` は Objectクラスのメソッドに限らない。スーパークラス（`─⊳`）の同一シグネチャのメソッドのオーバーライド、実装インタフェース（`---⊳`）のメソッドの実装、`toString`/`equals`/`hashCode` のオーバーライドには `@Override` を付ける（判定はスーパークラス・インタフェースのソースを参照する）。ただし通常の getter/setter は（スーパークラスで宣言されていない限り）付けない。

##### 9.6.5 コンストラクタ（`コンストラクタ` ノード）

自動生成（`## 9.6.3`）で表せないコンストラクタ（全フィールドを取るが単純な代入では済まないもの、引数の並びが異なるオーバーロード）は、クラス定義内の `コンストラクタ` ノードで明示的に定義する。単純な全フィールド版・引数なし版で足りる場合は `自動生成`（`## 9.6.3`）を使う。

ノード名は `コンストラクタ`（旧表記 `コンストラクタ：オーバーロード` も同義）。1つのクラスに複数定義してよい。
`[修飾子] コンストラクタ` をヘッダとし、`引数`／`処理` を子に持つ。修飾子省略時は `public`。
`引数` の各行は `<型> <変数名>[ : 説明]` と `<説明>：<型> <変数名>`（フィールド `## 9.6.2` と同じ形式）のどちらの書式でもよい。`なし` の場合は引数なし。
サブクラスの場合は、スーパークラスのソースを参照して `super(...)` 呼び出しも生成する。
**自動生成のコンストラクタ（`## 9.6.3`）と引数の型の並びが同じ場合は、自動生成側を生成せず、この `コンストラクタ` ノードの定義だけを生成する**（エラーにはしない。`## 9.6.4`）。判定は引数名ではなく型の並びで行う。
`コンストラクタ` ノード同士が同じ型の並びで重複する場合は生成せず、エラーを報告する：「〜は引数が同じなのでオーバーロードできません。」

引数なしのコンストラクタ（`コンストラクタ：引数なし` の自動生成で足りない場合）
```
├─コンストラクタ
│    ├─引数─なし
│    └─処理─"guest"をnameに代入する
```

```java
public Member() {
    this.name = "guest";
}
```

引数ありの独自コンストラクタ
```
├─# コンストラクタ
│    ├─引数
│    │   └─ int uid : 番号
│    └─処理
│         ├─ uidをフィールドに設定する
│         └─ "guest"をフィールドnameに設定する
```

```java
protected Member(int uid) {
    this.uid = uid;
    this.name = "guest";
}
```

自動生成とノード定義が共存する例
```
クラス: Function
├─目的: 関数ax+bを表すクラス
├─フィールド
│   ├─係数1: int a
│   └─係数2: int b
├─自動生成
│   └─コンストラクタ：全引数
└─コンストラクタ
    ├─引数
    │   └─int b: 係数2
    └─処理
         ├─フィールドa に10を代入する
         └─フィールドb に、引数のb を代入する
```

```java
// 関数ax+bを表すクラス
public class Function {
    private int a; // 係数1
    private int b; // 係数2

    // 自動生成：コンストラクタ：全引数（9.6.3）
    public Function(int a, int b) {
        this.a = a;
        this.b = b;
    }

    // コンストラクタノードによる追加分（9.6.5）
    public Function(int b) {
        this.a = 10;
        this.b = b;
    }
}
```

> 上の例で `コンストラクタ` ノードの引数が `int x, int y` だった場合は、自動生成と型の並びが同じなので**自動生成側は生成せず**、ノード定義の本体（`Function(int x, int y)`）だけを生成する。

##### 9.6.6 メソッド定義

`メソッド: [修飾子] <名前>`（インスタンスメソッド）または `クラスメソッド: [修飾子] <名前>`（クラスメソッド＝static）をヘッダとし、`目的／引数／戻り値／処理` を子に持つ。
`メソッド:` と `インスタンスメソッド:` は同義であり、どちらで書いてもよい（`## 9.2` 別名表）。
クラス定義内のメンバーノード（`## 9.5.1`）としても、独立SPDとしても書ける。
```
クラスメソッド: mile2km
│
├─ 目的: マイルをキロメートルに変換する
├─ 引数
│    └─ double mile : マイルの値
├─ 戻り値
│     └─ double: キロメートルの値
└─ 処理
      ├─ km = mile * 1.609
      └─ kmを小数点以下2桁までに四捨五入して返す
```

```java
/**
 * マイルをキロメートルに変換する
 * @param mile マイルの値
 * @return キロメートルの値
 */
public static double mile2km(double mile) {
    double km = mile * 1.609;
    return Tools.round(km, 2);
}
```

修飾子省略時は `public`。`クラスメソッド:` ヘッダのメソッドは `static` を付けて生成し、`クラスメソッド: main` は `public static void main(String[] args)`（目的・引数・戻り値の記載は不要）。
`引数` の各行は `<型> <変数名>[ : 説明]` と `<説明>：<型> <変数名>` のどちらの書式でもよい（`## 9.6.5` と同様）。`戻り値` は `<型>、<説明>` と読点で区切って書き、型をシグネチャに、説明を `@return` にする。
スーパークラス（`─⊳`）の同一シグネチャのメソッドのオーバーライド、実装インタフェース（`---⊳`）のメソッドの実装にあたる場合は `@Override` を付ける（判定はソースを参照。`## 9.6.4` と整合）。
**自動生成（`## 9.6.4`）と同名・同シグネチャの本定義が共存する場合は、自動生成側を生成せず本定義だけを生成する**（エラーにはしない）。メソッド定義同士が同名・同シグネチャで重複する場合は生成せず、エラーを報告する。

###### メソッドが投げる例外（`throws`）

ヘッダの名前の後ろに `throws <例外型>[, <例外型>…]` を書ける。書かれていれば、そのまま
シグネチャの `throws` として生成する（`メソッド:`／`クラスメソッド:`／`抽象メソッド:`／
`コンストラクタ` のどのヘッダでも同じ）。

```
スタティックメソッド：doSomething throws CheckedNumberException
│
├─目的：チェック例外を投げる
├─引数
│    └─回数：int count
├─戻り値：なし
└─処理
      ├─◇─count は負である
      │        └─CheckedNumberExceptionを投げる
      │              └─エラーメッセージは "不正な値" + count とする
      │
      └─count を "回数＝〇〇" の形式で表示する
```
```java
/**
 * チェック例外を投げる
 * @param count 回数
 * @throws CheckedNumberException 不正な値のとき
 */
public static void doSomething(int count) throws CheckedNumberException {
    if (count < 0) {
        throw new CheckedNumberException("不正な値" + count);
    }
    System.out.printf("回数＝%s%n", count);
}
```

- Javadocには `@throws <例外型>` を出す。`目的／引数／戻り値` と並べて `例外` ノードを書いてもよく、
  その説明を `@throws` の説明文にする（`例外` ノードにだけ書かれた例外型も `throws` に出す）。
- **書き忘れの補完**：SPDに `throws` が書かれていなくても、次のどちらかに当てはまる**検査例外**があれば
  `throws` を補う（`throws` は処理ではなくコンパイル要件であり、補わないとコードが通らないため）。
  1. `処理` の中に `…を投げる`（`## 9.4` パターンC）がある
  2. 呼び出しているメソッドが `throws` を宣言している（呼び出し元へ順に伝播させる。`main` も同じ）

  ただし、その例外を受ける `〇─try/catch` がSPD内にある場合は補わない。
- 補ったときは、**メソッド宣言の直前に行コメント1行**で明示する（`## 9.6.3` の警告コメントと同じ流儀）。
  ```java
  // SPDに throws の記載が無いため、検査例外 CheckedNumberException を宣言に補った
  ```
- **非検査例外**（`RuntimeException` とそのサブクラス）は補わない。SPDに書かれていればそのまま出す。
- 検査／非検査の判定は、ワークスペース内に例外クラスの定義があれば `extends` をたどって行う。
  定義が見つからない独自例外は、名前が `〜Exception` で `Runtime` を含まなければ**検査例外とみなす**。

##### 9.6.7 クラス定義を含まないSPD

クラス宣言が無く、処理のタイトル＋手順だけのSPD → そのクラスファイルの mainメソッド本体。
クラス宣言が無く、`クラスメソッド:` のメソッド定義だけのSPD → そのクラスファイルに含まれる クラスメソッド。

##### 9.6.8 移譲メソッドの自動生成

`自動生成` に `移譲メソッド` の記載がある場合、フィールドの中からプロジェクト内で定義された自作クラス型のフィールドを探し、そのクラスの公開メソッドを呼び出すだけの移譲メソッドを自動生成する。`移譲メソッド ← product` のように `←` で対象フィールドを指定できる（省略時は自作クラス型の全フィールド。`String` やコレクションなど標準ライブラリ型は対象外）。
移譲の対象にするメソッドは、対象フィールドのクラスのソースを参照して決定する：ゲッター・セッター、そのクラスで定義された公開インスタンスメソッド、スーパークラスから継承した公開インスタンスメソッド（Objectクラスのメソッド・`static` メソッドは対象外）。
生成する移譲メソッドは対象メソッドと同名・同シグネチャとし、本体はフィールド経由の呼び出し1文のみ（戻り値があれば `return`）。`@Override` は付けない（オーバーライドではないため）。
自クラスに同名・同シグネチャのメソッドが既にある場合（自動生成のゲッター／セッター、`メソッド:` 定義 `## 9.6.6` を含む）は、その移譲メソッドを生成しない（エラーにはしない）。

例（`src/chapter22/Stock.java`）
```
クラス:Stock
├─フィールド
│  ├─商品：Product product
│  └─在庫数：int quantity
└─自動生成
    ├─コンストラクタ：全引数
    ├─ゲッター
    └─移譲メソッド
```

```java
// Product の公開メソッド（getNumber/getName/getPrice …）をそれぞれ移譲する
public int getNumber() {
    return product.getNumber();
}
```

##### 9.6.9 抽象メソッド

`抽象メソッド: [修飾子] <名前>` をヘッダとし、`目的／引数／戻り値` を子に持つ。
**`処理` は書かない**（`処理` ノードがあれば、不整合として指摘する）。
```
└─抽象メソッド：kai_hi
      ├─目的：会費額を返す
      ├─引数：なし
      └─戻り値：int 、会費額
```

```java
/**
 * 会費額を返す
 * @return 会費額
 */
public abstract int kai_hi();
```

* `abstract` を付け、**本体なし（`;` で終わる宣言）** で生成する。
* 修飾子省略時は `public`。`-`（private）は `abstract` と両立しないため、指摘する。
* 書ける場所は `抽象クラス：`（`## 9.5.4`）と `インタフェース：`（`## 9.5.2`）だけである。
* **インタフェース内では `public abstract` が暗黙**のため、修飾子・`abstract` を書かずに生成する（例：`String version();`）。
* `目的` はJavadoc、`引数` の説明は `@param`、`戻り値` の説明は `@return` にする（`引数`／`戻り値` の書式は `## 9.6.6` と同じ）。
* サブクラス・実装クラスでこの抽象メソッドを実装するメソッドには `@Override` を付ける（`## 9.6.4`）。
