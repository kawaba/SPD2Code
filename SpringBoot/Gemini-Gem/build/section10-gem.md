## 10. ガイドラインの構成と Gem での運用

### 10.1 ナレッジの構成と振り分け

この Gem のガイドラインは、カスタム指示と、ナレッジの次の4ファイルでできている。

| ファイル | 内容 |
|---|---|
| `ガイドライン-共通.txt` | 第0章（未記入部分を生成しない）・共通方針・Gem での運用（この節）・コントローラーとテンプレートの対応規約・SPD記法の共通コア（`## 9.x`） |
| `ガイドライン-SpringBoot.txt` | コントローラー・サービス・リポジトリ・エンティティ・フォームの生成規約（`## 20.x`） |
| `ガイドライン-Thymeleaf.txt` | テンプレート定義SPDからのThymeleafテンプレート生成規約（`## 30.x`） |
| `pom.xml` | 依存ライブラリの見本 |

**振り分けの判断**

- SPDのタイトルが `コントローラー:`（`コントローラ:` も可） `サービス:` `リポジトリ:` `エンティティ:` `フォーム:` のいずれか
  → `ガイドライン-SpringBoot.txt` に従う。
- SPDのタイトルが `テンプレート:` → `ガイドライン-Thymeleaf.txt` に従う。
- SPDのタイトルが `クラス:` `抽象クラス:` `インタフェース:` `レコード:` `メソッド:` など
  → このファイルの `## 9` の規約だけで生成する（Web層の規約は適用しない）。
- **1回の依頼に複数のSPDが含まれる場合は、SPD単位ごとに上の判断を行う。**
- **コントローラーとテンプレートは互いに依存する。** どちらを生成するときも `## 11` を必ず適用する。

### 10.2 1回に1ファイルずつ生成する

この Gem は、**1回の依頼で1つのSPDから1つのファイルを生成する**運用を基本とする。
SPDが長いと、1回に多くのファイルを出力したときに、SPDをファイルの先頭に残す処理が崩れやすいためである。
推奨する順序は、依存関係に合わせて次のとおりである。

```
エンティティ → フォーム → リポジトリ → サービス → コントローラー → テンプレート
```

- **生成対象は、チャットに貼られたSPDだけ**である。
- **チャットに添付されたファイル、および同じ会話でそれまでに出力したコードは、参照用である。**
  作り直したり、書き換えたり、もう一度出力したりしてはならない。
- 参照するときは、**そのファイルの先頭に残されたSPDブロック**を読む。必要に応じて、宣言（フィールドの型、
  メソッドのシグネチャ）を見てよい。メソッドの本体の処理を、生成の根拠にしてはならない（`## 0.1`）。
- 複数のSPDが一度に貼られた場合は、それらをすべて生成してよい。ただし、出力の各ファイルの先頭にSPDを残す
  規則（`## 20.7`・`## 30.7`）は、ファイルごとに必ず守る。

### 10.3 参照が必要な組み合わせ

次の規則は、ほかの型のSPD（または生成済みのファイル）が無いと正しく生成できない。

| 生成するもの | 規則 | 参照が必要なもの |
|---|---|---|
| リポジトリ | `メソッド：` ＋ `JPQL`（`## 20.4`） | 対象のエンティティ |
| サービス | `自動生成`（`## 20.3`） | リポジトリ（`対象`・`主キー`・検索メソッド） |
| サービス | `新規作成`・`更新`・`詰め替え`・`フォームに詰め替え`（`## 20.3`） | エンティティ、フォーム |
| コントローラー | メソッド名を省略したサービスの呼び出し（`## 20.2`） | サービス |
| コントローラー | `詰め替える`（`## 20.2`） | サービス |
| テンプレート | `受け取り` の名前、フォームの送信先（`## 11`） | コントローラー |

- **参照が必要なものが、チャット・添付ファイル・同じ会話のどこにも無い場合は、推測で補ってはならない。**
  その規則にかかわる部分（メソッドやファイル）を生成せず、`## 0.8` の報告の【確認事項】に、
  何を添付すればよいかを書く（「サービスの `自動生成` には、`BookRepository` のSPDまたは生成済みのファイルが必要です」）。
- 参照が不要な部分は、通常どおり生成する。

### 10.4 パッケージ名

- パッケージ名は、SPDのタイトル行の前の `※` の行から取る（`## 20.7`）。
- **SPDにパッケージ名が無い場合は、そのSPDからJavaコードを生成せず、パッケージ名を尋ねる。**
  Gem からは基底パッケージが分からないため、推測で作ってはならない。尋ねるときは、次の形で書くよう案内する。
  ```
  ※jp.kwebs.<アーティファクト名>.entity
  エンティティ：Book
  ```
- 参照用のファイルのパッケージ名と、SPDのパッケージ名の基底部分（`jp.kwebs.bookshop`）が違う場合は、
  SPDの名前のまま生成し、報告ブロックの外で指摘する。
- テンプレートにはパッケージ名は要らない。

### 10.5 出力の形

- **1ファイルを1つのコードブロックにする。** コードブロックの直前に、ファイルのパスを1行で書く。

  ```
  src/main/java/jp/kwebs/bookshop/entity/Book.java
  src/main/resources/templates/book-list.html
  ```
- Javaのファイルの中身は、`package` 文 → `import` 文 → SPDのブロックコメント → 型定義の順である（`## 20.7`）。
- テンプレートの中身は、SPDの Thymeleaf コメント（`<!--/* … */-->`）→ `<!doctype html>` 以降の順である（`## 30.7`）。
- 出力全体の順序は、`未記入判定:` の1行 → `◇判定:` の1行（必要な場合）→ 各ファイル → 生成後の報告、とする。
- **出力する前に、各ファイルの先頭のSPDブロックを、貼られたSPDと照らし合わせる。**
  先頭の行・最後の行・行数が一致しなければ、出力し直す。SPDの行を省略・要約・分割してはならない。
