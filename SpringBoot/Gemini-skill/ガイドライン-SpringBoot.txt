### 層の責務と依存方向

```
Controller  →  Service  →  Repository  →  （DB）
                  ↓
              Entity / Form
```

- **依存は上から下への一方向のみ**とする。
- **コントローラーからリポジトリを直接呼び出すコードを生成してはならない。**
  SPDにそう書かれていた場合も生成せず、`## 0.8` の報告の【確認事項】に載せること。
- 各層の責務は次のとおりである。

| 層 | 責務 | してはならないこと |
|---|---|---|
| Controller | HTTPの受け口、画面の選択、Modelへの受け渡し | 業務ロジック、DBアクセス |
| Service | 業務ロジック、トランザクション境界 | HTTPに依存する型（`Model`・`HttpServletRequest`）の使用 |
| Repository | 永続化 | 業務ロジック |
| Entity | テーブルとの対応 | 業務ロジック、画面用の項目 |
| Form | 画面の入力項目と入力検証 | 永続化アノテーション |

- SPDのマーカー（`@検証`・`@主キー` など、`@` で始まる指定）の `@` は、**半角 `@` と全角 `＠` のどちらで書いてもよい。**

### インジェクション（コントローラー・サービス共通）

```
├─インジェクション
│  └─会員サービス：MemberService memberService
```
```java
private final MemberService memberService; // 会員サービス

public MemberController(MemberService memberService) {
    this.memberService = memberService;
}
```

- **フィールドへの `@Autowired` を生成してはならない。** 必ずコンストラクタインジェクションにする。
- インジェクションが1つでもある場合、コンストラクタは**必ず明示的に生成する**（`@RequiredArgsConstructor` などの
  Lombok は使わない。学習者が生成物を読めることを優先する）。
- コントローラー・サービスのどちらでも使える。`インジェクション：なし` は記入済みとして扱う。

## 20.2 コントローラー

### 記法

コントローラーのメソッドは、**一般の `メソッド:`（`spd-core` の `## 9.6.6`）と同じ形**で書く。
`目的`・`引数`・`戻り値`・`処理` を持ち、そこに `マッピング` を加えたものがハンドラーメソッドになる。
Javaで、マッピングのアノテーションが付いたメソッドがハンドラーになるのと同じである。

```
コントローラー：MemberController
│
├─目的：会員の一覧・登録・削除を扱う
├─ベースパス：/members
│
├─インジェクション
│  └─会員サービス：MemberService memberService
│
├─メソッド：list
│  ├─目的：会員の一覧を表示する
│  ├─マッピング：GET
│  ├─引数：なし
│  └─処理
│        ├─memberServiceを使って、全件を読み出した結果をmemberListとしてテンプレートに渡す
│        └─"member/list"を返す
│
├─メソッド：newForm
│  ├─目的：新規登録画面を表示する
│  ├─マッピング：GET /new
│  ├─引数：なし
│  └─処理
│        ├─空のMemberFormを作ってテンプレートに渡す
│        └─"member/form"を返す
│
├─メソッド：create
│  ├─目的：入力された会員を登録する
│  ├─マッピング：POST
│  ├─引数
│  │    └─入力内容：@検証 MemberForm memberForm
│  └─処理
│        ├─◇─検証結果にエラーがある
│        │  └─"member/form"を返す
│        ├─memberServiceを使って、memberFormから会員を登録する
│        ├─"登録しました"をフラッシュメッセージとして渡す
│        └─ベースパスにリダイレクトする
│
└─メソッド：delete
     ├─目的：会員を削除する
     ├─マッピング：POST /{id}/delete
     ├─引数
     │    └─会員番号：@パス変数 Long id
     └─処理
           ├─memberServiceを使って、idで会員を削除する
           └─ベースパスにリダイレクトする
```

### ノードの意味と生成規則

| ノード | 生成されるもの |
|---|---|
| タイトル `コントローラー：X` | `@Controller` を付けた `public class X` |
| `目的：…` | クラス宣言の直上の行コメント（`// …`） |
| `ベースパス：/members` | クラスに `@RequestMapping("/members")` |
| `インジェクション` | `private final` フィールド＋**コンストラクタインジェクション**（`## 20.1` の「インジェクション」） |
| `メソッド：名前` | `spd-core` の `## 9.6.6` に従う通常のインスタンスメソッド |
| `マッピング：GET /new`（`メソッド` の子） | `@GetMapping("/new")` などのマッピング。これが付いたメソッドがハンドラーメソッドになる |

- タイトルは `コントローラ：X`（長音なし）と書いてもよい。`コントローラー：X` と同じに扱う。
- **`マッピング` は、必ず `メソッド` の子として書く。** コントローラーの直下に書かれた場合は、
  どのメソッドに付くのか決められないため生成せず、`## 0.8` の報告の【確認事項】に載せること
  （`spd-core` の `## 9.5.1` のとおり、項目の並び順には意味が無い）。
- `マッピング` の無い `メソッド` は、ハンドラーではない通常のメソッドとして生成する（アノテーションを付けない）。
- **ハンドラーメソッドの戻り値は `String` である。** 返す文字列が、表示するテンプレート名（`## 11.1`）
  またはリダイレクト先になる。`戻り値` が `String` 以外の場合は生成せず、`## 0.8` の報告の【確認事項】に載せること。
- **ハンドラーメソッドでは `戻り値` を省略してよい。** 省略した場合も戻り値の型は `String` とし、
  Javadoc の `@return` の説明は、`処理` の終わり方から次のように決める。
  `戻り値` を書いた場合は、従来どおり書かれた説明を使う。

  | `処理` の終わり方 | `@return` の説明 |
  |---|---|
  | すべて `"…"を返す` | `表示するテンプレート名` |
  | すべて「〜にリダイレクトする」 | `リダイレクト先` |
  | 両方がある | `表示するテンプレート名またはリダイレクト先` |

**`マッピング` の書式**

`マッピング：<HTTPメソッド> [<パス>]` と書く。パスは `ベースパス` からの相対である。
**HTTPメソッドは `GET` と `POST` だけを書ける**（HTMLのリンクとフォームから送れるのはこの2つだけであるため）。
`PUT`・`DELETE`・`PATCH` などが書かれた場合は、そのメソッドを生成せず【確認事項】に載せること
（削除・更新は `POST /{id}/delete` のように `POST` とパスで表す）。

| SPDの記述 | 生成 |
|---|---|
| `マッピング：GET` | `@GetMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため` |
| `マッピング：GET /` | `@GetMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため` |
| `マッピング：GET /{id}/edit` | `@GetMapping("/{id}/edit")` |
| `マッピング：POST` | `@PostMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため` |
| `マッピング：POST /{id}/delete` | `@PostMapping("/{id}/delete")` |

- **パスを省略した場合、または `/` だけの場合は、`ベースパス` そのものに割り当てる。**
  HTTPメソッドにかかわらず、マッピングの引数を `{"", "/"}` とし、同じ行の末尾に
  行コメント `// 末尾の / の有無どちらでも受け付けるため` を付ける。
  Spring Boot 3 以降は末尾の `/` を区別するため、`@GetMapping` だけでは
  `/members/` へのアクセスが 404 になる。
- `ベースパス` が無いコントローラーでも同じに生成する。
- **パスを明示した場合は、そのパスだけを書く。** 末尾に `/` を付けた別名を加えてはならない
  （`マッピング：GET /books` → `@GetMapping("/books")`。`{"/books", "/books/"}` としない）。
  `{"", "/"}` にするのは、パスを省略した場合と `/` だけの場合に限る。
- **`マッピング` のパスが `ベースパス` と同じ文字列で始まる場合**（`ベースパス：/date` に対して
  `マッピング：GET /date`・`マッピング：GET /date/new` など。`/dates` のように区切りの `/` が続かないものは当たらない）は、
  URL がベースパスを2回重ねたもの（`/date/date`）になる。パスはベースパスからの相対であることを書き忘れた誤りであることが多い。
  **SPDのとおりに生成し**（`@GetMapping("/date")`。パスを推測で直さない）、`## 0.8` の報告の【確認事項】に次の形で載せること。

  ```text
  - entry の `マッピング：GET /date` は、ベースパス `/date` からの相対なので、URL は `/date/date` になります。
    `/date` にする場合は、マッピングのパスを省いて `マッピング：GET` と書きます。
  ```

  マッピングのパスがベースパスと同じでなく、続きがある場合（`/date/new`）は、2行目を
  「`/date/new` にする場合は、`マッピング：GET /new` と書きます。」とする。

**`引数` の書式**

`<説明>：[<マーカー>] <型> <変数名>` の形で書く。`spd-core` の `引数`（`<説明>：<型> <変数名>`）に、
値の受け取り方を表すマーカーを加えたものである。**説明は自由に書いてよく、生成には影響しない**
（Javadoc の `@param` の説明になる）。マーカーの `@` は全角 `＠` でもよい（`## 20.1`）。
引数が1つだけのときは、`引数：会員番号：@パス変数 Long id` のように `引数` に続けて1行で書いてもよい
（`spd-core` の `## 9.6.5`）。

| SPDの記述 | 生成される引数 |
|---|---|
| `入力内容：@検証 MemberForm memberForm` | `@Valid MemberForm memberForm` |
| `入力内容：MemberForm memberForm` | `MemberForm memberForm` |
| `会員番号：@パス変数 Long id` | `@PathVariable Long id` |
| `キーワード：@パラメータ String keyword` | `@RequestParam String keyword` |
| `キーワード：@パラメータ String keyword = ""` | `@RequestParam(defaultValue = "") String keyword` |
| `モデル：Model model` | `Model model` |
| `検証結果：BindingResult result` | `BindingResult result` |
| `転送属性：RedirectAttributes redirectAttrs` | `RedirectAttributes redirectAttrs` |
| `引数：なし` | 引数なし（下の「補う引数」は補う） |

- `Model`・`BindingResult`・`RedirectAttributes` は**型で判別する。** マーカーは付けない。
- **ハンドラーメソッドで、マーカーの無い単純な型**（`String`・数値型とそのラッパークラス・`LocalDate` など）の引数は、
  値をパスから受け取るのかパラメータから受け取るのか決められないため、そのメソッドを生成せず、
  `## 0.8` の報告の【確認事項】に載せること。
  説明が `パス変数`・`パラメータ` でマーカーが無いもの（`パス変数：Long id`）も、これに当たる（`## 20.1` の「規約に無い書き方」）。
- **フォーム（クラス型）の変数名は、型名の先頭の1文字を小文字にしたものとする**（`MemberForm` → `memberForm`）。
  **`@ModelAttribute` は付けない。** Spring では、クラス型の引数は `@ModelAttribute` が付いているものとして
  扱われ、Model の属性名は型名の先頭を小文字にしたものになる。この規則により、変数名・Model の属性名・
  テンプレートの `受け取り` の名前がすべて一致する（`## 11.3`）。
- SPDに別の変数名（`入力内容：MemberForm form` など）が書かれていた場合は、**名前を勝手に変えず**、
  そのメソッドを生成せずに `## 0.8` の報告の【確認事項】に載せること。
- **`マッピング` のパスの `{…}` と、`@パス変数` の引数の変数名は、一致させる。**
  パスにある `{名前}` に同じ名前の `@パス変数` の引数が無い場合、または `@パス変数` の引数の名前がパスに無い場合は、
  そのメソッドを生成せず【確認事項】に載せること（`{memberId}` と `Long id` のように食い違うと、
  コンパイルは通っても実行時にエラーになるため）。名前を推測で書き換えてはならない。
- **`引数：なし` は、「SPDに書く引数が無い」という意味である。** 下の「補う引数」は、`引数：なし` でも補う
  （`newForm` は `引数：なし` でも `Model model` を補う）。

**補う引数**

次の引数は、`引数` に書かれていなくても補う。**変数名は固定**であり、`処理` の中ではこの名前で参照する
（`resultにエラーがある` など。ただし、検証エラーの判定は変数名を使わない `検証結果にエラーがある` で書くことを勧める）。

| 補う引数 | 補う条件 | 置く位置 |
|---|---|---|
| `BindingResult result` | `@検証` の引数があり、その直後に `BindingResult` が書かれていない | `@Valid` を付けた引数の**直後** |
| `Model model` | `処理` に「〜をテンプレートに渡す」がある | 引数の末尾 |
| `RedirectAttributes redirectAttrs` | `処理` に「〜をフラッシュメッセージ…として渡す」がある | 引数の末尾（`Model` の後） |

- **`引数` に書かれていれば、書かれた変数名を使う**（補わない）。`引数：なし` と書かれていても補う。
- `@Valid` を付けた引数の直後には、必ず `BindingResult` を置く（Spring の要件）。
  書かれた `BindingResult` が直後に無い場合は、直後へ移す。
- `RedirectAttributes` は、`処理` にフラッシュメッセージが無ければ補わない。
- **補った引数ごとに、メソッドのアノテーションの直前（Javadoc の後）に行コメントを1行付ける**
  （`// SPDに無いため BindingResult result を補った`）。Javadoc の `@param` にも載せ、説明は
  `result` が「検証結果」、`model` が「モデル」、`redirectAttrs` が「リダイレクト先へ渡す属性」とする。

**`処理` の中の Web 固有の表現**

| SPDの記述 | 生成 |
|---|---|
| `"member/form"を返す` | `return "member/form";` |
| `/membersへリダイレクトする` | `return "redirect:/members";` |
| `/members/{id}へリダイレクトする` | `return "redirect:/members/" + id;` |
| `ベースパスにリダイレクトする` | `return "redirect:/members";`（`ベースパス` の値） |
| `ベースパス（"/members"）にリダイレクトする` | 同上 |
| `ベースパスの/{id}/editにリダイレクトする` | `return "redirect:/members/" + id + "/edit";`（`ベースパス` の値に続けたパス） |
| `◇─検証結果にエラーがある` | `if (result.hasErrors()) {`（`result` は、そのメソッドの `BindingResult` の引数の名前） |
| `"…"をフラッシュメッセージとして渡す` | `redirectAttrs.addFlashAttribute("message", "…");` |
| `"…"をフラッシュメッセージ<名前>として渡す` | `redirectAttrs.addFlashAttribute("<名前>", "…");` |
| `<名前>をテンプレートに渡す` | `model.addAttribute("<名前>", <名前>);` |
| `<式>を<名前>としてテンプレートに渡す` | `model.addAttribute("<名前>", <式>);` |
| `空の<フォーム型>を作ってテンプレートに渡す` | `model.addAttribute("<型名の先頭を小文字>", new <フォーム型>());` |
| `<変数>を<フォーム型>型の変数<名前>に詰め替える` | `var <名前> = new <フォーム型>();` ＋ `<サービス>.copyEntityToForm(<変数>, <名前>);` |

- 「テンプレートに渡す」は「テンプレートへ渡す」「画面に渡す」「画面へ渡す」と書いてもよい。同じに扱う。
- 「テンプレートに渡す」の `<名前>` が、テンプレート側の `受け取り` と照合する属性名である（`## 11.2`）。
- **フラッシュメッセージの名前を省略した場合は `message` とする。** テンプレート側は `message` で受け取る。
- **フラッシュメッセージはリダイレクトと組で使う。** リダイレクトを伴わない
  `addFlashAttribute` を生成してはならない。
- **`ベースパスにリダイレクトする`** は、`ベースパス` の値へのリダイレクトにする。
  `ベースパス` が無いコントローラーで使われた場合、または括弧の中の値が `ベースパス` と違う場合は、
  そのメソッドを生成せず、`## 0.8` の報告の【確認事項】に載せること。
- **`ベースパスの<パス>にリダイレクトする`** は、`ベースパス` の値に `<パス>`（`/` で始める）を続けた先へのリダイレクトにする。
  `マッピング` と同じく、パスはベースパスからの相対で書ける。`{名前}` は、そのメソッドの同じ名前の変数を文字列連結で埋め込む
  （`"redirect:/members/" + id + "/edit"`）。同じ名前の変数が無い場合、または `ベースパス` が無いコントローラーで使われた場合は、
  そのメソッドを生成せず【確認事項】に載せること。「へリダイレクトする」と書いてもよい。
- テンプレートに渡す名前を変えるときは、`<式>を<名前>としてテンプレートに渡す` と書く。
  以前の `<式>を"<名前>"という名前でテンプレートに渡す` は、規約に無い書き方として報告する（`## 20.1`）。
- **`空の<フォーム型>を作ってテンプレートに渡す`** の属性名は、フォームの変数名と同じ規則
  （型名の先頭を小文字）で決める（`## 11.3`）。
- **`詰め替える`** は、`インジェクション` にあるサービスのうち、`自動生成` に `詰め替え`（フォームの型が `<フォーム型>` のもの。
  `## 20.3`）を持つものの `copyEntityToForm` を呼び出す。該当するサービスが無い、または2つ以上ある場合は、
  そのメソッドを生成せず【確認事項】に載せること。**コントローラーでフィールドを1つずつコピーするコードを生成してはならない。**
- **`検証結果にエラーがある`** は、そのメソッドの `BindingResult` の引数（「補う引数」で補ったもの、または `引数` に書かれたもの）の `hasErrors()` にする。
  変数名を書かずに済むので、こちらで書くことを勧める。以前からの `resultにエラーがある` のように変数名で書いてもよい。
  `@検証` の引数が無いメソッドに書かれた場合、または `@検証` の引数が2つ以上あってどの検証結果か決められない場合は、
  そのメソッドを生成せず、【確認事項】に載せること。`検証エラーがある`・`入力エラーがある` などの言い回しは規約に無い書き方として報告する。
- `"…"を返す` の文字列は、テンプレート名としてそのまま使う。**`/` で始まっていた場合は生成せず**、
  【確認事項】に載せること（`## 11.1`）。

**サービスの呼び出し（メソッド名の省略）**

`処理` の中でサービスを呼び出すときは、**文脈から推測できる場合はメソッド名を書かず**、何をするかを書く。

```
├─memberServiceを使って、全件を読み出した結果をmemberListとしてテンプレートに渡す
├─memberServiceを使って、memberFormから会員を登録する
└─memberServiceを使って、idで会員を削除する
```
```java
model.addAttribute("memberList", memberService.findAll());
memberService.create(memberForm);
memberService.deleteById(id);
```

- **呼び出すメソッドは、そのサービスのSPD（または生成済みのサービス）に実在するものから選ぶ。**
  候補は、`自動生成` の項目（`全件検索` → `findAll()`、`削除` → `deleteById` など。`## 20.3`）と、
  `メソッド：` の `目的`、`検索メソッド` の移譲元の説明である。書かれた動作と意味が合うものを1つ選ぶ。
- 引数は、`処理` に書かれた変数（`memberFormから`・`idで`）を、選んだメソッドの引数の型と照らして渡す。
- **候補が無い、または2つ以上あって決められない場合は、推測でメソッドを作らず**、そのメソッドを生成せずに
  `## 0.8` の報告の【確認事項】に載せること。サービスにメソッドを勝手に追加してはならない。
- メソッド名を書いた場合（`memberServiceのfindAllを呼び出す`）は、それに従う。書かれた名前がサービスに無い場合は
  【見つからない名前】に載せること。

**リストの名前**

- **結果がリスト（`List`）になる値の名前は、`～s`（複数形）ではなく `～List` とする**（`memberList`・`bookList`）。
  これはSPDを書く側の規則である。テンプレートの `受け取り` も同じ名前で書く（`## 11.2`）。
- 生成時には、SPDに書かれた名前を**そのまま使い、書き換えない**（`members` と書かれていても `memberList` に直さない。`## 11.2`）。

### 生成例

上の `create` から生成されるコード：

```java
/**
 * 入力された会員を登録する
 *
 * @param memberForm 入力内容
 * @param result 検証結果
 * @param redirectAttrs リダイレクト先へ渡す属性
 * @return 表示するテンプレート名またはリダイレクト先
 */
// SPDに無いため BindingResult result を補った
// SPDに無いため RedirectAttributes redirectAttrs を補った
@PostMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため
public String create(@Valid MemberForm memberForm,
                     BindingResult result,
                     RedirectAttributes redirectAttrs) {
    if (result.hasErrors()) {
        return "member/form";
    }
    memberService.create(memberForm);
    redirectAttrs.addFlashAttribute("message", "登録しました");
    return "redirect:/members";
}
```

`newForm` と `delete`：

```java
/**
 * 新規登録画面を表示する
 *
 * @param model モデル
 * @return 表示するテンプレート名
 */
// SPDに無いため Model model を補った
@GetMapping("/new")
public String newForm(Model model) {
    model.addAttribute("memberForm", new MemberForm());
    return "member/form";
}

/**
 * 会員を削除する
 *
 * @param id 会員番号
 * @return リダイレクト先
 */
@PostMapping("/{id}/delete")
public String delete(@PathVariable Long id) {
    memberService.deleteById(id);
    return "redirect:/members";
}
```

## 20.3 サービス

### 記法

リポジトリを呼び出すだけの定型のメソッドは、**`自動生成`** で作る（下記「自動生成」）。
それ以外の処理だけを `メソッド：` で書く。

```
サービス：MemberService
│
├─目的：会員に関する業務処理を行う
│
├─インジェクション
│  └─会員リポジトリ：MemberRepository memberRepository
│
├─自動生成：MemberRepository
│     ├─全件検索
│     ├─新規作成
│     └─詰め替え
│
└─メソッド：countJoinedAfter
     ├─目的：指定した日より後に入会した会員の人数を数える
     ├─トランザクション：参照のみ
     ├─引数：基準日：LocalDate date
     ├─戻り値：long、会員の人数
     └─処理
           └─memberRepositoryのfindAllの結果のうち、joinedOnがdateより後の要素の数を返す
```

### 生成規則

| ノード | 生成されるもの |
|---|---|
| タイトル `サービス：X` | `@Service` を付けた `public class X` |
| `インジェクション` | `private final` フィールド＋コンストラクタインジェクション（`## 20.1` の「インジェクション」） |
| `自動生成：<リポジトリ型名>` | リポジトリを呼び出すだけの定型のメソッド（下記「自動生成」） |
| `メソッド：名前` | `spd-core` の `## 9.6.6` に従う通常のインスタンスメソッド |
| `トランザクション：更新あり` | `@Transactional` |
| `トランザクション：参照のみ` | `@Transactional(readOnly = true)` |

- **`トランザクション` ノードが無い場合は、アノテーションを付けない。** 勝手に補わない。
  データベースを読み書きする `メソッド：` には、`トランザクション` を書くことを勧める。
- `@Transactional` は `org.springframework.transaction.annotation.Transactional` を使う
  （`jakarta.transaction.Transactional` ではない）。
- サービスは HTTP に依存してはならない。SPDに `Model` や `HttpServletRequest` が現れた場合は
  生成せず、`## 0.8` の報告の【確認事項】に載せること。
- **メソッドは、SPDに書かれた順に並べる。** `自動生成` で作るメソッドは、`自動生成` の枝の位置に、
  下の表の順（`詰め替え` は最後）でまとめて置く。
- `主キーで検索` などで見つからないときは例外（`NoSuchElementException`）になる。
  見つからないときの扱いは当面の対象外である（`## 20.1`）。

### 自動生成（リポジトリを呼び出すだけのメソッド）

リポジトリを呼び出すだけの定型のメソッドは、`自動生成：<リポジトリ型名>` の下に項目名を並べて生成できる。

```
サービス：BookService
│
├─目的：本のデータベース操作
├─インジェクション
│    └─本のリポジトリ：BookRepository bookRepository
│
└─自動生成：BookRepository
      ├─全件検索
      ├─主キーで検索
      ├─新規作成
      ├─更新
      ├─削除
      ├─総件数
      ├─ページング
      ├─検索メソッド
      └─詰め替え
```

`BookRepository` が `対象：Book`・`主キー：Long` の場合、各項目から次のメソッドを生成する
（表の `E` は対象の型、`K` は主キーの型、`F` はフォームの型、`repo` はリポジトリの変数名）。

| 項目 | 生成するメソッド | 本体 | トランザクション |
|---|---|---|---|
| `全件検索` | `List<E> findAll()` | `return repo.findAll();` | `@Transactional(readOnly = true)` |
| `主キーで検索` | `E findById(K id)` | `return repo.findById(id).orElseThrow();` | `@Transactional(readOnly = true)` |
| `新規作成`（`新規作成 ← F`） | `E create(F f)` | 下記「フォームからの作成と更新」 | `@Transactional` |
| `更新`（`更新 ← F`） | `E update(F f)` | 下記「フォームからの作成と更新」 | `@Transactional` |
| `削除` | `void deleteById(K id)` | `repo.deleteById(id);` | `@Transactional` |
| `総件数` | `long countAll()` | `return repo.count();` | `@Transactional(readOnly = true)` |
| `ページング` | `Page<E> findAll(Pageable pageable)` | `return repo.findAll(pageable);` | `@Transactional(readOnly = true)` |
| `検索メソッド` | リポジトリの検索メソッドと同名・同シグネチャ | 下記「検索メソッドの移譲」 | `@Transactional(readOnly = true)` |
| `詰め替え`（`詰め替え：F`） | `private void copyFormToEntity(F f, E e)` と `public void copyEntityToForm(E e, F f)` の2つ | 下記「詰め替えメソッド」 | 付けない |

- **書かれた項目だけを生成する。** 上の表に無い項目名があれば、その項目だけを生成せず【確認事項】に載せる
  （ほかの項目は生成する）。`詰め替え` も、`新規作成`・`更新` があるからといって**暗黙に生成してはならない。**
- 項目の右に `※…` の注記（シグネチャのメモなど）が書かれていても、生成には使わない。生成するシグネチャは上の表で決まる。
- `F f` の変数名は、型名の先頭を小文字にしたもの（`BookForm bookForm`）とする（`## 20.2` のフォームと同じ）。
  `E e` の変数名も同じく、型名の先頭を小文字にしたもの（`Book book`）とする。
- `主キーで検索` の `orElseThrow()` は引数なしとする（見つからなければ `NoSuchElementException`）。
  `主キーで検索` は、アプリが渡した主キーで探すためのものである。利用者が入力した値で探す画面には使わない（`## 20.7`「例外処理」）。
- 自動生成したメソッドには、上の表のトランザクションを付ける。
  **`トランザクション` ノードが無ければ付けない、という規則（上の「生成規則」）の例外である。**
- 同じシグネチャのメソッドを `メソッド：` で書いた場合は、そちらを優先し、自動生成はしない（`spd-core` の `## 9.5.1`）。
- 各メソッドの直前に、`// 自動生成：<項目名>` の行コメントを1行付ける。

**フォームの型（`F`）**

- `新規作成`・`更新`・`詰め替え` のフォームの型は、**省略すると「対象のエンティティ名＋`Form`」とする**（`Book` → `BookForm`）。
- 別の名前のフォームを使うときは、`新規作成 ← BookCreateForm`・`更新 ← BookUpdateForm`・`詰め替え：BookCreateForm` のように書く。
- フォームの型のSPD（または生成済みのファイル）が見つからない場合は、推測で補わず、その項目を生成せず【確認事項】で添付を求める。
- 以前の `詰め替え ← F`・`フォームに詰め替え → F` は、規約に無い書き方として報告し、`詰め替え`（または `詰め替え：F`）を案内する（`## 20.1`）。

**リポジトリの指定**

- `自動生成：` の後のリポジトリ型名は、**`インジェクション` にある型でなければならない。**
  無い場合、または型名が書かれていない場合は、`自動生成` 全体を生成せず【確認事項】に載せる。`インジェクション` を勝手に補ってはならない。
- 対象の型と主キーの型は、そのリポジトリの `対象`・`主キー`（`## 20.4`）、または生成済みの
  `JpaRepository<対象, 主キー>` から得る。見つからない場合は自動生成せず、`## 0.8` の報告の【確認事項】に載せること。
- `自動生成` は1つのサービスに**1回だけ**書ける（2つのリポジトリで自動生成するとメソッド名がぶつかるため）。

**検索メソッドの移譲（`検索メソッド`）**

リポジトリのメソッドを呼び出してその結果を返すだけのメソッドを、`spd-core` の `移譲メソッド`（`## 9.6.8`）と
同じ考え方で生成する。

| SPDの記述 | 対象 |
|---|---|
| `検索メソッド` | リポジトリのSPDの `検索メソッド` の全行と、`メソッド：`（JPQL。`## 20.4`）のすべて |
| `検索メソッド ← findByTitle, searchByPriceAndTitle` | `←` で名前を指定したものだけ（区切りは `,` または `、`） |

- **対象は、リポジトリのSPD（または生成済みのリポジトリ）に書かれたメソッドだけ**である。
  `JpaRepository` から継承したメソッド（`findAll`・`count` など）は含まない。それらは上の表の他の項目で生成する。
- 生成するメソッドは、リポジトリのメソッドと**同名・同シグネチャ**（戻り値の型・引数の型と名前が同じ）とし、
  本体は `return repo.<同名>(<引数>);` の1文だけにする。
- `←` で指定した名前がリポジトリに無い場合は、その名前の移譲だけを生成せず【確認事項】に載せる。
- 同じシグネチャのメソッドがサービスに `メソッド：` で書かれている場合は、その1つだけ移譲を生成しない（エラーにはしない）。
- 直前の行コメントは、`// 自動生成：検索メソッド（<リポジトリでの説明>）` とする。
  リポジトリの `メソッド：` の場合は、説明にその `目的` を使う。

```java
// 自動生成：検索メソッド（表題で検索）
@Transactional(readOnly = true)
public List<Book> findByTitle(String title) {
    return bookRepository.findByTitle(title);
}

// 自動生成：検索メソッド（価格と表題で検索する）
@Transactional(readOnly = true)
public List<Book> searchByPriceAndTitle(Integer price, String title) {
    return bookRepository.searchByPriceAndTitle(price, title);
}
```

**フォームからの作成と更新（`新規作成`・`更新`）**

- フォームとエンティティのSPD（または生成済みのJavaファイル）を読み、**名前と型が同じフィールド**を、
  ゲッター・セッターで1つずつコピーする。主キーのフィールドはコピーしない。
- **フォームのフィールドのうち、エンティティに同じ名前・同じ型のフィールドが無いものが1つでもあれば**、
  その項目は生成せず、`## 0.8` の報告の【確認事項】に載せること。推測で型変換や検索を補ってはならない。
  このような場合は、`メソッド：` で処理を書いてもらう。
- `更新` では、フォームに**エンティティの主キーと同じ名前・同じ型のフィールド**が必要である。
  無い場合は生成せず、【確認事項】に載せること。
- 同じフォーム型の `詰め替え` がある場合は、コピーを本体に書かず、`copyFormToEntity(f, e);` の呼び出し1行にする
  （下の2つ目の例）。無い場合は、コピーを本体に直接書く（下の1つ目の例）。

`詰め替え` が無い場合：

```java
// 自動生成：新規作成
@Transactional
public Book create(BookForm bookForm) {
    var book = new Book();
    book.setTitle(bookForm.getTitle());
    book.setPrice(bookForm.getPrice());
    return bookRepository.save(book);
}

// 自動生成：更新
@Transactional
public Book update(BookForm bookForm) {
    var book = bookRepository.findById(bookForm.getId()).orElseThrow();
    book.setTitle(bookForm.getTitle());
    book.setPrice(bookForm.getPrice());
    return bookRepository.save(book);
}
```

`詰め替え` がある場合：

```java
// 自動生成：新規作成
@Transactional
public Book create(BookForm bookForm) {
    var book = new Book();
    copyFormToEntity(bookForm, book);
    return bookRepository.save(book);
}

// 自動生成：更新
@Transactional
public Book update(BookForm bookForm) {
    var book = bookRepository.findById(bookForm.getId()).orElseThrow();
    copyFormToEntity(bookForm, book);
    return bookRepository.save(book);
}
```

**詰め替えメソッド（`詰め替え`）**

- `詰め替え` の1項目から、**両方向の2つのメソッド**を生成する。どちらも、**名前と型が同じフィールド**を
  ゲッター・セッターで1つずつコピーする。
  - `copyFormToEntity(F f, E e)`：フォームからエンティティへ（`新規作成`・`更新` が使う）
  - `copyEntityToForm(E e, F f)`：エンティティからフォームへ（コントローラーの編集画面の表示が使う。`## 20.2` の `詰め替える`）
- **どちらも、コピー先を引数で受け取り、戻り値は `void` とする。**
  `copyFormToEntity` は、`更新` でDBから読んだエンティティに上書きするため、新しいインスタンスを返す形にしない
  （フォームに無いフィールドや関連が消えるため）。`copyEntityToForm` は、オーバーロード（下記）で
  戻り値の型だけが違うメソッドにならないよう、同じ形にそろえる。
- `copyFormToEntity` は**主キーをコピーしない**（`新規作成` の自動採番と `更新` の検索を壊さないため）。
  `copyEntityToForm` は**主キーもコピーする**（編集画面から `更新` に主キーを渡すため）。
- **フォームのフィールドのうち、エンティティに同じ名前・同じ型のフィールドが無いものが1つでもあれば**、
  2つとも生成せず、`## 0.8` の報告の【確認事項】に載せること（「フォームからの作成と更新」と同じ）。
  エンティティにだけあるフィールドは、どちらの向きでもコピーしない。
- `copyFormToEntity` はサービスの中からだけ呼ぶため `private` とし、`copyEntityToForm` は
  コントローラーから呼ぶため `public` とする。どちらも DB にアクセスしないので、`@Transactional` を付けない。
  `新規作成`・`更新` が無いと `copyFormToEntity` は使われないが、そのまま生成する（IDE の「使われていない」という警告は無視してよい）。
- **フォーム型が違えば、`詰め替え` を複数書ける。** 同名のメソッドをオーバーロードとして生成する
  （`詰め替え：BookCreateForm` と `詰め替え：BookUpdateForm` → 2つずつ）。
  同じフォーム型が2回書かれていた場合は、2回目を生成せず【確認事項】に載せる。
- 行コメントは、`// 自動生成：詰め替え（フォーム → エンティティ）`・`// 自動生成：詰め替え（エンティティ → フォーム）` とする。

```java
// 自動生成：詰め替え（フォーム → エンティティ）
private void copyFormToEntity(BookForm bookForm, Book book) {
    book.setTitle(bookForm.getTitle());
    book.setPrice(bookForm.getPrice());
}

// 自動生成：詰め替え（エンティティ → フォーム）
public void copyEntityToForm(Book book, BookForm bookForm) {
    bookForm.setId(book.getId());
    bookForm.setTitle(book.getTitle());
    bookForm.setPrice(book.getPrice());
}
```

## 20.4 リポジトリ

### 記法

```
リポジトリ：BookRepository
│
├─目的：書籍の永続化を行う
├─対象：Book
├─主キー：Long
│
├─検索メソッド
│    ├─表題で検索：List<Book> findByTitle(String title)
│    ├─表題の部分一致：List<Book> findByTitleContaining(String keyword)
│    └─価格の降順で全件：List<Book> findAllByOrderByPriceDesc()
│
├─メソッド：searchByPriceAndTitle
│     ├─目的：価格と表題で検索する
│     ├─引数
│     │    ├─上限価格：Integer price
│     │    └─表題のキーワード：String title
│     ├─戻り値：List<Book>、書籍のリスト
│     └─JPQL：価格がprice以下で表題にtitleを含む書籍を検索し、価格の昇順に並べて返す
│
└─メソッド：searchByPriceRange
      ├─目的：価格の範囲で検索する
      ├─引数
      │    ├─下限価格：Integer minPrice
      │    └─上限価格：Integer maxPrice
      ├─戻り値：List<Book>、書籍のリスト
      └─JPQL：価格がminPrice以上かつmaxPrice以下の書籍を検索し、価格の昇順に並べて返す
```

### 生成規則

```java
public interface BookRepository extends JpaRepository<Book, Long> {
    List<Book> findByTitle(String title);               // 表題で検索
    List<Book> findByTitleContaining(String keyword);   // 表題の部分一致
    List<Book> findAllByOrderByPriceDesc();             // 価格の降順で全件

    /**
     * 価格と表題で検索する
     *
     * @param price 上限価格
     * @param title 表題のキーワード
     * @return 書籍のリスト
     */
    // JPQL：価格がprice以下で表題にtitleを含む書籍を検索し、価格の昇順に並べて返す
    @Query("SELECT b FROM Book b WHERE b.price <= :price AND b.title LIKE CONCAT('%', :title, '%') ORDER BY b.price ASC")
    List<Book> searchByPriceAndTitle(@Param("price") Integer price, @Param("title") String title);

    /**
     * 価格の範囲で検索する
     *
     * @param minPrice 下限価格
     * @param maxPrice 上限価格
     * @return 書籍のリスト
     */
    // JPQL：価格がminPrice以上かつmaxPrice以下の書籍を検索し、価格の昇順に並べて返す
    @Query("SELECT b FROM Book b WHERE b.price >= :minPrice AND b.price <= :maxPrice ORDER BY b.price ASC")
    List<Book> searchByPriceRange(@Param("minPrice") Integer minPrice, @Param("maxPrice") Integer maxPrice);
}
```

- `対象` と `主キー` から `JpaRepository<対象, 主キー>` を組み立てる。
- **`主キー` の型は、対象のエンティティの `@主キー` のフィールドの型と同じでなければならない。**
  エンティティのSPD（または生成済みのファイル）と照らし合わせ、違う場合は生成せず【確認事項】に載せること。
  エンティティが参照できない場合は、SPDのとおりに生成し、照合できなかったことを【確認事項】に書く。
- **`interface` として生成する。** `@Repository` は付けない（Spring Data JPA が自動検出するため）。
- `検索メソッド` が無い、または `検索メソッド：なし` の場合は、その部分のメソッドを生成しない（これは未記入ではない）。
  `メソッド：` も無ければ、メソッドを持たない空のインタフェースになる。

### 検索メソッド（命名規約によるメソッド）

- `検索メソッド` の各行は、`<説明>：<シグネチャ>` の形である。シグネチャは**そのまま**宣言にし、
  説明は行末の行コメントにする。本体は書かない。
- メソッド名がSpring Dataの命名規約に合わない場合は、**推測で `@Query` を補わず**、
  `## 0.8` の報告の【確認事項】に載せること。命名規約で書けない検索は、下の `メソッド：` と `JPQL` で書く。
- **メソッド名に含まれるフィールド名（`findByTitle` の `Title`、`OrderByPriceDesc` の `Price` など。先頭を小文字にして読む）が、
  対象のエンティティにあることを確かめる。** 無い場合（`findByTitel` など）は、その行を生成せず【確認事項】に載せること
  （コンパイルは通っても、アプリの起動時にエラーになるため）。名前を推測で直してはならない。
  エンティティが参照できない場合は、SPDのとおりに生成し、照合できなかったことを【確認事項】に書く。

### JPQL によるメソッド（`メソッド：` ＋ `JPQL`）

リポジトリの `メソッド：` は、`目的`・`引数`・`戻り値` を持ち、**`処理` の代わりに `JPQL` を書く。**
JPQL が処理の本体に当たるからである。

| ノード | 生成されるもの |
|---|---|
| `メソッド：名前` | インタフェースの抽象メソッド（`spd-core` の `## 9.6.6` と同じ Javadoc を付ける） |
| `引数` の各行 | 引数。**すべての引数に `@Param("<変数名>")` を付ける** |
| `JPQL：<自然文>` | 自然文から組み立てた `@Query("…")`。直前に `// JPQL：<自然文>` の行コメントを付ける |
| `JPQL："<JPQL文>"` | 引用符の中をそのまま `@Query("…")` にする |

- **`JPQL` の指示は特別なものとして扱い、自然文から必ず `@Query` を生成する。**
  `検索メソッド` の「推測で `@Query` を補わない」という規則の例外である。
- **`JPQL` で書けるのは検索（`SELECT`）だけである。** 更新・削除（「〜を削除する」「〜を更新する」）は、
  `@Modifying` とトランザクションが要るため当面の対象外とし、生成せず【確認事項】に載せること。
- `引数` にはマーカーを書かなくてよい。**リポジトリでは、マーカーの有無にかかわらず `@Param` を付ける**
  （`@パラメータ` と書いてもよく、結果は同じである。コントローラーの `@パラメータ`（`@RequestParam`）とは意味が違う）。
- JPQL の中では、エンティティのクラス名とフィールド名を使う（テーブル名・列名ではない）。
  別名はエンティティ名の先頭の1文字を小文字にしたもの（`Book` → `b`）とする。
- `JPQL` の代わりに `処理` が書かれていた場合は、生成せず【確認事項】に載せること（インタフェースには処理を書けない）。

**条件の読み方（フィールドと引数の対応）**

自然文の条件は、「**<フィールド>が<引数>以下**」のように、比べるフィールドと引数で書く。

- **フィールドは、エンティティのフィールド名（`price`）か、エンティティのSPDのフィールドの説明（`価格：Integer price` の `価格`）で名指しする。**
  このとき、引数名はフィールド名と違ってよい（`価格がminPrice以上` → `b.price >= :minPrice`）。
- 1つのフィールドに続けて条件を書くときは、2つ目からフィールドを省いてよい。省いた条件は直前のフィールドに付く
  （`価格がminPrice以上かつmaxPrice以下` → `b.price >= :minPrice AND b.price <= :maxPrice`）。
- フィールドを名指しせずに引数だけを書いた条件（`price以下` など）は、**引数名と同じ名前のフィールド**との条件として読む。
  同じ名前のフィールドが無い場合は、そのメソッドを生成せず【確認事項】に載せること。
- **引数の型は、比べるフィールドの型と同じにする。** 違う場合（`Integer` のフィールドに `BigDecimal` の引数など）は
  生成せず、【確認事項】に載せること（Hibernate 6 は、パラメータの型が合わないと実行時に例外を投げる）。
- 名指ししたフィールドがエンティティに無い場合、自然文の中の条件・並び順がフィールドや引数に対応づけられない場合も、
  生成せず【確認事項】に載せること。
- 自然文で表しにくい検索は、`JPQL："…"` と JPQL 文を直接書いてもらう。直接書かれた JPQL 文は、名前の照合をせずにそのまま使う。

**自然文の読み方**

| 自然文 | JPQL |
|---|---|
| `priceがX以下`・`以上`・`より小さい`・`より大きい` | `b.price <= :X`・`>=`・`<`・`>` |
| `dateがX以前`・`以降`・`より前`・`より後` | `b.date <= :X`・`>=`・`<`・`>` |
| `titleがXと等しい`・`titleがX` | `b.title = :X` |
| `titleがXと等しくない` | `b.title <> :X` |
| `titleにXを含む` | `b.title LIKE CONCAT('%', :X, '%')` |
| `titleがXで始まる`・`Xで終わる` | `b.title LIKE CONCAT(:X, '%')`・`LIKE CONCAT('%', :X)` |
| `titleが空である`・`空でない` | `b.title IS NULL`・`IS NOT NULL` |
| `〜かつ〜`・`〜で〜`（条件の連結） | `AND` |
| `〜または〜` | `OR` |
| `priceの昇順に並べる`・`降順` | `ORDER BY b.price ASC`・`DESC` |
| `件数を返す` | `SELECT COUNT(b) FROM …` |

- 表の `price`・`title`・`date` は例であり、フィールドは日本語の説明（`価格`）で書いてもよい。引数は必ず変数名で書く。
- `空である` は値が無い（`null`）ことを表す。空文字（`""`）との比較は `titleが""と等しい` のように書く。
- `LIKE %:title%` の形（Spring Data 独自の拡張）は生成しない。標準の `CONCAT` を使う。

## 20.5 エンティティ

### 記法

```
エンティティ：Member
│
├─目的：会員を表すエンティティ
├─テーブル：members
│
├─フィールド
│  ├─番号：@主キー @自動採番 Long id
│  ├─名前：@必須 @文字数(20) String name
│  ├─メール：@一意 String email
│  ├─入会日：LocalDate joinedOn
│  ├─年会費：@精度(8, 2) BigDecimal annualFee
│  └─タグ：@値コレクション Set<String> tags
│
├─関連
│  └─所属：多対一 Department department
│
└─自動生成
     ├─コンストラクタ：引数なし
     ├─ゲッター
     └─セッター
```

### フィールドのマーカー

マーカーの `@` は全角 `＠` で書いてもよい（`## 20.1`）。


| マーカー | 生成されるアノテーション |
|---|---|
| `@主キー` | `@Id` |
| `@自動採番` | `@GeneratedValue(strategy = GenerationType.IDENTITY)` |
| `@必須` | `@Column(nullable = false)` |
| `@一意` | `@Column(unique = true)` |
| `@文字数(N)` | `@Column(length = N)`（文字列の長さの上限） |
| `@精度(P, S)` | `@Column(precision = P, scale = S)`（全体の桁数 P、小数点以下の桁数 S） |
| `@列名(x)` | `@Column(name = "x")` |
| `@値コレクション` | `@ElementCollection` |
| （マーカーなし） | アノテーションを付けない |

- 複数のマーカーは1つの `@Column` にまとめる（`@必須 @一意` → `@Column(nullable = false, unique = true)`。
  `@必須 @精度(10, 2)` → `@Column(nullable = false, precision = 10, scale = 2)`）。
- `@主キー` が1つも無い場合は、生成せず `## 0.8` の報告の【確認事項】に載せること。
- **`@自動採番` は、`@主キー` を付けた `Long`・`Integer` のフィールドにだけ付けられる。** `@主キー` の無いフィールドや、
  `String` などの型に付いていた場合は、生成せず【確認事項】に載せること（起動時か保存時にエラーになるため）。
  `long`・`int` の基本型の場合は生成したうえで、ラッパー型（`Long`・`Integer`）を勧める旨を【確認事項】に書く
  （保存前の id が `0` になり、新しいエンティティかどうかの判断を誤りやすいため）。
- **`@文字数(N)` は `String` のフィールドにだけ付けられる。** **`@精度(P, S)` は `BigDecimal` のフィールドにだけ付けられる**（`P` は `S` 以上）。
  ほかの型に付いていた場合は、効果が無い（または誤った指定になる）ため、生成せず【確認事項】に載せること。
- 以前の `@桁数(N)` は、規約に無い書き方として報告し、`@文字数(N)` を案内する（`## 20.1`）。
- `@値コレクション` は、要素が文字列・ラッパークラス・`@Embeddable` クラスである `List`・`Set`・`Map` のフィールドに付ける。
  要素がエンティティの場合は `フィールド` ではなく `関連` に書く。
- `@値コレクション` には `@CollectionTable`・`@Column` を付けず、テーブル名・列名はJPAの既定の命名に任せる。
  他のマーカー（`@必須`・`@一意` など）と組み合わせてはならない。組み合わされていた場合は生成せず、
  `## 0.8` の報告の【確認事項】に載せること。
- 日付・時刻のフィールドは `java.time` の型（`LocalDate`・`LocalDateTime`・`LocalTime` など）で書き、
  **アノテーションを付けない。** 型から保存形式が決まるため、`@Temporal` は不要である
  （`java.time` の型に付けると、Hibernate 6 では起動時にエラーになる）。
- SPDに `Date`・`Calendar`（`java.util.Date`・`java.sql.Date`・`java.util.Calendar`）が書かれていた場合は生成せず、
  `java.time` の型への書き換えを促す旨を `## 0.8` の報告の【確認事項】に載せること。

### 関連のマーカー

| SPDの記述 | 生成 |
|---|---|
| `所属：多対一 Department department` | `@ManyToOne(fetch = FetchType.LAZY)` + `@JoinColumn(name = "department_id")` |
| `受講：一対多 List<Enrollment> enrollments ※mappedBy=member` | `@OneToMany(mappedBy = "member")` |
| `詳細：一対一 MemberDetail detail` | `@OneToOne` |
| `資格：多対多 List<License> licenses` | `@ManyToMany` |

- **`多対一`・`一対一` は必ず `fetch = FetchType.LAZY` を付ける。** N+1問題を避けるためである。
- `一対多`・`多対多` は既定で遅延読み込みのため、`fetch` を書かない。
- `@JoinColumn` の既定の列名は `<フィールド名>_id` とする。`※列名=…` の指定があればそれに従う。

### その他

- クラスには `@Entity` を付ける。`テーブル` ノードがある場合は `@Table(name = "…")` も付ける。
- **JPAは引数なしコンストラクタを必要とする。** `自動生成` に `コンストラクタ：引数なし` が
  書かれていない場合でも補い、その旨を宣言の直前に行コメント1行で明示する。
- `自動生成` の各項目（ゲッター・セッター・toString・等値判定）は `spd-core` の `## 9.6.4` に従う。
- `等値判定` は主キーだけを対象にすることが望ましい。`←` の指定が無い場合は主キーを対象とし、
  その旨を行コメントで明示する。
- **主キーを対象とする `等値判定` は、`spd-core` の `## 9.6.4` の形ではなく、次の JPA 向けの形で生成する。**
  保存前のエンティティは主キーが `null` なので、主キーどうしを比べるだけでは保存前のものがすべて等しくなる。
  また、保存すると主キーが入るので、主キーから作る `hashCode` は保存の前後で変わり、`HashSet` などに入れたものを見失う。

  ```java
  // 等値判定：主キー（id）で比べる。保存前（id が null）のものは、自分自身とだけ等しい
  @Override
  public boolean equals(Object o) {
      if (this == o) {
          return true;
      }
      if (!(o instanceof Member other)) {
          return false;
      }
      return id != null && id.equals(other.id);
  }

  // 保存の前後で変わらないよう、クラスごとに一定の値を返す
  @Override
  public int hashCode() {
      return getClass().hashCode();
  }
  ```

  `等値判定 ← email` のように主キー以外のフィールドを指定した場合は、`spd-core` の `## 9.6.4` の形で生成する。

## 20.6 フォーム

### 記法

```
フォーム：BookForm
│
├─目的：書籍の入力フォーム
│
├─フィールド
│    ├─主キー：Long id
│    ├─表題：String title　　　　　＠必須("表題を入力してください")、＠20文字以内
│    ├─発行日：LocalDate issuedOn　＠過去の日付
│    ├─価格：Integer price
│    │        ＠必須("価格を入力してください")
│    │        ＠0以上("価格は0以上で入力してください")
│    │        ＠1000000以下("価格は1,000,000以下で入力してください")
│    ├─ISBN：String isbn　＠"^$|^[0-9-]{10,17}$"に一致
│    └─メディア：List<String> mediaTypes
│              ＠必須("メディアを1つ以上選択してください")
│              ＠3個以内("メディアは3つまで選べます")
│
└─自動生成
      ├─コンストラクタ：引数なし
      ├─ゲッター
      └─セッター
```

**フィールドの検証は、検証ごとに `@`（全角 `＠` でもよい。`## 20.1`）を付けて書く。**
書く場所は、次の2つのどちらかである。

1. **フィールドの行の末尾**：変数名の後に並べる（`＠必須、＠20文字以内`）。
2. **フィールドの行の下の行**：フィールドの行のすぐ下に、枝（`├─`・`└─`）を付けずに書く。
   検証が多いときやメッセージが長いときに、行が横に長くならないようにするためである。
   - フィールドの `├─`・`└─` より深く字下げする。深さは問わない。
   - 縦線 `│` は、親の枝が続いていれば通常どおり引く（最後のフィールドの下では引かない）。
   - 検証の行の間に `※` のコメント行（`spd-core` の `## 9.3` ルール6）を挟んでもよい。
   - 1行に1つずつ書くことを勧めるが、1行に複数書いてもよい。

- 検証が無いフィールドには `@` を書かない。
- **1つのフィールドで、行の末尾と下の行の両方に検証を書いてはならない。**
  書かれていた場合は生成せず、【確認事項】に載せること。
- **1行に複数の検証を書くときは、検証ごとに `@` を付ける。** 区切りは `、` または1文字以上の空白（半角・全角）とする。
  `@` の前後の空白は、半角・全角・個数を問わず無視する。位置をそろえるために空白を入れてよい。
- **1つの `@` の後に検証を2つ以上書いてはならない**（`＠必須、20文字以内`。以前の版の書き方）。
  `,` で区切った場合（`＠必須,＠20文字以内`）も含め、規約に無い書き方として生成せず、
  検証ごとに `@` を付けるよう【確認事項】に載せること。
- アノテーションは、書かれた順（下の行に書いた場合は上の行から）に並べる。
- **エンティティのマーカー（`## 20.5`）は型の前に書くが、フォームの検証は変数名の後（または下の行）に書く。**
  エンティティのマーカーは1語ずつアノテーションに対応するが、検証は「20文字以内」のような句であり、
  並べて書く方が読みやすいためである。エンティティに `@` で始まる行が書かれていた場合は、生成せずに報告する。
- **正規表現は `"` で囲む**（`"^[0-9-]{10,17}$"に一致`）。
- **メッセージは、検証の直後の `()` の中に `"` で囲んで書く**（`必須("表題を入力してください")`）。
  括弧は全角 `（）` でもよい。括弧の内側で引用符の外にある空白（`（ "…" ）`）は無視する。
- **引用符の中の `@`・`＠`・`、`・`,`・空白・括弧は、検証の始まりや区切りとみなさない**
  （`"^[^@]+@[^@]+$"に一致` の `@` は検証の始まりではない）。
- **`検証` の枝は廃止した。** フォームに `検証` の枝が書かれていた場合は生成せず、
  検証を各フィールドの行の末尾か下の行へ移すよう `## 0.8` の報告の【確認事項】に載せること。

### 検証の対応表

| SPDの記述 | 生成されるアノテーション |
|---|---|
| `必須`（`String` の場合） | `@NotBlank` |
| `必須`（`List`・`Set`・`Map` の場合） | `@NotEmpty` |
| `必須`（上記以外） | `@NotNull` |
| `N文字以内` | `@Size(max = N)` |
| `N文字以上` | `@Size(min = N)` |
| `N文字以上M文字以内` | `@Size(min = N, max = M)` |
| `N個以内`（コレクション） | `@Size(max = N)` |
| `N個以上`（コレクション） | `@Size(min = N)` |
| `N個以上M個以内`（コレクション） | `@Size(min = N, max = M)` |
| `N以上` | `@Min(N)` |
| `M以下` | `@Max(M)` |
| `N以上M以下` | `@Min(N)` + `@Max(M)` |
| `N以上`（N が小数） | `@DecimalMin("N")` |
| `M以下`（M が小数） | `@DecimalMax("M")` |
| `N以上M以下`（N・M のどちらかが小数） | `@DecimalMin("N")` + `@DecimalMax("M")` |
| `N超`・`Nより大きい` | `@DecimalMin(value = "N", inclusive = false)` |
| `M未満` | `@DecimalMax(value = "M", inclusive = false)` |
| `N以上M未満` | `@DecimalMin("N")` + `@DecimalMax(value = "M", inclusive = false)` |
| `N超M以下`・`Nより大きくM以下` | `@DecimalMin(value = "N", inclusive = false)` + `@DecimalMax("M")` |
| `N超M未満`・`Nより大きくM未満` | `@DecimalMin(value = "N", inclusive = false)` + `@DecimalMax(value = "M", inclusive = false)` |
| `整数N桁以内` | `@Digits(integer = N, fraction = 0)` |
| `整数N桁・小数M桁以内` | `@Digits(integer = N, fraction = M)` |
| `正の数` | `@Positive` |
| `正の数または0` | `@PositiveOrZero` |
| `負の数` | `@Negative` |
| `負の数または0` | `@NegativeOrZero` |
| `trueである` | `@AssertTrue` |
| `falseである` | `@AssertFalse` |
| `過去の日付` | `@Past` |
| `今日以前の日付` | `@PastOrPresent` |
| `未来の日付` | `@Future` |
| `今日以降の日付` | `@FutureOrPresent` |
| `値なし` | `@Null` |
| `メール` | `@Email` |
| `URL` | `@URL` |
| `クレジットカード番号` | `@CreditCardNumber` |
| `ISBN` | `@ISBN` |
| `ISBN-10` | `@ISBN(type = ISBN.Type.ISBN_10)` |
| `"<正規表現>"に一致` | `@Pattern(regexp = "…")` |

- 対応表に無い表現は、**推測でアノテーションを作らず**、`## 0.8` の報告の
  【確認事項】に載せること。
- コレクションの `必須` を `@NotNull` にしてはならない。チェックボックスを1つも選ばずに送信すると、
  Spring は `null` ではなく空のコレクションを設定するため、`@NotNull` では検証が働かない。
- **`boolean`・`Boolean` の `必須` は、チェックを強制しない。** `th:field` のチェックボックスは、
  チェックしないと `false` を送るため、`必須`（`@NotNull`）では検証が働かない。
  チェックを求める場合（利用規約への同意など）は `trueである`（`@AssertTrue`）と書く。
- **小数の判定**：`N以上`・`M以下`・`N以上M以下` は、N・M に小数点が無ければ `@Min`・`@Max` を、
  あれば `@DecimalMin`・`@DecimalMax` を生成する。`@DecimalMin`・`@DecimalMax` の値は文字列で書く。
  `超`・`より大きい`・`未満` は、整数でも `@DecimalMin`・`@DecimalMax` に `inclusive = false` を付けて生成する
  （`M未満` を `@Max(M-1)` のように読み替えない）。N・M には負の数（`-10以上`）も書ける。
- `正の数または0` は `0以上`（`@Min(0)`）とほぼ同じ働きをするが、`double` にも使える。どちらを書いてもよい。
- `今日以前の日付`・`今日以降の日付` の「今日」は、`LocalDateTime`・`LocalTime` では現在の時刻を意味する。
- **`値なし`（`@Null`）は、`String` には使えない。** 空の入力欄は `null` ではなく `""` を送るため、
  何も入力しなくても検証に失敗する。`String` 以外の型か、画面に置かない項目にだけ使う。
  `String` の `値なし` は生成せず、【確認事項】に載せること。
- `@Length`（Hibernate Validator）は使わない。文字数の検証は `@Size` で生成する。
- 正規表現は、Javaの文字列リテラルとして正しくなるよう、`\` を `\\` に、`"` を `\"` にして `regexp` に書く
  （`"^\d{3}$"に一致` → `@Pattern(regexp = "^\\d{3}$")`）。
- **メッセージ（`message = "…"`）は、SPDに明示された場合だけ付ける。**
  `必須("表題を入力してください")` → `@NotBlank(message = "表題を入力してください")`。
  1つの検証から2つのアノテーションができる場合（`N以上M以下`）は、両方に同じメッセージを付ける。
- 1つのフィールドに複数の検証がある場合、アノテーションは**SPDに書かれた順**に並べる。
- **フォームに永続化アノテーション（`@Entity`・`@Column` など）を付けてはならない。**
- 検証アノテーションは `jakarta.validation.constraints.*` を使う（`javax.*` ではない）。
  ただし `@URL`・`@CreditCardNumber`・`@ISBN` は Hibernate Validator のもので、
  `org.hibernate.validator.constraints.*` から取る（`spring-boot-starter-validation` に含まれる）。

### 検証とフィールドの型

**検証は、書ける型のフィールドにだけ書ける。** 型に合わない検証（`Integer` の `20文字以内` など）は、
コンパイルは通っても、送信したときに `UnexpectedTypeException` が起きて画面がエラーになる。
型に合わない検証は**その検証を生成せず**、【確認事項】に載せること（フィールドとほかの検証は生成する）。

| 検証 | 書ける型 |
|---|---|
| `必須` | すべての型（基本型・`boolean` については下記） |
| `N文字以内`・`N文字以上`・`N文字以上M文字以内` | `String` |
| `N個以内`・`N個以上`・`N個以上M個以内` | `List`・`Set`・`Map` |
| `N以上`・`M以下`・`N超`・`Nより大きい`・`M未満` とその組み合わせ、`整数N桁以内`・`整数N桁・小数M桁以内`、`正の数`・`正の数または0`・`負の数`・`負の数または0` | 数値の型（`Integer`・`Long`・`Short`・`Byte`・`BigDecimal`・`BigInteger`・`Double`・`Float` と、その基本型） |
| `過去の日付`・`今日以前の日付`・`未来の日付`・`今日以降の日付` | `LocalDate`・`LocalDateTime`・`LocalTime` |
| `trueである`・`falseである` | `boolean`・`Boolean` |
| `値なし` | `String` 以外のすべての型 |
| `メール`・`URL`・`クレジットカード番号`・`ISBN`・`ISBN-10`・`"<正規表現>"に一致` | `String` |

- コレクションに `N文字以内` などを書いた場合も、型に合わない検証として報告し、`N個以内` などを案内する。
- 型が `String` で、内容が数字の項目（郵便番号など）の桁や範囲は、`"<正規表現>"に一致` で書いてもらう
  （`N以上`・`N桁以内` は数値の型にだけ書ける）。

### 空欄を受け付けない検証

入力欄を空のまま送信すると、`String` のフィールドには `null` ではなく空文字（`""`）が入る。
そのため、次の検証は、**`必須` を書かなくても空欄を受け付けない**。

| 検証 | 空欄（`""`）の扱い |
|---|---|
| `N文字以上`・`N文字以上M文字以内` | 0文字なのでエラー |
| `"<正規表現>"に一致` | 正規表現が空文字に一致しなければエラー |

- 空欄を許す項目に正規表現を書くときは、`"^$|^[0-9-]{10,17}$"` のように、空文字にも一致する形で書いてもらう。
- このことは生成時に報告しない（書いた人の意図が「入力を求める」場合もあるため）。
- `メール`・`URL`・`ISBN` などは、空文字を正しい値とみなすので、空欄を受け付ける。

### 数値の基本型

**フォームの数値のフィールドは、ラッパー型（`Integer`・`Long`・`Double` など）で書く。**
基本型（`int`・`long`・`short`・`byte`・`double`・`float`）では、空欄で送信したときに `null` を入れられず、
変換エラー（画面には `Failed to convert property value…` という英語のメッセージが出る）になる。`必須` も働かない。

- 数値の基本型のフィールドは、**生成したうえで**、ラッパー型を勧める旨を【確認事項】に書く。
- `boolean` は、チェックボックスに使うので対象外とする（チェックしないと `false` が送られる）。

### 主キーのフィールド

- 更新画面で使うフォームには、エンティティの主キーと同じ名前・同じ型のフィールドを置く（`## 20.3` の `更新`）。
- **主キーのフィールドに `必須` を書いてはならない。** 新規作成では主キーの値が無いので、検証が必ず失敗する。
  対象のエンティティ（`## 20.3` と同じく、フォーム名から `Form` を除いた名前のエンティティ）が参照でき、
  その `@主キー` と同じ名前のフィールドに `必須` が書かれていた場合は、**生成したうえで**【確認事項】に載せる。
  エンティティが参照できない場合は、この確認をしない。

### 自動生成

- **フォームには、`自動生成` に `ゲッター` と `セッター` の両方が要る。**
  送信された値はセッターで設定され、`th:field` はゲッターで値を表示する。どちらかが無いと、
  エラーにならないまま値が `null` になる。
- `ゲッター`・`セッター` のどちらか（または `自動生成` そのもの）が無い場合は、**SPDのとおりに生成したうえで**、
  【確認事項】に載せること。推測で補ってはならない。
- `自動生成` の各項目は `spd-core` の `## 9.6.4` に従う。

### 対象外の検証

次の検証は、当面の対象外である。SPDに書かれていた場合は、推測で生成せず【確認事項】に載せること。

- 複数のフィールドを比べる検証（パスワードと確認用のパスワードが等しい、開始日が終了日以前など）
- 登録と更新で検証を変える検証グループ（`groups`）
- フォームの中のフォーム（フィールドに `@Valid` を付けて、入れ子のオブジェクトを検証する）

### 日付・時刻のフィールド

**フォームの `java.time` のフィールドには、検証の有無にかかわらず `@DateTimeFormat` を必ず付ける。**
付けないと、`<input type="date">` などが送る ISO 形式の値（`2026-09-28`）を変換できず、バインドエラーになる。

| 型 | 生成されるアノテーション | 対応する入力欄 |
|---|---|---|
| `LocalDate` | `@DateTimeFormat(iso = DateTimeFormat.ISO.DATE)` | `<input type="date">` |
| `LocalDateTime` | `@DateTimeFormat(iso = DateTimeFormat.ISO.DATE_TIME)` | `<input type="datetime-local">` |
| `LocalTime` | `@DateTimeFormat(iso = DateTimeFormat.ISO.TIME)` | `<input type="time">` |

- `@DateTimeFormat` は `org.springframework.format.annotation.DateTimeFormat` を使う。
- 検証アノテーションの後、フィールド宣言の直前に置く。
- エンティティには付けない（エンティティは画面から直接バインドしないため）。
- `Date`・`Calendar` の扱いはエンティティと同じく、生成せずに報告する（`## 20.5`）。

### 生成例

上の `BookForm` のフィールド部分：

```java
private Long id; // 主キー

@NotBlank(message = "表題を入力してください")
@Size(max = 20)
private String title; // 表題

@Past
@DateTimeFormat(iso = DateTimeFormat.ISO.DATE)
private LocalDate issuedOn; // 発行日

@NotNull(message = "価格を入力してください")
@Min(value = 0, message = "価格は0以上で入力してください")
@Max(value = 1000000, message = "価格は1,000,000以下で入力してください")
private Integer price; // 価格

@Pattern(regexp = "^$|^[0-9-]{10,17}$")
private String isbn; // ISBN

@NotEmpty(message = "メディアを1つ以上選択してください")
@Size(max = 3, message = "メディアは3つまで選べます")
private List<String> mediaTypes; // メディア
```

## 20.7 共通の生成規約（入出力・例外・パッケージ・インポート・SPDの残し方）

`spd-core` の共通規約に、次を上乗せする。

### 入出力

**このワークスペースでは `System.out` / `System.err` を使わない。**
SE版の `Input` クラスによるコンソール入出力も**使用しない**（Web アプリには入力の受け口が無い）。

| SPDの記述 | 生成 |
|---|---|
| `"<メッセージ>"をログに出す`・`記録する` | `log.info(...)` |
| `"<メッセージ>"を警告としてログに出す` | `log.warn(...)` |
| `"<メッセージ>"をエラーとしてログに出す` | `log.error(...)` |
| `"<メッセージ>"を例外<変数>とともにエラーとしてログに出す` | `log.error("…", <変数>)`（`警告として` なら `log.warn`） |
| 画面に表示する | Model経由で渡し、テンプレート側で表示（`## 11.2`） |

**ロガーは自動で補う。**

- メソッドの `処理` に、上の表のログの行が1つでもあれば、クラスに次のフィールドを補う。
  `フィールド` に書かなくてよい。
  ```java
  // SPDに無いため Logger log を補った
  private static final Logger log = LoggerFactory.getLogger(MemberService.class);
  ```
- `getLogger` の引数は、生成するクラス自身とする。フィールドの先頭（インジェクションのフィールドより前）に置く。
- SPDの `フィールド` に `Logger` 型のフィールドが書かれていれば、補わずにそれを使う（名前が `log` でなくてもその名前で呼ぶ）。
- ログの行が無ければ、ロガーは補わない。
- コントローラー・サービスのほか、`処理` を持つ型（`クラス:` など）でも同じに扱う。

**メッセージの書き方**

- メッセージは `"…"` で囲む。**値は、メッセージの中に `{…}` で Java の式を書いて埋め込む。**
  `{…}` の部分を SLF4J のプレースホルダー `{}` にし、式を書かれた順に後ろの引数に並べる。
  ```
  ├─"会員 {member.getId()} を登録した"をログに出す
  ├─"{memberForm.getName()} さんの登録で {result.getErrorCount()} 件のエラーがあった"を警告としてログに出す
  ```
  ```java
  log.info("会員 {} を登録した", member.getId());
  log.warn("{} さんの登録で {} 件のエラーがあった", memberForm.getName(), result.getErrorCount());
  ```
- **文字列の `+` でつないだ形（`"会員 " + member.getId() + " を登録した"`）は生成しない。**
- `{…}` の中は、`処理` のほかの行と同じく Java の式として読む。`{member.id}` のような Thymeleaf の書き方は使えない
  （`member.id` は Java ではフィールドを直接読む式になり、`private` のフィールドには使えない）。
  式として成り立たない場合は、その行を生成せず【確認事項】に載せること。
- **例外を一緒に記録するとき**は、`例外<変数>とともに` と書く。例外は最後の引数にする
  （SLF4J は、最後の引数が例外ならスタックトレースを出す）。
  ```
  ├─"会員 {id} の削除に失敗した"を例外eとともにエラーとしてログに出す
  ```
  ```java
  log.error("会員 {} の削除に失敗した", id, e);
  ```
- メッセージを `"…"` で囲まずに書いた行（`登録した会員のidをログに出す`）は、推測で文を作らず、
  生成せず【確認事項】に載せること。

- SPDに `コンソールに表示する`・`コンソールに出力する` と書かれていた場合は、`log.info` などに読み替えず、
  その行を生成せず【確認事項】に載せ、`"…"をログに出す` と書くよう案内すること。

### 例外処理

`spd-core` の共通規則（握りつぶさない／try-with-resources を優先）はそのまま適用する。

**生成するもの**

- SPDの `処理` に書かれた `〜を投げる`・`try`・`catch` は、`spd-core` のとおりに生成する。

**生成しないもの**

- **SPDに書かれていない `catch` を補ってはならない。** コントローラー・サービスで例外を受け止めて握りつぶすコードも生成しない。
- `@ExceptionHandler`・`@ControllerAdvice` による例外の受け止めと、データが見つからないときの画面の切り替え
  （404 の画面・一覧へ戻すなど）は、当面の対象外である（`## 20.1`）。

**「見つからない」の2つの場合**

データが見つからない場合は、次の2つで扱いが違う。

| 場合 | 例 | 使うもの | 見つからないとき |
|---|---|---|---|
| **利用者が入力した条件で探す** | 表題・名前で検索する画面 | `List` を返す検索メソッド（`## 20.4`） | **空のリスト**が返る。例外にはならない。テンプレートの条件表示で「見つかりませんでした」と表示する |
| **アプリが渡した主キーで探す** | 一覧のリンクから開く編集・削除、更新の送信 | サービスの `主キーで検索`（`findById(id).orElseThrow()`） | **異常として** `NoSuchElementException` が投げられ、エラーの画面になる |

- 後者で見つからないのは、他の利用者による削除・URL の書き換え・プログラムの誤りなどの異常な場合に限られるため、
  処理を止めてエラーの画面を出す。
- **利用者が主キーそのもの（会員番号など）を入力して探す画面**は前者に当たる。サービスの `主キーで検索` は使わず、
  `List<Member> findByMemberNo(String memberNo)` のような検索メソッドを書いてもらう。
  入力された値で `主キーで検索` を呼ぶ `処理` を見つけた場合は、生成したうえで【確認事項】にこのことを書く。
- `Optional` からの取り出しは、引数なしの `orElseThrow()` を既定とする。

### 骨格

- 型定義のタイトルが `コントローラー:`（`コントローラ:` も可）・`サービス:`・`リポジトリ:`・`エンティティ:`・`フォーム:` の
  いずれかであれば、このファイルの規約で生成する。
- タイトルが `設定ファイル:` のSPDは、Javaのコードではなく `application.properties` を生成する（`## 20.10`）。
- それ以外のタイトル（`クラス:`・`レコード:` など）は、`spd-core` の `## 9.5` に従う通常の
  Javaの型として生成する。**Web層のアノテーションを勝手に付けてはならない。**
- **インデントは半角スペース4つとする。** タブは使わない。アノテーションは、それが付く宣言と
  同じ深さに置く（`@GetMapping` とメソッド宣言、`@Id` とフィールド宣言の字下げをそろえる）。

### パッケージ

**パッケージ名は、SPDのタイトル行の前に `※` のコメントで書く。**

```
※jp.kwebs.bookshop.entity
エンティティ：Book
├─目的：書籍を表すエンティティ
…
```
```java
package jp.kwebs.bookshop.entity;
```

- タイトル行より前にある `※` の行で、`※` の後（前後の空白を除く）がJavaのパッケージ名の形
  （英小文字で始まる語を `.` でつないだもの。`jp.kwebs.bookshop.entity`）であるものを、パッケージ名として読む。
  `※パッケージ：jp.kwebs.bookshop.entity` と書いてもよい。
- 書かれたパッケージ名を**そのまま** `package` 文にする。末尾の語（`entity` など）を下の表に合わせて直してはならない。
- この行は `package` 文になるので、`// …` の行コメントには転記しない（`spd-core` の `## 9.3` ルール6の例外）。
  ファイル冒頭に残すSPDブロックには、この行も原文のまま含める。
- 複数のSPDをまとめて与えられた場合は、SPDごとに、そのタイトル行の前の行を読む。
- テンプレート（`テンプレート:`）のSPDには書かない。書かれていても無視する。

**SPDにパッケージ名が無い場合**は、プロジェクトの基底パッケージ（`@SpringBootApplication` を付けたクラスのパッケージ）
から、次の表で決める。

| 型 | パッケージ |
|---|---|
| コントローラー | `<基底パッケージ>.controller` |
| サービス | `<基底パッケージ>.service` |
| リポジトリ | `<基底パッケージ>.repository` |
| エンティティ | `<基底パッケージ>.entity` |
| フォーム | `<基底パッケージ>.form` |

- **このスキルでは、SPDにパッケージ名が無い場合は `package` 文を書かずに生成する。** 生成を止めて尋ねてはならない。
  同じプロジェクトのクラスの import とファイルのパスの書き方は、`ガイドライン-共通.txt` の `## 10.4`・`## 10.5` に従う。
- **表に無い型**（`クラス:`・`レコード:`・`インタフェース:` など、`spd-core` の `## 9.5` で生成する型）は、
  パッケージを決められないので、SPDのタイトル行の前の `※` の行で書いてもらう。
  書かれていない場合は、上の「基底パッケージも分からない場合」と同じに扱う（推測で `dto`・`util` などを作らない）。

### インポート処理

**import 文の書き方**

- **使うクラスを1つずつ import する。** `jakarta.persistence.*` のようなワイルドカードは使わない。
- 使わないクラスの import は書かない。同じパッケージのクラスと `java.lang` のクラスは import しない。
- **並べ方は、VS Code の「インポートの整理」（Organize Imports）と同じにする。** 生成後に整理し直しても順が変わらないようにするためである。
  1. `java.*`
  2. `javax.*`
  3. `org.*`
  4. `com.*`
  5. そのほか（`jakarta.*`・`jp.*` など）
  - グループの間は空行を1つ入れ、グループの中はアルファベット順に並べる。
  - 同じプロジェクトのクラスも、パッケージ名に従って上のどこかのグループに入る（`com.example.app.entity.Member` は4、`jp.kwebs.bookshop.entity.Book` は5）。

**どこから import するか**

SPDにインポート文の明示がない場合は、次の優先順位で決定する。

1. **同一プロジェクト内のクラス**（エンティティ・フォーム・サービスなど）
2. **pom.xml に記載された依存ライブラリ**から選択する

   | 用途 | 主なパッケージ |
   |---|---|
   | コントローラー | `org.springframework.stereotype`（`Controller`）、`org.springframework.web.bind.annotation`（`GetMapping`・`PostMapping`・`RequestMapping`・`PathVariable`・`RequestParam`） |
   | 画面への受け渡し | `org.springframework.ui`（`Model`）、`org.springframework.web.servlet.mvc.support`（`RedirectAttributes`）、`org.springframework.validation`（`BindingResult`） |
   | サービス | `org.springframework.stereotype`（`Service`）、`org.springframework.transaction.annotation`（`Transactional`） |
   | リポジトリ | `org.springframework.data.jpa.repository`（`JpaRepository`） |
   | JPQL | `org.springframework.data.jpa.repository`（`Query`）、`org.springframework.data.repository.query`（`Param`） |
   | ページング | `org.springframework.data.domain`（`Page`・`Pageable`） |
   | エンティティ | `jakarta.persistence`（`Entity`・`Table`・`Id`・`GeneratedValue`・`GenerationType`・`Column` など） |
   | 入力検証 | `jakarta.validation`（`Valid`）、`jakarta.validation.constraints`（`NotBlank`・`Size` など）、`org.hibernate.validator.constraints`（`URL`・`CreditCardNumber`・`ISBN`） |
   | 日付・時刻の入力 | `org.springframework.format.annotation`（`DateTimeFormat`） |
   | ログ | `org.slf4j`（`Logger`・`LoggerFactory`） |

3. **Java 標準ライブラリ**（`java.*`）

- **依存ライブラリの正はプロジェクトの `pom.xml` である。** 上の表は代表例であり、
  `pom.xml` と食い違う場合は `pom.xml` を優先する。
- **pom.xml に存在しないライブラリは追加しないこと。** 必要な場合はユーザーに確認すること。
- **`javax.*` ではなく `jakarta.*` を使う。** Spring Boot 3 以降の前提である。

### SPDの残し方

`spd-core` の `## 9.10` と同じく、**与えられたSPD全体を1つのブロックコメント（`/* … */`）に
まとめ、そのファイルの先頭（`package` 文・`import` 文より前）に残す。** SPDブロックの下に、`package` 文・`import` 文・型定義の順に書く。

- 複数の型（コントローラー・サービス・エンティティなど）のSPDがまとめて与えられた場合は、
  **各Javaファイルに、そのファイルで定義する型のSPDだけ**を冒頭に置く。
  1つのSPD群を複数ファイルに分けて生成するときの、唯一の例外である。
- テンプレート（`テンプレート:`）のSPDは、対応するテンプレートファイルの冒頭に
  Thymeleafのコメント（`<!--/* … */-->`）として残す（`ガイドライン-Thymeleaf.txt`）。
- 設定ファイル（`設定ファイル:`）のSPDは、`application.properties` の先頭に `# ` のコメントとして残す（`## 20.10`）。

## 20.8 生成時のチェックリスト（Spring Boot 固有）

`spd-core` の `## 9.9` に加えて、次を確認する。

### 共通（`## 20.1`）

- [ ] 規約に無い書き方（以前の版の `依存`・`基底パス`・`フォームへ詰め替え`・`フォームに詰め替え → F`・`詰め替え ← F`・`@桁数(N)`、マーカーの無い `パス変数：`・`パラメータ：` など）を読み替えずに、生成せず報告したか
- [ ] 全角 `＠` のマーカー・検証も読み落としていないか。生成したアノテーションを半角の `@` にしたか
- [ ] `インジェクション` を**コンストラクタインジェクション**で注入したか。フィールドに `@Autowired` を付けていないか
- [ ] コントローラーからリポジトリを直接呼び出していないか
- [ ] REST API の指定があった場合、生成せずに報告したか
- [ ] データが見つからないときの画面の切り替え（404 の画面・一覧へ戻すなど）や `@ExceptionHandler` が書かれていた場合、推測で生成せず報告したか

### コントローラー（`## 20.2`）

- [ ] `マッピング` を `メソッド` の子としてだけ扱ったか。パスが省略または `/` だけのとき、マッピングの引数を `{"", "/"}` とし、行末に理由の行コメントを付けたか
- [ ] パスを明示した `マッピング` に、末尾に `/` を付けた別名（`{"/books", "/books/"}` など）を加えていないか
- [ ] `マッピング` のパスが `ベースパス` と同じ文字列で始まるとき、パスを直さずにSPDのとおり生成し、URL が重なることを【確認事項】で知らせたか
- [ ] `マッピング` の HTTPメソッドが `GET`・`POST` 以外のとき、生成せずに報告したか。パスの `{…}` と `@パス変数` の引数の名前が食い違うとき、名前を直さずに報告したか
- [ ] `戻り値` が省略されたハンドラーメソッドを `String` で生成し、`@return` の説明を `処理` の終わり方から決めたか。`引数：なし` でも補う引数を補ったか
- [ ] 引数の種類を、マーカー（`@検証`・`@パス変数`・`@パラメータ`）と型で決めたか。ハンドラーメソッドのマーカーの無い単純な型の引数を、推測で `@RequestParam` などにしていないか

- [ ] `@Valid` を付けた引数の**直後**に `BindingResult` を置いたか。`BindingResult result`・`Model model`・`RedirectAttributes redirectAttrs` を条件どおりに補い、それぞれ行コメントで明示したか。書かれた名前があればそれを使ったか
- [ ] `検証結果にエラーがある` を、そのメソッドの `BindingResult` の引数の `hasErrors()` にしたか。`@検証` の引数が無い・2つ以上ある場合と、`検証エラーがある` などの言い回しを報告したか
- [ ] 「〜をテンプレートに渡す」の名前を**言い換えずに**そのまま `addAttribute` の第1引数にしたか（`## 11.2`）
- [ ] サービスのメソッド名が省略されているとき、サービスに実在するメソッドから1つに決めたか。決められない場合に推測でメソッドを作らず報告したか
- [ ] `処理` の「"…"を返す」の文字列を**そのまま** `return` したか。`.html` を付けていないか。`/` で始まるテンプレート名を報告したか（`## 11.1`）
- [ ] `ベースパスにリダイレクトする` を `ベースパス` の値へのリダイレクトにしたか。`ベースパスの<パス>にリダイレクトする` を、`ベースパス` の値にパスを続け、`{名前}` を変数の連結にしたものにしたか
- [ ] フラッシュメッセージの名前が省略されたとき `message` にしたか。`addFlashAttribute` を、リダイレクトと**組で**使ったか
- [ ] 「詰め替える」を、サービスの `copyEntityToForm` の呼び出しにしたか。コントローラーでフィールドをコピーしていないか

### サービス（`## 20.3`）

- [ ] サービスに `Model` や `HttpServletRequest` を持ち込んでいないか
- [ ] `トランザクション` ノードが無い `メソッド：` に、`@Transactional` を勝手に付けていないか。`@Transactional` を `org.springframework.transaction.annotation` から取ったか
- [ ] `自動生成` は、書かれた項目だけを表どおりのシグネチャ・トランザクションで生成したか。リポジトリが `インジェクション` にあることを確かめたか
- [ ] フォームの型を省略した `新規作成`・`更新`・`詰め替え` を「エンティティ名＋Form」にしたか。`新規作成`・`更新` で、同名・同型でないフィールドを推測で詰め替えていないか
- [ ] メソッドをSPDの順に並べ、自動生成のメソッドを `自動生成` の枝の位置に置いたか
- [ ] `検索メソッド` の移譲を、リポジトリのSPDに書かれたメソッドだけについて、同名・同シグネチャ・`readOnly = true` で生成したか
- [ ] `詰め替え` を、書かれていないのに暗黙に生成していないか。`詰め替え` の1項目から `copyFormToEntity` と `copyEntityToForm` の2つを生成したか
- [ ] `copyFormToEntity` は `private void`・主キーを除いてコピー、`copyEntityToForm` は `public void`・主キーも含めてコピーとし、同じフォーム型の `詰め替え` があるとき `新規作成`・`更新` からそれを呼び出したか

### リポジトリ（`## 20.4`）

- [ ] リポジトリを `interface` として生成し、`@Repository` を付けていないか
- [ ] 命名規約に合わない `検索メソッド` に、推測で `@Query` を補っていないか。メソッド名に含まれるフィールド名がエンティティにあることを確かめ、無いものを報告したか。`主キー` の型をエンティティの主キーの型と照合したか
- [ ] `メソッド：` の `JPQL` から、必ず `@Query` を生成したか。すべての引数に `@Param` を付けたか。更新・削除の JPQL を報告したか
- [ ] JPQL の条件のフィールドを、名指しされたフィールド（説明またはフィールド名）か、名指しが無ければ引数名と同じフィールドとして読んだか。引数の型がそのフィールドの型と一致することを確かめたか
- [ ] 部分一致を `LIKE %:x%` ではなく `CONCAT` で生成したか

### エンティティ（`## 20.5`）

- [ ] エンティティに `@主キー` があったか。引数なしコンストラクタを補い、行コメントで明示したか
- [ ] `@自動採番` を `@主キー` の `Long`・`Integer` だけに付けたか。`@文字数(N)` を `String`、`@精度(P, S)` を `BigDecimal` だけに付け、ほかを報告したか
- [ ] 主キーを対象とするエンティティの `等値判定` を、id が `null` でないときだけ等しいとする `equals` と、一定の値を返す `hashCode` で生成したか
- [ ] `多対一`・`一対一` の関連に `fetch = FetchType.LAZY` を付けたか
- [ ] `@値コレクション` のフィールドに `@ElementCollection` だけを付けたか
- [ ] 日付・時刻のフィールドに `@Temporal` を付けていないか。`Date`・`Calendar` が書かれていた場合、生成せずに報告したか

### フォーム（`## 20.6`）

- [ ] フォームに永続化アノテーションを付けていないか
- [ ] フォームの検証を、フィールドの行末と、その下の枝の無い `@` の行から読んだか。検証ごとに `@` が付いているか（1つの `@` の後に2つ以上書かれていたら報告したか）。行末と下の行の両方に書かれていたら報告したか。引用符の中の `@`・`、`・空白で区切っていないか。`検証` の枝が書かれていた場合、生成せずに報告したか
- [ ] 検証の対応表に無い表現を、推測でアノテーション化していないか
- [ ] フォームの検証を、フィールドの型と照らし合わせたか。型に合わない検証（`Integer` の `N文字以内`、コレクションの `N文字以内` など）を生成せず報告したか。コレクションの個数を `N個以内` などから `@Size` にしたか
- [ ] コレクションの `必須` を `@NotEmpty` にしたか。メッセージはSPDに明示された場合だけ付けたか
- [ ] 小数を含む範囲を `@DecimalMin`・`@DecimalMax` に、`超`・`より大きい`・`未満` を `inclusive = false` にしたか。`String` の `値なし` を生成せず報告したか。`@URL`・`@CreditCardNumber`・`@ISBN` を `org.hibernate.validator.constraints` から取ったか
- [ ] フォームの `java.time` のフィールドに、型に合った `@DateTimeFormat` を付けたか
- [ ] フォームの数値の基本型、主キーのフィールドの `必須`、`ゲッター`・`セッター` の無い `自動生成` を、生成したうえで報告したか
- [ ] 複数のフィールドを比べる検証・検証グループ・入れ子のフォームを、生成せず報告したか

### 共通の生成規約（`## 20.7`）

- [ ] `System.out` / `System.err` / `Input` クラスを使っていないか。`コンソールに表示する` を読み替えずに報告したか
- [ ] `処理` にログの行があるとき、ロガー（`private static final Logger log`）をフィールドの先頭に補ったか。メッセージの `{…}` を SLF4J の `{}` と後ろの引数にし、文字列の `+` でつないでいないか。`例外<変数>とともに` の例外を最後の引数にしたか。`"…"` で囲まれていないメッセージを報告したか
- [ ] SPDに無い `catch` を補っていないか。利用者が入力した値で `主キーで検索` を呼ぶ `処理` を、生成したうえで報告したか
- [ ] インデントを半角スペース4つにし、アノテーションを付く宣言と同じ深さに置いたか。`クラス:` などのタイトルの型に、Web 層のアノテーションを付けていないか
- [ ] パッケージ名を、SPDのタイトル行の前の `※` の行から取り、そのまま `package` 文にしたか。無い場合に `package` 文を書かずに生成し、パッケージの分からない同じプロジェクトのクラスの import を推測で書かなかったか（`## 10.4`）。表に無い型（`クラス:` など）のパッケージを推測で作っていないか
- [ ] import を1クラスずつ書き（ワイルドカードなし）、使わないものを書かず、`java` → `javax` → `org` → `com` → そのほか の順に、グループの間を空行にして並べたか。`javax.*` ではなく `jakarta.*` を使ったか
- [ ] 各Javaファイルの先頭（`package` 文・`import` 文より前）に、**その型のSPDだけ**をブロックコメントとして残したか

### 設定ファイル（`## 20.10`）

- [ ] 設定ファイルのSPDを、`application.properties` の先頭に各行 `# ` を付けて原文のまま残し、項目をSPDの順に、対応表のキーで出力したか。見出し・`データベース`・ドライバークラス名・dialect を出力していないか

/*
サービス：MemberService
├─目的：会員に関する業務処理を行う
├─インジェクション

package com.example.app.service;

// 会員に関する業務処理を行う

**MemberController.java**

```java
/*
コントローラー：MemberController
├─目的：会員の一覧・登録を扱う
├─ベースパス：/members
├─インジェクション
│  └─会員サービス：MemberService memberService
├─メソッド：list
│  ├─目的：会員の一覧を表示する
│  ├─マッピング：GET
│  ├─引数：なし
│  └─処理
│        ├─memberServiceを使って、全件を読み出した結果をmemberListとしてテンプレートに渡す
│        └─"member/list"を返す
└─メソッド：create
     ├─目的：入力された会員を登録する
     ├─マッピング：POST
     ├─引数
     │    └─入力内容：@検証 MemberForm memberForm
     └─処理
           ├─◇─検証結果にエラーがある
           │  └─"member/form"を返す
           ├─memberServiceのcreateでmemberFormから会員を登録し、memberとする
           ├─"会員 {member.getId()} を登録した"をログに出す
           ├─"登録しました"をフラッシュメッセージとして渡す

package com.example.app.controller;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.validation.BindingResult;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import com.example.app.form.MemberForm;
import com.example.app.service.MemberService;

import jakarta.validation.Valid;

// 会員の一覧・登録を扱う
@Controller
@RequestMapping("/members")
public class MemberController {

    // SPDに無いため Logger log を補った
    private static final Logger log = LoggerFactory.getLogger(MemberController.class);

    private final MemberService memberService; // 会員サービス

    public MemberController(MemberService memberService) {
        this.memberService = memberService;
    }

    /**
     * 会員の一覧を表示する
     *
     * @param model モデル
     * @return 表示するテンプレート名
     */
    // SPDに無いため Model model を補った
    @GetMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため
    public String list(Model model) {
        model.addAttribute("memberList", memberService.findAll());
        return "member/list";
    }

    /**
     * 入力された会員を登録する
     *
     * @param memberForm 入力内容
     * @param result 検証結果
     * @param redirectAttrs リダイレクト先へ渡す属性
     * @return 表示するテンプレート名またはリダイレクト先
     */
    // SPDに無いため BindingResult result を補った
    // SPDに無いため RedirectAttributes redirectAttrs を補った
    @PostMapping({"", "/"}) // 末尾の / の有無どちらでも受け付けるため
    public String create(@Valid MemberForm memberForm,
                         BindingResult result,
                         RedirectAttributes redirectAttrs) {
        if (result.hasErrors()) {
            return "member/form";
        }
        var member = memberService.create(memberForm);
        log.info("会員 {} を登録した", member.getId());
        redirectAttrs.addFlashAttribute("message", "登録しました");
        return "redirect:/members";
    }
}

## 20.10 設定ファイル（application.properties）

タイトルが `設定ファイル：application.properties` のSPDから、`src/main/resources/application.properties` を生成する。
扱うのはデータベースの設定で、対象のデータベースは **H2・PostgreSQL・MySQL** の3つである。

- 設定のキーを並べるのではなく、**日本語の項目名**で書く。項目名と設定のキーの対応は、この節の表で決まっている。
- ファイル名は `application.properties` だけを認める。`application-dev.properties` のようなプロファイル別のファイルや
  `application.yml` が書かれた場合は、生成せず【確認事項】に載せること。

### 記法

```
設定ファイル：application.properties
│
└─データベース設定
      ├─データベース：<H2／PostgreSQL／MySQL>
      │
      ├─接続
      │    ├─接続URL
      │    │    └─（データベースごとの項目。下の「接続URL」）
      │    │
      │    └─認証情報
      │          ├─ユーザー名：<値>
      │          └─パスワード：<値>　　　　　※パスワードが空なら「なし」
      │
      ├─JPA
      │    ├─スキーマ自動生成：<none／validate／update／create／create-drop>
      │    ├─SQL ログを表示する　　　　　　　※または「表示しない」
      │    ├─SQL を見やすく整形する　　　　　※または「整形しない」
      │    └─Open Session in View を有効にしない　※または「有効にする」
      │
      └─H2コンソール　　　　　　　　　　　※H2 のときだけ
            ├─H2コンソールを有効にする　　　※または「有効にしない」
            └─パス：/h2-console
```

- 見出し（`データベース設定`・`接続`・`接続URL`・`認証情報`・`JPA`・`H2コンソール`）は、設定のキーのプレフィックス
  （`spring.datasource`・`spring.jpa`・`spring.h2.console`）ごとに分けたものである。見出しそのものは出力しない。
- オン・オフの項目は **「〜する」「〜しない」** で書く。`有効化`・`無効化`・`表示` などの書き方は、規約に無い書き方として報告する。
- **書かなかった項目は出力しない**（Spring Boot の既定値になる）。必要な項目だけを書けばよい。
- 項目名の中の空白の有無は問わない（`SQLログを表示する` は `SQL ログを表示する` と同じ）。

### 接続URL

`接続URL` の下の項目は、`データベース` の値で決まる。

| データベース | 項目 | 省略したとき | 生成する URL |
|---|---|---|---|
| `H2` | `DB名`・`記録場所`（`インメモリー`／`ファイル`）・`保存先`（`ファイル` のときだけ） | `記録場所` は `インメモリー`、`保存先` は `./data` | `jdbc:h2:mem:<DB名>`<br>`jdbc:h2:file:<保存先>/<DB名>` |
| `PostgreSQL` | `ホスト名`・`ポート番号`・`DB名` | `localhost`・`5432` | `jdbc:postgresql://<ホスト名>:<ポート番号>/<DB名>` |
| `MySQL` | `ホスト名`・`ポート番号`・`DB名` | `localhost`・`3306` | `jdbc:mysql://<ホスト名>:<ポート番号>/<DB名>` |

- `DB名` は必ず書く。無い場合は生成せず【確認事項】に載せること（H2 のインメモリーで DB名を省くと、
  起動のたびに名前が変わり、H2コンソールから接続しにくいため）。
- そのデータベースに無い項目（H2 の `ホスト名`、PostgreSQL の `記録場所` など）は、生成せず【確認事項】に載せること。

### 項目と出力の対応

| SPDの項目 | 出力 |
|---|---|
| `データベース：…` | 出力しない（接続URL の形と、`H2コンソール` を書けるかどうかを決める） |
| `接続URL` の下の項目 | `spring.datasource.url=…`（上の表） |
| `ユーザー名：<値>` | `spring.datasource.username=<値>` |
| `パスワード：<値>` | `spring.datasource.password=<値>` |
| `パスワード：なし` | `spring.datasource.password=`（値を空にする） |
| `スキーマ自動生成：<値>` | `spring.jpa.hibernate.ddl-auto=<値>` |
| `SQL ログを表示する`／`表示しない` | `spring.jpa.show-sql=true`／`false` |
| `SQL を見やすく整形する`／`整形しない` | `spring.jpa.properties.hibernate.format_sql=true`／`false` |
| `Open Session in View を有効にする`／`有効にしない` | `spring.jpa.open-in-view=true`／`false` |
| `H2コンソールを有効にする`／`有効にしない` | `spring.h2.console.enabled=true`／`false` |
| `パス：<値>`（`H2コンソール` の下） | `spring.h2.console.path=<値>` |
| `<設定のキー>：<値>`（`spring.` などで始まるキー） | `<設定のキー>=<値>`（表に無い設定を、キーのまま書いたもの） |

### 生成規則

- **値はSPDに書かれたまま出力する。** `スキーマ自動生成` の値を日本語から言い換えたり、別の値を選んだりしない。
  `none`・`validate`・`update`・`create`・`create-drop` 以外が書かれた場合は、その行を出力せず【確認事項】に載せること。
- **ドライバークラス名（`spring.datasource.driver-class-name`）と Hibernate の dialect は出力しない。**
  Spring Boot が接続URLから判定するためである。SPDに `ドライバークラス名` などが書かれていた場合は、
  その行を出力せず【確認事項】に載せること。
- `データベース` が `H2` でないのに `H2コンソール` がある場合は、その枝を出力せず【確認事項】に載せること。
- `データベース` が無い、または H2・PostgreSQL・MySQL 以外の場合は、ファイルを生成せず【確認事項】に載せること。
- この表に無い日本語の項目名は、推測でキーに読み替えず、その行を出力せず【確認事項】に載せること
  （`## 20.1` の「規約に無い書き方」）。表に無い設定は、`<設定のキー>：<値>` の形で書けばよい。
- **出力の順序はSPDの順とする。** `接続`・`JPA`・`H2コンソール` などの見出しが変わるところに空行を1行入れる。
- **`※` のコメントは、その直後の項目（行末の `※` はその行の項目）の前の行に、`# <コメント>` として出力する。**
- 値に `\`・`:`・`=` などの properties の特殊文字が含まれていても、エスケープせずに書かれたまま出力する（パスワードなど）。
  問題になりそうな場合は【確認事項】で知らせる。

### 未記入の判定

設定ファイルのSPDは、**ファイル全体を1つの単位**として判定する（`## 0.3`）。

- 条件A：タイトル行の下に枝が1つも無い、または `データベース設定` の下に枝が無い。
- 条件B：`★` を含む行などのマーカー（`## 0.3.4`）がある。**値が空の項目（`DB名：`・`パスワード：`）もマーカーと同じく未記入とする。**
  パスワードが空であることは `パスワード：なし` と書く。
- 未完成の場合は、SPDのコメントの下に `# application.properties：SPDが未記入のため生成していません` の1行だけを置く。
- `未記入判定:` の行には `application.properties=記入済み` のように書く。

### SPDの残し方

**与えられたSPD全体を、ファイルの先頭に、各行の頭に `# ` を付けたコメントとして原文のまま残す。**
SPDの下に空行を1行置き、続けて設定を書く。

### 依存関係

ドライバーの依存関係は `pom.xml` に必要だが、SPDからは生成しない。
データベースに対応する依存関係（H2：`com.h2database:h2`、PostgreSQL：`org.postgresql:postgresql`、
MySQL：`com.mysql:mysql-connector-j`）が、参照できる `pom.xml` に無い場合は、【確認事項】で知らせる。
`pom.xml` が参照できない場合は、必要な依存関係を【確認事項】に1行で書く。

spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
# トランザクションが終わると EntityManager が閉じる
spring.jpa.open-in-view=false

spring.h2.console.enabled=true
spring.h2.console.path=/h2-console
```

PostgreSQL・MySQL では、`接続URL` の下を `ホスト名`・`ポート番号`・`DB名` にし、`H2コンソール` を書かない。

```
      ├─接続
      │    ├─接続URL
      │    │    ├─ホスト名：localhost
      │    │    ├─ポート番号：5432
      │    │    └─DB名：bookstore
```

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/bookstore
```
