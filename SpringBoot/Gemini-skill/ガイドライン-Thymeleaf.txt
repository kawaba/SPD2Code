## 30.1 適用範囲とファイル配置

- **タイトルが `テンプレート：…` のSPDだけ**がこのファイルの対象である。
- 生成先は `src/main/resources/templates/<テンプレート名>.html` とする。
  テンプレート名はSPDのタイトルに書かれた文字列をそのまま使い、`.html` は付けない（`## 11.1`）。

```

→ src/main/resources/templates/member/list.html
```

- Web層のJavaコードの規約は `ガイドライン-SpringBoot.txt` にある。
  **コントローラーとテンプレートを同時に生成する場合は、両方の規約を適用すること。**

### 未記入判定の適用

### 構成の行の書き方

**`構成` の中の行は、次の形で書き分ける。** 混同してはならない。

| 書き方 | 意味 | 例 |
|---|---|---|
| `［種類］…` | **ノード**：見出し・リンク・表などの要素。`［…］` の中が要素の種類である | `［見出し］会員一覧`・`［表（行）］` |
| `ラベル：値` | **表示**：`：` の左がラベル、右が表示する値。値の中の `{…}` が変数である | `名前：{m.name}` |
| `ラベル＜種類＞：名前` | **入力**：ラベルの項目に入力した値を、`：` の右の名前で送る | `名前＜text＞：name` |
| `キャプション＜種類＞` | **ボタン** | `登録する＜submit＞` |
| `→ パス` | **移動**：リンクの行き先・フォームの送信先 | `［リンク］新規登録 → /members/new` |
| `［空］：…` | **ラベルなし**：`：` の左を空にする。`：…` と同じ | `［空］：［リンク］戻る → /end` |
| `┬─…` | **まとめ**：表（行）の1マスの中に、複数の要素を並べる | `┬─登録する＜submit＞` |
| `(条件)…` | **条件表示**：条件が成り立つときだけ、その後に書いたものを表示する。行の先頭か値の先頭に書く | `({message}は空ではない) ［通知］{message}` |

- **`(条件)` は、上の形の行や値の先頭に付ける印であり、新しい行の形を作らない**（`## 30.4` の「条件表示」）。
  `(条件)` を取り除いた行は、この規約で正しい行でなければならない。例外は、`(条件)` だけの行に子を置く書き方である。
- **`［…］` で始まる行だけがノードである。** `：` は常にラベルと値の区切りであり、ノードの種類の区切りには使わない。
  例外は `［空］` で、ノードではなく、**ラベルが空であることを表す印**として `：` の左にだけ書ける（`## 30.4`・`## 30.5`）。
  `：` の左以外（値の位置・`：` の無い行）に書かれた `［空］` は、生成せず【確認事項】に載せること。
- `┬` は `［表（行）］` の子にだけ書ける（`## 30.5` の「表（行）」）。それ以外の場所に書かれていた場合は生成せず、【確認事項】に載せること。
- `［…］` の中は `## 30.3` の対応表にある種類だけである。表に無い種類は、生成せず【確認事項】に載せること。
- **`ラベル：値` を書けるのは、`［表（列）］`・`［表（行）］` の子と、`［フォーム］` の直下だけ**である（`## 30.4`・`## 30.5`）。
  それ以外の場所（`構成` の直下など）に書かれていた場合は生成せず、【確認事項】に載せること。
  `(条件)` だけの行の子は、その行を置いた場所に書いたものとして扱う（表（行）の中なら書ける、`構成` の直下なら書けない）。
  画面に値を1つ出すときは `［文字］…`・`［段落］…` を使う。
- **`＜種類＞` の付いた項目だけが入力項目である**（`## 30.5`）。`＜種類＞` は省略できない（`text` も `＜text＞` と書く）。
- 表示の値で、**`{…}` で囲んだ部分だけが変数**であり、それ以外は書かれたとおりの文字である（`## 30.3` の「値の書き方」）。
- 入力項目とボタン（`＜submit＞`・`＜reset＞`）は、フォームの中にだけ書ける。フォームの外に書かれていた場合は生成せず、
  【確認事項】に載せること。
- **`［…］` も `：` も `＜…＞` も無い文字だけの行は、生成せず【確認事項】に載せること。**
  例外は、入力項目の子の「`<リスト>の各要素を<変数>とする`」と、子を置いた `(条件)` だけの行である
  （`## 30.5` の「リストから作る選択肢」、`## 30.4` の「条件表示」）。
  `(条件)` の後が文字だけの行（`({flag}) 在庫あり`）も、条件を除くと文字だけの行なので報告する。`(条件) ［文字］在庫あり` と書く。

### 記号の表記

| 記号 | 使う場所 | 全角・半角 |
|---|---|---|
| `［…］` | ノードの種類（`［見出し］`） | どちらでもよい（`[…]`） |
| `＜…＞` | 入力項目とボタンの種類（`＜date＞`・`＜submit＞`） | どちらでもよい（`<…>`） |
| `<<…>>` | 書式・画像のサイズ・クラス名（`<<"yyyy年MM月dd日">>`・`<<120px .写真枠>>`） | 半角を基本とする。全角の `＜＜…＞＞` も受け付ける |
| `"…"` | 書式の日付・時刻のパターンと連結の区切り（`<<"yyyy年MM月dd日">>`・`<<"、"で連結>>`） | どちらでもよい（`＂…＂`・`“…”`）。生成する式では `'…'` にする |
| `(…)` | 条件（`({stock}は10未満)`）と表の種類（`［表（列）］`・`［表（行）］`） | どちらでもよい（`（…）`）。開き括弧と閉じ括弧で違ってもよい |
| `{…}` | 変数 | **半角だけ** |
| `@` | マーカー | どちらでもよい（`＠`）（`springboot-java` の `## 20.1` と同じ） |
| `：` | ラベルと値の区切り | どちらでもよい（`:`） |

- `<` と `>` が2つ続いたもの（`<<`・`>>`）が書式などの印であり、1つだけのもの（`<date>`）が入力項目の種類である。
- 山括弧の前後と内側の空白は無視する（`種別 ＜radio ＞` と `種別＜radio＞` は同じ）。
- **`：` と `→` の前後の空白は、あってもなくてもよい**（`css ：css/style.css` と `css：css/style.css` は同じ）。
  値の前後の空白は取り除き、値の途中の空白はそのまま残す。
- 無視する空白は、半角・全角のどちらでもよい。
- **変数を囲む中括弧 `{…}` は半角だけ**である。全角の `｛…｝` は変数の印にならない。値の中に全角の `｛…｝` があれば、
  書き間違いとして【確認事項】に載せること。

### 表記の揺れ

次のノード名は、送り仮名などの違いがあっても同じものとして扱う。「規約に無い書き方」には当たらない。

| ノード名 | 同じに扱う書き方 |
|---|---|
| `受け取り` | `受取り`・`受取` |
| `見出し` | `見出` |
| `小見出し` | `小見出` |

- この表に無い書き方は、似ていても読み替えない（下記「規約に無い書き方」）。
- 条件の言い方の揺れは、`## 30.4` の「条件表示」の「表記の揺れ」に従う。

### 規約に無い書き方

**この規約に無い書き方で書かれたノードは、推測で読み替えず、生成せずに【確認事項】に載せること。**
以前の版の記法も、これに当たる。たとえば次のものである。

- v7 までの箇条書き（`［一覧］memberListの各要素をmとする`）。報告では、`［箇条書き］` で書いた形を示す
- v6 までの条件表示（`［条件表示］messageがある`・`［そうでなければ］`）。報告では、`(条件)` で書いた形
  （`({message}は空ではない) ［通知］{message}`。`［そうでなければ］` は否定の条件を書いた行）を示す

- v5 までの表の種類（`表＜列定義＞：…`・`表＜行定義＞`）、`［…］` で書いた書式（`{m.joinedOn}［"yyyy年MM月dd日"］`）、
  `：` の無い行・列（`操作` の下に子を置く形）
- それより前の記法（`名前 ← m.name`・`名前 ⇒ name`・`ボタン：登録する`・`選択欄：…`・`入力欄：…`・`列：…` など）

報告では、該当するノードと、この規約での書き方を示す。

## 30.2 テンプレートSPDの記法

```
テンプレート：member/list
│
├─目的：会員の一覧を表示する
├─レイアウト：なし
├─タイトル：会員一覧
├─css：css/style.css
│
├─受け取り
│  ├─会員リスト：List<Member> memberList
│  └─メッセージ：String message　※任意
│
└─構成
     ├─［見出し］会員一覧
     ├─({message}は空ではない) ［通知］{message}
     ├─［表（列）］memberListの各要素をmとする
     │  ├─番号：{m.id}
     │  ├─名前：{m.name}
     │  └─操作：［リンク］編集 → /members/{m.id}/edit
     └─［リンク］新規登録 → /members/new
```

| ノード | 意味 |
|---|---|
| タイトル `テンプレート：…` | テンプレートのパス（`templates/` 配下・拡張子なし） |
| `目的：…` | ファイル冒頭のコメントに記載 |
| `レイアウト：…` | 使用する共通レイアウト。`なし` なら単独のHTMLとして生成（`## 30.6`） |
| `タイトル：…` | `<title>` の内容 |
| `css：…` | 読み込むスタイルシート（下記） |
| `受け取り` | コントローラーから渡される Model 属性 |
| `構成` | 画面の中身（`## 30.3`〜`## 30.5`） |

- `構成` の外のノード（上の表）は、設定の項目なので `［…］` で囲まず、`名前：内容` の形で書く。
- **`レイアウト` の行が無い場合は、`レイアウト：なし` として扱う。**
  ワークスペースにレイアウトファイルがあっても、推測で適用してはならない。

### `受け取り`

`<説明>：<型> <名前>` の形で書く（`spd-core` の引数・フィールドと同じ形）。

- ノード名は `受取り`・`受取` と書いてもよい（`## 30.1` の「表記の揺れ」）。
- **型はテンプレートの宣言には使わない**（テンプレートは型を宣言しないため）。値の書式が型に合うかを確かめるときと、
  条件の式を決めるとき（「空」の式・`true`／`false` の条件）にだけ使う（`## 30.4` の「値の書式」「条件表示」）。
- **`<名前>` は、対応するコントローラーの `処理` で「〜をテンプレートに渡す」とした名前と一致していなければならない**（`## 11.2`）。
  フォームオブジェクトは、型名の先頭を小文字にした名前（`bookForm`）になる（`## 11.3`）。
  一致しない名前をテンプレートで参照しようとした場合は、推測で補わず
  `## 0.8` の報告の【見つからない名前】に載せること。
- `※任意` と書かれた受け取りは、SPD で条件を付けて（`({message}は空ではない) ［通知］{message}`）、存在を確かめてから使う
  （`## 30.4` の「条件表示」）。条件を付けずに使っている場合は、生成したうえで【確認事項】に載せること。
  フラッシュメッセージ（`message`）は、リダイレクトの直後にしか存在しないので `※任意` にする。

### `css`

| SPDの記述 | 生成 |
|---|---|
| `css：css/style.css` | `<link rel="stylesheet" th:href="@{/css/style.css}">` |

- パスは `src/main/resources/static/` からの相対である。先頭の `/` はあっても無くてもよい。
- `<head>` の中、`<meta name="viewport" …>` の後・`<title>` の前に置く。
- 複数のファイルを読み込む場合は、`css` の子に1行ずつ並べる。書かれた順に `<link>` を置く。
- ノード名は `CSS` と書いてもよい。
- `レイアウト` が `なし` 以外の場合は、画面側の `<head>` がレイアウトに置き換えられて失われるため、
  `<link>` を生成せず、`## 0.8` の報告の【確認事項】に載せること（CSS はレイアウト側に書く）。

## 30.3 構成ノードの対応表

### 基本の原則

- **`{…}` を含まない値（静的な文字列）は、HTMLの本文にそのまま書く。** `th:text` を付けない。
- **`{…}`（変数）を含む値と、`＜種類＞`（入力）が書かれた項目だけが動的**である（`## 30.1` の「構成の行の書き方」）。
  `{…}` を含む値は `th:text` で出力する（下記「値の書き方」）。`＜種類＞` の付いた項目は入力項目になる（`## 30.5`）。
- `th:text` を使うときは、**プレビュー用のダミー文字列を本文にも残す**
  （`<td th:text="${m.name}">名前</td>`）。ブラウザで直接開いたときに崩れないためである。
  ダミーの文字列は、下記「プレビュー用のダミー」の規則で決める。

### 対応表

| SPDの記述 | 生成されるHTML |
|---|---|
| `［見出し］会員一覧` | `<h1>会員一覧</h1>` |
| `［見出し］{title}` | `<h1 th:text="${title}">表題</h1>` |
| `［小見出し］基本情報` | `<h2>基本情報</h2>` |
| `［段落］…` | `<p>…</p>` |
| `［段落］` ＋ 子 | `<p>子を書かれた順に</p>`（下記「段落に複数の要素を並べる」） |
| `［改行］` | `<br>`（下記「改行」） |
| `［文字］{m.name}` | `<span th:text="${m.name}">name</span>` |
| `［文字］\|`（`{…}` なし） | `\|`（本文にそのまま書く。タグで囲まない） |
| `［通知］{message}` | `<div class="message" th:text="${message}">メッセージ</div>` |
| `［リンク］新規登録 → /members/new` | `<a th:href="@{/members/new}">新規登録</a>` |
| `［リンク］{m.name}を編集 → /members/{m.id}/edit` | `<a th:href="@{/members/{id}/edit(id=${m.id})}" th:text="\|${m.name}を編集\|">nameを編集</a>` |
| `［リンク］新規登録 → /members/new <<.ボタン風>>` | `<a th:href="@{/members/new}" class="ボタン風">新規登録</a>`（下記「リンクのクラス名」） |
| `［画像］/images/logo.png "会社のロゴ"` | `<img th:src="@{/images/logo.png}" alt="会社のロゴ">`（下記「画像」） |
| `［区切り］` | `<hr>` |
| `［表（列）］…`・`［表（行）］` | `<table>`（`## 30.4`・`## 30.5`） |
| `［箇条書き］…`・`［項目］…` | `<ul>`・`<li>`（`## 30.4`） |
| `(条件)…`（行・値の先頭） | `th:if`（`## 30.4` の「条件表示」） |
| `［フォーム］…` | `<form>`（`## 30.5`） |

- `［…］` の後ろに書いたもの（`［見出し］会員一覧` の `会員一覧`）が、そのノードの値である。
  値の書き方は下記「値の書き方」と同じである。
- **`［見出し］` の階層**は、`構成` 直下を `<h1>`、その1段下を `<h2>` とする。
- ボタン（`登録する＜submit＞`）はフォームの中にだけ書ける（`## 30.5` の「ボタン」）。
  ボタンの形で別の画面へ移るには、`GET` のフォーム（`## 30.5` の「フォームの形」）を使う。

**リンクのクラス名**

- `［リンク］` の行の末尾（`→ パス` の後ろ）に `<<.クラス名>>` を書くと、`<a>` に `class` を付ける。
  キャプションに `{…}` があるかどうかにかかわらず付ける。`<<` の前の空白は、あってもなくてもよい。
- **書けるのはクラス名だけ**である。書式・サイズが書かれていた場合は生成せず、【確認事項】に載せること。
- 値の位置（`戻り先：［リンク］一覧へ → /members <<.控えめ>>`）や表（列）の列（`：［リンク］編集 → … <<.小ボタン>>`）でも、
  マスの `<td>` ではなく `<a>` に付ける。`┬` の行の末尾の `<<…>>` は `<td colspan="2">` に付く（`## 30.5` の「表（行）」）。
- `<<…>>` を `→` の前（`新規登録 <<.x>> → /path`）に書いた場合は生成せず、【確認事項】に載せること。
- クラス名の書き方（`.` の全角・半角、複数のクラス）は `## 30.4` の「CSSクラスの指定」と同じである。

### 値の書き方

表示の値（`ラベル：値` の `：` の右と、`［見出し］`・`［段落］`・`［文字］`・`［通知］`・`［項目］` などの後ろ）では、
**半角の `{…}` で囲んだ部分が変数**であり、それ以外は書かれたとおりの文字である。
**文字と変数を混ぜて書いてよい。**

| 値 | 生成する `th:text` |
|---|---|
| `会員一覧`（`{…}` なし） | 付けない（本文にそのまま書く） |
| `{m.name}`（`{…}` が1つだけで、前後に文字が無い） | `th:text="${m.name}"` |
| `{m.name}さんの情報`（文字と変数が混ざっている） | `th:text="\|${m.name}さんの情報\|"` |
| `{m.lastName} {m.firstName}`（変数が2つ以上） | `th:text="\|${m.lastName} ${m.firstName}\|"` |

- 文字と変数が混ざっている場合は、Thymeleaf のリテラル置換（`|…|`）で生成する。文字の部分に `|` を含む場合は、
  リテラル置換を使わず `'文字' + ${式}` の連結で生成する。
- `th:object` のフォームの中で、**フォームのオブジェクト名で始まる式**（`{memberForm.id}`）は、オブジェクト名を除いて
  `*{…}` で生成する（`*{id}`）。それ以外の式（`{message}`）は `${…}` で生成する（`## 30.5` の「フォームの中の表示だけの項目」）。
- **`{…}` を書けるのは値と条件の中だけ**である（条件は `## 30.4` の「条件表示」）。ラベル（表の列見出し・行の見出し・入力項目のラベル・ボタンのキャプション）に
  書かれていた場合は生成せず、【確認事項】に載せること。表の列見出しの `<th>` は繰り返し（`th:each`）の外にあり、
  要素の変数が使えないためである。例外は、リストから作る選択肢の表示名である（`## 30.5`）。
- `{…}` の中は、`受け取り` の名前か「〜の各要素を〜とする」の変数から始まる式である（`m.name`・`message`）。
- `{` と `}` は常に変数の印である。文字としての中括弧は表示できない。
- 値の後には、書式とクラス名を `<<…>>` で付けられる（`## 30.4` の「値の書式」「CSSクラスの指定」）。
- パス（`→ /members/{m.id}/edit`）の `{…}` も変数である（下記「パスの書き方」）。

### プレビュー用のダミー

`th:text` を付けた要素の本文に残すダミーの文字列（上記「基本の原則」）は、**`{…}` ごとに次の順で決める。**
生成するたびに同じ文字列になるようにするためである。

| 順 | `{…}` の式 | ダミー | 例 |
|---|---|---|---|
| 1 | `受け取り` の名前そのもの | その受け取りのラベル（`：` の左。`※任意` は除く） | `入力した値：String title` の `{title}` → `入力した値` |
| 2 | 1に当たらず、`ラベル：値` の値が `{…}` 1つだけ | そのラベル（表（列）では列見出し） | `名前：{m.name}` → `名前` |
| 3 | 1・2のどちらにも当たらない | 式の最後の名前 | `［文字］{member.name}` → `name` |

- **1は2より優先する。** 受け取りが `生年月日：LocalDate birthday` のとき、`日付：{birthday}` のダミーは `生年月日` である。
  同じ変数は、どこに書いてもダミーが同じになる。
- 2に当たるのは、表（列）の列・表（行）の行・フォームの直下の表示だけの項目で、値が `{…}` 1つだけ（前後に文字が無い）のときである。
  値の先頭の `(条件)` と末尾の `<<…>>` は値に含めない。ラベルが無い行（`：{x}`・`［空］：{x}`）、値の位置のノード（`警告：［通知］{message}`）、
  `ラベル：` の子に並べた要素は、2に当たらない（1か3で決める）。
- **文字と変数が混ざった値**は、`{…}` の部分だけを1か3のダミーに置き換え、文字はそのまま残す
  （`{title}さんの情報` → `入力した値さんの情報`、`{m.lastName} {m.firstName}` → `lastName firstName`）。
- **書式を付けた値も、同じ規則で決める。** 書式に合わせた見本の値（`2026年01月01日`・`1,000`）は作らない
  （`入会日：{m.joinedOn} <<"yyyy年MM月dd日">>` → `入会日`）。
- フォームの中で `*{…}` で生成する値も、SPD の式（`{memberForm.id}`）で決める。`memberForm.id` は受け取りの名前そのものではないので、
  2か3になる（`会員番号：{memberForm.id}` → `会員番号`）。
- `［リンク］` のキャプション（`［リンク］{m.name}を編集 → …` → `nameを編集`）と、リストから作る選択肢の表示名
  （`{d.name}：{d.id}` → `name`。`## 30.5`）にも適用する。`th:alt` の代わりに残す `alt=""` は変えない（下記「画像」）。

この規約の例で `受け取り` を示していない名前は、次のラベルで受け取っているものとする。

| 名前 | ラベル |
|---|---|
| `title` | `表題` |
| `message` | `メッセージ` |
| `price` | `価格` |
| `point` | `ポイント` |
| `birthday` | `生年月日` |

### 値の位置に書くノード

`ラベル：値` の値の位置には、**`［画像］`・`［リンク］`・`［文字］`・`［通知］` の4つのノード**を書ける。
値の位置に書いたノードは、表のマス（`<td>`）やフォームの直下の項目の中に、そのノードの要素として生成する。

| SPDの記述（`［表（行）］` の子） | 生成 |
|---|---|
| `写真：［画像］/images/{m.photo} <<120px>>` | `<tr><td>写真</td><td><img th:src="@{/images/{photo}(photo=${m.photo})}" alt="" width="120"></td></tr>` |
| `戻り先：［リンク］一覧へ → /members` | `<tr><td>戻り先</td><td><a th:href="@{/members}">一覧へ</a></td></tr>` |
| `警告：［通知］{message} <<.赤字>>` | `<tr><td>警告</td><td><div class="message 赤字" th:text="${message}">メッセージ</div></td></tr>` |

- **`［…］` は値の先頭に1つだけ書ける。** `詳しくは［リンク］こちら → /about` のように文字と混ぜた値や、
  `［…］` を2つ以上並べた値は、生成せず【確認事項】に載せること。文字とリンクのように複数の要素を並べるときは、
  子に並べる（`## 30.5` の「表（行）」）。
- 上の4つ以外のノード（`［段落］`・`［見出し］`・`［フォーム］` など）を値の位置に書いた場合は、生成せず【確認事項】に載せること。
- `<<…>>` は、値の位置のノードの要素（`<img>`・`<div class="message">` など）に付く。マスの `<td>` には付けない。
- 要素が1つだけのときは、子に置かず値の位置に書く（`写真：［画像］…`）。

### 段落に複数の要素を並べる

値を書かず、**`［段落］` の子に並べる**と、子の要素を書かれた順に1つの `<p>` の中に置く。
文字と変数・リンク・画像を混ぜた文や、途中で改行する文を書くときに使う。

```
└─構成
      └─［段落］
              ├─［文字］表題＝
              ├─［文字］{title}
              ├─［改行］
              ├─［画像］/images/logo.png
              ├─［文字］詳しくは
              └─［リンク］こちら → /about
```
```html
<p>表題＝<span th:text="${title}">表題</span><br>
<img th:src="@{/images/logo.png}" alt="">詳しくは<a th:href="@{/about}">こちら</a></p>
```

- **子に書けるのは、`［文字］`・`［リンク］`・`［画像］`・`［改行］` の4つだけ**である。
  `<p>` の中にはブロック要素を置けない（置くと、ブラウザがその手前で `<p>` を閉じてしまう）ためである。
  それ以外のノード（`［通知］`（`<div>` を作る）・`［フォーム］`・`［段落］`・`［見出し］`・`［箇条書き］`・`［表（…）］` など）、
  `ラベル：値`・入力項目・ボタンが書かれていた場合は生成せず、【確認事項】に載せること。
- **子の要素は、間に空白も改行も入れずに続けて生成する。** HTML の改行は空白1つとして表示され、
  `表題＝ タイトル` のように日本語の文の途中に空白が入るためである。
  例外として、`［改行］` の `<br>` の後では改行してよい（改行した行の先頭の空白は表示されない）。
- 子の書き方と生成は、`構成` の直下に書いたときと同じである（`{…}` の無い `［文字］` は本文にそのまま書き、
  `{…}` のある `［文字］` は `<span th:text="…">` にする。書式・クラス名の `<<…>>` もそのノードの要素に付く）。
- 子には1つずつ条件を付けられる（`(条件) ［文字］…`。その要素だけに `th:if` を付ける）。
  複数の子をまとめて消すときは、`(条件)` だけの行の子に並べる（`<th:block th:if="…">`。`## 30.4` の「条件表示」）。
- **値と子の両方を書いた `［段落］`、値も子も無い `［段落］` は、生成せず【確認事項】に載せること。**
  子が `［文字］` だけのときは、子に並べず値に書ける（`［段落］表題＝{title}`）。
- 子に並べた `［段落］` の行に書いた `<<…>>` は、生成せず【確認事項】に載せること（`## 30.4` の「CSSクラスの指定」）。
- 子に並べた `［段落］` も、`［表（行）］` の1マスの行に書ける（`<td colspan="2"><p>…</p></td>`。`## 30.5`）。

### 改行

**`［改行］`** は、要素を並べる途中で改行する（`<br>`）。値を書かない。

- **書けるのは、複数の要素を並べる場所だけ**である。`［段落］` の子（上記）、表のマスの子（`［表（列）］` の `見出し：` の子、
  `［表（行）］` の `ラベル：`・`［空］：` の子）、`┬` でまとめた要素（`## 30.4`・`## 30.5`）に書ける。
- それ以外の場所（`構成` の直下、`［フォーム］` の直下、表（行）の1マスの行、値の位置、`［箇条書き］` の中など）に書かれていた場合は
  生成せず、【確認事項】に載せること。段落や見出しの間を空けるのは `<br>` ではなく CSS の役割であるため、ブロック要素の間には書けないことにしている。
- 値を書いた `［改行］`（`［改行］あいう`）、`<<…>>` を書いた `［改行］` は、生成せず【確認事項】に載せること。
- 条件を付けられる（`({flag}) ［改行］` → `<br th:if="${flag}">`）。

### パスの書き方

**パスは必ず `@{…}` で囲む**（`## 11.4`）。素の `href="/members"` を生成してはならない。

| SPDの記述 | 生成 |
|---|---|
| `→ /members/new` | `th:href="@{/members/new}"` |
| `→ /members/{m.id}/edit` | `th:href="@{/members/{id}/edit(id=${m.id})}"` |
| `→ /members?keyword={keyword}` | `th:href="@{/members(keyword=${keyword})}"` |

- **パス変数は `{名前}` のプレースホルダと `(名前=${式})` の組で書く。**
  プレースホルダの名前は、式の最後の名前（`m.id` → `id`）とする。
  文字列連結（`@{'/members/' + ${m.id}}`）は生成しない。
- フォームの送信先（`th:action`）も同じ書き方にする。
- パスは、コントローラーの `ベースパス` を含めた絶対パスで書く。コントローラーの `ベースパス` ＋ `マッピング` と
  一致しない場合は、【確認事項】に載せること（`## 11.4`）。

### 画像

**`［画像］<パス> ["<代替文字列>"] [<<サイズ クラス名>>]`** と書く。パスは必須、代替文字列と `<<…>>` は省略できる。

| SPDの記述 | 生成 |
|---|---|
| `［画像］/images/logo.png` | `<img th:src="@{/images/logo.png}" alt="">` |
| `［画像］/images/logo.png "会社のロゴ"` | `<img th:src="@{/images/logo.png}" alt="会社のロゴ">` |
| `［画像］/images/logo.png "会社のロゴ" <<120px>>` | `<img th:src="@{/images/logo.png}" alt="会社のロゴ" width="120">` |
| `［画像］/images/logo.png "会社のロゴ" <<120px .ロゴ>>` | `<img th:src="@{/images/logo.png}" alt="会社のロゴ" width="120" class="ロゴ">` |
| `［画像］/images/{member.photo} "{member.name}の写真"` | `<img th:src="@{/images/{photo}(photo=${member.photo})}" th:alt="\|${member.name}の写真\|" alt="">` |

**書き方**

- パス・代替文字列・`<<…>>` は空白（全角・半角）で区切り、**この順に書く。** 順序が違う場合は生成せず、【確認事項】に載せること。
- **パスは `/` から書く。** `src/main/resources/static/` に置いたファイルを、そこからの位置で指す
  （`static/images/logo.png` → `/images/logo.png`）。先頭の `/` が無いパスは、生成せず【確認事項】に載せること。
- **外部のURL（`http://`・`https://`・`//` で始まるもの）は書けない。** 書かれていた場合は生成せず、【確認事項】に載せること。
- 区切りが空白なので、**パスに空白は書けない。**
- **代替文字列は半角の `"` で囲む。** 代替文字列の中に `"` は書けない。

**生成**

- パスは `th:src="@{…}"` で生成する。素の `src` を生成してはならない（上記「パスの書き方」）。
- パスの `{…}` は、上記「パスの書き方」と同じく `{名前}` のプレースホルダと `(名前=${式})` の組で生成する
  （`/images/{city}.png` → `@{/images/{city}.png(city=${city})}`）。
  **`{…}` に入れる値は、ファイル名など、パスの1区切り分だけ**である。値が `/` を含む（`members/1.png`）と、
  `%2F` に変換されて画像が表示されない。
- 代替文字列は `alt` で生成する。**代替文字列を省略した場合は `alt=""` を生成する**（装飾の画像として扱う）。
  `alt` 属性そのものを省いてはならない。
- 代替文字列には `{…}` を書ける（`## 30.3` の「値の書き方」）。`{…}` を含む場合は `th:alt` で生成し、
  プレビュー用に `alt=""` も残す。`th:object` のフォームの中では、フォームのオブジェクト名で始まる式を `*{…}` で生成する。
- パスの `{…}` の値が `null` の場合は、画像が表示されない。必要なら SPD で条件を付ける
  （`({member.photo}は空ではない) ［画像］/images/{member.photo}`。`## 30.4` の「条件表示」）。

**サイズとクラス名（`<<…>>`）**

- `<<…>>` の中は空白（全角・半角）で区切る。**`.` で始まるものがクラス名、それ以外がサイズ**である。
  サイズとクラス名の両方を書く場合は、**サイズを先に書く。**
- **サイズは画像の幅であり、`<整数>px` と書く（`px` は必須）。** `width="<整数>"` で生成する。高さは指定できない
  （縦横の比は保たれる）。
- `%` のサイズ・単位の無いサイズ・値の書式（`"yyyy年MM月dd日"`・`3桁区切り` など）は、生成せず【確認事項】に載せること。
  `%` で指定したい場合は、クラス名を付けて CSS で定める。
- クラス名は `## 30.4` の「CSSクラスの指定」と同じく、`<img>` に `class` として付ける。
- **`style` 属性を生成してはならない**（`## 30.4` の「CSSクラスの指定」）。

**書ける場所**

- `構成` の中、`(条件)` だけの行の子、フォームの中、表のマスの中（値の位置・子）、表（行）の1マスの行（`┬` でまとめた行を含む）に書ける
  （上記「値の位置に書くノード」、`## 30.4`・`## 30.5`）。
- `［箇条書き］` の子は `［項目］…` の1行だけなので、`［箇条書き］` の中には書けない。

## 30.4 繰り返しと条件表示

### 表（列）

**`［表（列）］<リスト>の各要素を<変数>とする`** は、リストの要素ごとに1行を作る表である。
**子の各枝が1つの列**を表す。

```
├─［表（列）］memberListの各要素をmとする
│  ├─番号：{m.id}
│  ├─名前：{m.name}
│  ├─入会日：{m.joinedOn} <<"yyyy年MM月dd日">>
│  ├─写真：［画像］/images/{m.photo} <<60px>>
│  └─操作：
│        ├─［リンク］編集 → /members/{m.id}/edit
│        ├─［文字］|
│        └─［フォーム］→ POST /members/{m.id}/delete
│              └─削除＜submit＞
```

```html
<table>
  <thead>
    <tr>
      <th>番号</th>
      <th>名前</th>
      <th>入会日</th>
      <th>写真</th>
      <th>操作</th>
    </tr>
  </thead>
  <tbody>
    <tr th:each="m : ${memberList}">
      <td th:text="${m.id}">番号</td>
      <td th:text="${m.name}">名前</td>
      <td th:text="${m.joinedOn == null ? '' : #temporals.format(m.joinedOn, 'yyyy年MM月dd日')}">入会日</td>
      <td><img th:src="@{/images/{photo}(photo=${m.photo})}" alt="" width="60"></td>
      <td>
        <a th:href="@{/members/{id}/edit(id=${m.id})}">編集</a>
        |
        <form th:action="@{/members/{id}/delete(id=${m.id})}" method="post">
          <button type="submit">削除</button>
        </form>
      </td>
    </tr>
  </tbody>
</table>
```

- 列は `<見出し>：<値>` の形である。見出しは `<thead>` の `<th>` へ、値は `<tbody>` の `<td>` へ振り分ける。
  - 値は `## 30.3` の「値の書き方」のとおりに書く。値の後に書式とクラス名（`<<…>>`）を付けられる（下記「値の書式」「CSSクラスの指定」）。
  - 値の位置には `［画像］`・`［リンク］`・`［文字］`・`［通知］` を書ける（`## 30.3` の「値の位置に書くノード」）。
  - **値を書かず `<見出し>：` の子に並べた列**（上の例の `操作：`）は、子ノードの内容を、書かれた順に `<td>` の中に置く。
    子に書けるのは、`［画像］`・`［リンク］`・`［文字］`・`［通知］`・`［フォーム］`（ボタンだけのフォーム）・`［改行］` である。
    それ以外のノード（入力項目・`［段落］` など）が書かれていた場合は生成せず、【確認事項】に載せること。
  - 値も子も無い列（`備考：`）は、空の `<td></td>` にする。
  - 見出しの無い列（`：［リンク］詳細 → /members/{m.id}`）は、空の `<th></th>` にする。
    `［空］：［リンク］詳細 → /members/{m.id}` と書いてもよい（`## 30.1`）。同じ HTML を生成する。
- **値と子の両方を書いた列は、生成せず【確認事項】に載せること。**
- **`：` の無い列（`［リンク］…` を直接書いた列や、文字だけの `操作`）は、生成せず【確認事項】に載せること。**
  見出しの無い列にしたい場合は、`：［リンク］…`（または `［空］：［リンク］…`）と書く。
- 列の子にボタン（`＜submit＞`・`＜reset＞`）は書けない。行ごとのボタンは、子に `［フォーム］`（ボタンだけのフォーム）を置いて書く。
  `┬` も書けない（`## 30.5` の「表（行）」）。
- **`th:each` は `<tr>` に付ける。** `<tbody>` や `<table>` に付けてはならない。
- **`［表（列）］` には「〜の各要素を〜とする」が必須である。** 無い場合は生成せず、【確認事項】に載せること。
- 列の中のフォーム（削除ボタンなど）は、`<td>` の中に置く。`<form>` はブロック要素なので、リンクと横に並べる場合は
  CSS（`form { display: inline; }` など）で調整する。テンプレートに `style` 属性を書いてはならない。

### 値の書式

値の後に `<<書式>>` を付けると、書式を指定して表示する（`入会日：{m.joinedOn} <<"yyyy年MM月dd日">>`）。
**書式は次の表にあるものだけ**である。

| SPDの書式 | 生成される式（`x` は値） |
|---|---|
| `"yyyy年MM月dd日"`（引用符で囲んだ日付・時刻のパターン） | `${x == null ? '' : #temporals.format(x, 'yyyy年MM月dd日')}` |
| `3桁区切り` | `${x == null ? '' : #numbers.formatInteger(x, 1, 'COMMA')}` |
| `円表示` | `${x == null ? '' : #numbers.formatInteger(x, 1, 'COMMA') + '円'}` |
| `"<区切り>"で連結`（コレクション） | `${x == null ? '' : #strings.listJoin(x, '<区切り>')}` |

- 書式を付けた値は、**必ず上の表のとおり `null` のとき空欄にする。** 必須でないフィールドは `null` になり得るためである。
- 表に無い書式は、推測で式を作らず【確認事項】に載せること。
  特に `通貨表示`（`#numbers.formatCurrency`）は、閲覧者のブラウザのロケールで記号や桁が変わるため使わない。

**書ける場所**

- **書式を付けられるのは、`{…}` を1つだけ含み、前後に文字が無い表示の値だけ**である。すなわち、表（列）・表（行）のマスの値、
  `［文字］`・`［見出し］`・`［項目］`・`［通知］` の値、フォームの中の表示だけの項目（`## 30.5`）である。
- 文字と変数が混ざった値や、変数が2つ以上ある値に書式が付いていた場合は、どの変数に付くのか決められないため生成せず、
  【確認事項】に載せること。
- 入力項目（`入会日＜date＞：joinedOn <<"yyyy年MM月dd日">>`）・`［リンク］`・`［画像］`・`┬` の行・ボタンには書式を書けない。
  書かれていた場合は生成せず、【確認事項】に載せること（`［画像］` のサイズとクラス名、`［リンク］` と `┬` の行のクラス名は書ける。
  `## 30.3`・`## 30.5`・下記「CSSクラスの指定」）。
- `<<…>>` は値の末尾（最後の `}` の後）に書く。`<<` の前の空白は、あってもなくてもよい。
  値の途中に書かれていた場合は、生成せず【確認事項】に載せること。
- 値の先頭の `(条件)`（下記「条件表示」）は値に含めない。`価格：({flag}) {price} <<3桁区切り>>` は、`{…}` を1つだけ含み前後に文字が無い値である。

**フォームの中の書式**

上の表の `x` は値の式である。`th:object` のフォームの中で、フォームオブジェクトのフィールド（`{memberForm.joinedOn}`）に
書式を付けたときは、`${…}` ではなく **`*{…}` の中に式全体を書く**（`## 30.3` の「値の書き方」）。

```
├─［フォーム］memberForm → POST /members/update
│    └─［表（行）］
│         └─入会日：{memberForm.joinedOn} <<"yyyy年MM月dd日">>
```
```html
<td th:text="*{joinedOn == null ? '' : #temporals.format(joinedOn, 'yyyy年MM月dd日')}">入会日</td>
```

- `${memberForm.joinedOn == null ? …}` や、`*{…}` と `${…}` を混ぜた式にしない。

**書式と型**

| 書式 | 使える型 |
|---|---|
| 日付・時刻のパターン | `LocalDate`・`LocalDateTime`・`LocalTime`（`java.time`）。`LocalDate` には時刻の文字（`H`・`h`・`m`・`s`・`a`）、`LocalTime` には日付の文字（`y`・`M`・`d`・`E`）を使えない |
| `3桁区切り`・`円表示` | 整数（`int`・`long`・`Integer`・`Long`） |
| `"<区切り>"で連結` | `List`（`#strings.listJoin`）。`Set` は `#strings.setJoin`、配列は `#strings.arrayJoin` で生成する |

- 型は、`受け取り` の型か、同時に生成するクラス・レコードの SPD から分かる場合に確かめる。
  分からない場合（表（列）の要素のフィールドで、要素のクラスの SPD が無いときなど）は、上の表のとおりに生成する（連結は `listJoin`）。
- **型が合わない場合は生成せず、【確認事項】に載せること。** たとえば `java.util.Date` の日付（`#temporals` では書式にできない）、
  `BigDecimal`・`double` の `3桁区切り`・`円表示`（`formatInteger` は小数を黙って丸めて表示する）、`LocalDate` に `HH` を使ったパターン（実行時にエラーになる）である。

**日付・時刻のパターン**

パターンの英字は、次の意味を持つ（例は 2026年3月5日（木）9時7分3秒）。日本語の文字（`年`・`月`・`日` など）と記号（`/`・`-`・`:`・空白）は、そのまま表示される。

| 文字 | 意味 | 例 |
|---|---|---|
| `yyyy` | 年（4桁） | `2026` |
| `M`／`MM` | 月（`MM` は2桁にそろえる） | `3`／`03` |
| `d`／`dd` | 日 | `5`／`05` |
| `E` | 曜日 | `木`（閲覧者のブラウザの言語で変わる。英語なら `Thu`） |
| `H`／`HH` | 時（0〜23） | `9`／`09` |
| `m`／`mm` | 分 | `7`／`07` |
| `s`／`ss` | 秒 | `3`／`03` |

- **`MM` は月、`mm` は分**である。取り違えやすいので注意する。時の文字（`H`・`h`）が無いのに `mm` があるパターン（`"yyyy/mm/dd"`）は、
  ほとんどの場合 `MM` の書き間違いである。**生成したうえで【確認事項】に載せること。**
- `YYYY`（週を基準にした年。年末年始の数日だけ `yyyy` と1年ずれる）と `D`（1月1日からの通算日）は、ほとんどの場合
  `yyyy`・`d` の書き間違いである。**生成したうえで【確認事項】に載せること。**
- `h`（1〜12時）は午前・午後を表す `a` と組み合わせて使う。24時間制なら `H` を使う。
- パターンの中の英字は、すべてパターンの文字とみなされる。英字を文字として表示することはできない（`"yyyy年"` はよいが、`"yyyy year"` は書けない）。

**引用符**

- **日付・時刻のパターンと区切りの文字列は、`"` で囲む。** パターンの中の `.`（`"yyyy.MM.dd"`）や空白を、クラス名や区切りと誤らないためである。
- 引用符は全角（`＂…＂`・`“…”`）でもよい。生成する式では、どれも `'…'` にする（`## 30.1` の「記号の表記」）。
- パターンや区切りの中に `'` または `"` を書いた場合は、生成する式の文字列が壊れるため生成せず、【確認事項】に載せること。

### CSSクラスの指定

**`{…}`（変数）を含む表示の値**では、`<<…>>` の中に **`.<クラス名>`** を書くと、値を表示する要素に `class` を付ける。
テキストエリアで入力した改行をそのまま表示したい場合などに使う。

```
├─［表（行）］
│    ├─メッセージ：{message} <<.改行保持>>
│    └─価格：{price} <<3桁区切り .右寄せ>>
```
```html
<tr>
  <td>メッセージ</td>
  <td th:text="${message}" class="改行保持">メッセージ</td>
</tr>
<tr>
  <td>価格</td>
  <td th:text="${price == null ? '' : #numbers.formatInteger(price, 1, 'COMMA')}" class="右寄せ">価格</td>
</tr>
```
```css
/* css：に書いたファイル（例：css/style.css）に定義する */
.改行保持 {
  white-space: pre-wrap;
}
```

- `<<…>>` の中は空白（全角・半角）で区切る。**`.` で始まるものがクラス名、それ以外が書式**である。
  書式とクラス名の両方を書く場合は、**書式を先に書く。** 引用符で囲んだ書式（`"yyyy.MM.dd"`）の中の `.` はクラス名ではない。
- `.` は半角・全角（`．`）のどちらでもよい。生成する `class` には `.` を付けない。
- 複数のクラスは並べて書く（`<<.改行保持 .強調>>` → `class="改行保持 強調"`）。書かれた順に並べる。
- クラス名は、文字と変数が混ざった値にも付けてよい（要素全体に付くため）。
- `class` は **`th:text` を付ける要素**に付ける。`［表（列）］` では `<tbody>` の `<td>`、`［表（行）］` では値の `<td>`（2つ目の `<td>`）であり、
  列見出しの `<th>` やラベルの `<td>` には付けない。`［文字］{…}` では `<span>`、`［見出し］{…}` では `<h1>`／`<h2>`、
  `［項目］{…}` では `<li>` に付ける。`［リンク］` では `<a>` に付ける（`## 30.3` の「リンクのクラス名」）。
- `［通知］{…}` では `<div>` に付け、固定の `message` の後に並べる（`<<.赤字>>` → `class="message 赤字"`）。
- **クラス名を書けるのは、`{…}` を含む表示の値と `［画像］`・`［リンク］`、表（行）の `┬` の行だけ**である。`［画像］` と `［リンク］` では、
  `{…}` の有無にかかわらず `<img>`・`<a>` に付ける（`## 30.3` の「画像」「リンクのクラス名」）。`┬` の行では、1マスの `<td colspan="2">` に付ける
  （`## 30.5` の「表（行）」）。`{…}` を含まない値・入力項目（`＜種類＞`）・ボタン・`［フォーム］` などに
  書かれていた場合は `class` を生成せず、【確認事項】に載せること。
- 値の位置のノード（`警告：［通知］{message} <<.赤字>>`）では、そのノードの要素に付ける（`## 30.3` の「値の位置に書くノード」）。
- 値の先頭に条件を付けた値（`価格：({flag}) {price} <<.右寄せ>>`）では、`th:if` と `th:text` を付けるマスの中の `<span>` に付ける
  （下記「条件表示」）。
- **`style` 属性に置き換えてはならない。** CSSの中身はテンプレートに書かず、`css：` のファイルに定義する。
- CSSファイルは生成しない。ワークスペースに `css：` のファイルがあり、そのクラスが定義されていない場合は、
  【確認事項】に載せること。

### 箇条書き

```
├─［箇条書き］memberListの各要素をmとする
│  └─［項目］{m.name}
```
```html
<ul>
  <li th:each="m : ${memberList}" th:text="${m.name}">name</li>
</ul>
```

- 子は `［項目］<値>[<<書式・クラス名>>]` の1行とする（値は `## 30.3` の「値の書き方」、書式とクラス名は上の「値の書式」「CSSクラスの指定」と同じ）。

- `［項目］` にも条件を付けられる（`({m.active}) ［項目］{m.name}`）。`th:each` と同じ `<li>` に `th:if` を付ける
  （下記「条件表示」）。

### 条件表示

行の先頭か値の先頭に **`(<条件>)`** を書くと、条件が成り立つときだけ、その後に書いたものを表示する（`th:if`）。

```
└─［表（行）］
      ├─在庫：
      │    ├─({stock}は10未満) ［文字］在庫小
      │    └─({stock}は10以上) ［文字］在庫あり
      ├─備考：({flag}) 獲得ポイント {point}
      ├─({message}は空ではない) ［文字］{message}
      └─［リンク］戻る → /textbox
```
```html
<table>
  <tr>
    <td>在庫</td>
    <td>
      <span th:if="${stock lt 10}">在庫小</span>
      <span th:if="${stock ge 10}">在庫あり</span>
    </td>
  </tr>
  <tr>
    <td>備考</td>
    <td><span th:if="${flag}" th:text="|獲得ポイント ${point}|">獲得ポイント ポイント</span></td>
  </tr>
  <tr th:if="${not #strings.isEmpty(message)}">
    <td colspan="2"><span th:text="${message}">メッセージ</span></td>
  </tr>
  <tr>
    <td colspan="2"><a th:href="@{/textbox}">戻る</a></td>
  </tr>
</table>
```

**原則**

- **`(条件)` は、この規約で書ける行や値の先頭に付ける印であり、新しい行の形を作らない。** `(条件)` を取り除いた行は、
  そのまま正しい行でなければならない。正しくない行（`({flag}) 在庫あり` は、条件を除くと文字だけの行になる）は、
  生成せず【確認事項】に載せること（`## 30.1` の「構成の行の書き方」）。
- 例外は、`(条件)` だけの行に子を置く書き方（下記④）である。
- 条件が成り立たないときの表示は、**否定の条件を書いた行**で書く（上の例の `在庫あり`）。`th:unless` は生成しない。

**条件の見分け方**

- **行の先頭、または `：` の右の値の先頭にある `(…)` で、中に `{…}` を含むものが条件**である。括弧は全角・半角のどちらでもよく、
  開き括弧と閉じ括弧で違ってもよい（`（{message}は空ではない)`）。
- `{…}` を含まない括弧（`備考：(株)山田商店`・`（税込）`）は条件ではなく、書かれたとおりの文字である。
  値の途中にある括弧（`獲得({point}点)`）も、条件ではなく文字である。
- 閉じ括弧の後の空白は、あってもなくてもよい。引用符（`"…"`）の中の括弧は、条件の終わりとみなさない。

**付ける場所**

**`(条件)` は、そのすぐ後に書かれたものに付く。** 付いたものによって、`th:if` を付ける要素が決まる。

| 書き方 | 消えるもの | `th:if` を付ける要素 |
|---|---|---|
| ① `ラベル：(条件) 値` | 値だけ（ラベルは残る） | マスの中に作る `<span>` |
| ② `(条件) ラベル：値` | 行ごと | 表（行）では `<tr>`、フォームの直下では `<div>` |
| ③ `(条件) ［ノード］…`・`(条件) 入力項目`・`(条件) ボタン` | そのノード・項目 | その要素（`<a>`・`<img>`・`<h1>`・`<button>` など） |
| ④ `(条件)` だけの行に子を置く | 子全部 | `<th:block>` |

- **① 値だけ**
  - マスの中に `<span th:if="…">` を作り、値をその中に置く（`{…}` を含む値は `<span>` に `th:text` を付ける）。
    `<td>` に `th:if` を付けてはならない（マスが消えて、表の列がずれるため）。
  - 書式とクラス名（`<<…>>`）は `<span>` に付く。`{…}` を含まない値（`備考：({flag}) あり`）にも条件を付けられる。
  - 値の位置のノード（`写真：({showPhoto}) ［画像］/images/{photo}`）では、`<span>` を作らず、そのノードの要素に付ける。
  - 表（列）の列の値にも書ける（`名前：({m.active}) {m.name}`）。条件の中で要素の変数を使える。
  - フォームの直下の表示だけの項目では、`<div>ラベル <span th:if="…" th:text="…">…</span></div>` とする。
  - 値の無い `ラベル：` には書けない（子に条件を付ける）。入力項目のフィールド名（`名前＜text＞：(…) name`）にも書けない。
    書かれていた場合は生成せず、【確認事項】に載せること。
- **② 行ごと**
  - `［表（行）］` の子では `<tr>` に付ける。フォームの直下の項目（入力項目・表示だけの項目）では、その項目の `<div>` に付ける。
  - **`［表（列）］` の列には書けない。** 列見出しの `<th>` は繰り返しの外にあり、行ごとに消せないためである。
    書かれていた場合は生成せず、【確認事項】に載せること。マスの中身だけを消すときは ① の形で書く。
- **③ ノード・入力項目・ボタン**
  - そのノードの要素に付ける（`({message}は空ではない) ［通知］{message}` → `<div class="message" th:if="…" th:text="…">`）。
  - **`［表（行）］` の直下の行では、行頭の条件は常に `<tr>` に付ける**（1マスの行・入力項目の行・ボタンの行のどれでも同じ）。
    ノードの要素に付けると、空の行が残るためである。
  - フォームの直下の入力項目は、その項目の `<div>` に付ける。`＜hidden＞` は `<input type="hidden">` に付ける。
  - タグを作らないノード（`{…}` の無い `［文字］`）に条件を付けた場合は、`<span>` で囲んで付ける（上の例の `在庫小`）。
  - `ラベル：` の子に並べた要素（上の例の `在庫：` の子）と、`┬` でまとめた要素（`┬─({flag}) 登録する＜submit＞`）では、
    その要素だけに付く。`┬` の右に書いた条件も1つ目の要素に付き、`┬` の行全体には付かない。
  - `［箇条書き］` の `［項目］` では、`th:each` と同じ `<li>` に付ける。`th:each` が先に評価されるので、条件の中で要素の変数を使える。
- **④ `(条件)` だけの行に子を置く**
  - 子全体を `<th:block th:if="…">` で囲む。余計な `<div>` を作らない。
  - 子に書けるのは、`(条件)` だけの行を置いた場所に書けるものと同じである（`構成` の直下ならノード、表（行）の中なら行、
    `ラベル：` の子ならマスの中に並べられる要素、`［段落］` の子なら段落に並べられる要素）。表（行）の中では `<th:block>` が `<tr>` を囲む。
  - `┬` の行全体を消すときは、`┬` の行をこの子に置く。
  - `［表（列）］` の列と `［箇条書き］` の子には書けない（列は ② と同じ理由。`［箇条書き］` の子は `［項目］` の1行だけのため）。
    子の無い `(条件)` だけの行も、生成せず【確認事項】に載せること。
  - 入れ子にしてよい。

```
├─({memberList}は空ではない)
│    ├─［小見出し］会員一覧
│    └─［表（列）］memberListの各要素をmとする
│          ├─番号：{m.id}
│          └─名前：{m.name}
└─({memberList}は空である) ［段落］会員がいません
```
```html
<th:block th:if="${not #lists.isEmpty(memberList)}">
  <h2>会員一覧</h2>
  <table>…</table>
</th:block>
<p th:if="${#lists.isEmpty(memberList)}">会員がいません</p>
```

**条件の書き方**

条件は、**`{変数}は<比べる値><言い方>`** と書く。変数は値と同じく半角の `{…}` で囲む（`## 30.3` の「値の書き方」）。
**言い方は次の表にあるものだけ**である。

| 言い方 | 生成する式 |
|---|---|
| `{a}は10より大きい` | `a gt 10` |
| `{a}は10より小さい` | `a lt 10` |
| `{a}は10以上` | `a ge 10` |
| `{a}は10以下` | `a le 10` |
| `{a}は10である` | `a == 10` |
| `{a}は10ではない` | `a != 10` |
| `{flag}はtrueである`・`{flag}`（省略形） | `flag` |
| `{flag}はfalseである` | `not flag` |
| `{a}はnullである` | `a == null` |
| `{a}はnullではない` | `a != null` |
| `{s}は空である` | `#strings.isEmpty(s)`（型によって変わる。下記） |
| `{s}は空ではない` | `not #strings.isEmpty(s)`（同上） |

- 比べる値には、数（`10`・`-1`・`0.5`）、引用符で囲んだ文字列（`"general"`）、変数（`{limit}`）を書ける。
- 文字列は `"…"` で囲む。全角の引用符（`＂…＂`・`“…”`）でもよい。生成する式では `'…'` にする（`{kind}は"general"である` → `kind == 'general'`）。
  文字列の中に `'` または `"` を書いた場合は、生成する式が壊れるため生成せず、【確認事項】に載せること。
- **「空」の式は型で決める。** 型は `受け取り` の型か、同時に生成するクラス・レコードの SPD から分かる場合に使う。

| 型 | `空である` の式 |
|---|---|
| `String` | `#strings.isEmpty(s)` |
| `List` | `#lists.isEmpty(s)` |
| `Set` | `#sets.isEmpty(s)` |
| `Map` | `#maps.isEmpty(s)` |
| 配列 | `#arrays.isEmpty(s)` |

- **型が分からない場合は `String` とみなして `#strings.isEmpty` で生成し、【確認事項】に載せること。**
- 上の表に無い型（`int` など）に「空」を使った場合は、生成せず【確認事項】に載せること。
- 文字列が表示できるかを確かめるときは、`nullではない` ではなく **`空ではない`** を使う。`nullではない` は空文字（`""`）を通してしまう。
- **`true`／`false` の条件（省略形 `({flag})` を含む）は、型が `boolean`（`Boolean`）の変数にだけ使う。**
  型が分かり、`boolean` でない場合は、生成せず【確認事項】に載せること（Thymeleaf では、文字列の `"false"`・`"no"`・`"off"` も偽になるなど、
  `boolean` 以外の値の真偽は分かりにくいため）。型が分からない場合は、そのまま生成する。

**かつ・または**

| 言い方 | 生成する式 |
|---|---|
| `{a}は10以上かつ{b}は5以下` | `a ge 10 and b le 5` |
| `{a}は10以上かつ20以下`（2つ目の主語を省略） | `a ge 10 and a le 20` |
| `{kind}は"a"または"b"` | `kind == 'a' or kind == 'b'` |

- 2つ目からの条件は、主語（`{変数}は`）を省略できる。省略した場合は、直前の条件の主語を使う。
- **`かつ` と `または` を1つの条件の中で混ぜた場合は、どちらを先に結ぶか決められないため生成せず、【確認事項】に載せること。**
  混ぜる必要がある場合は、④ の `(条件)` だけの行を入れ子にして書く。

**表記の揺れ**

次の言い方は、同じものとして扱う（`## 30.1` の「表記の揺れ」と同じ扱い）。

| 言い方 | 同じに扱う書き方 |
|---|---|
| `は` | `が` |
| `である` | 省略してよい（`{a}は10以上`・`{kind}は"general"`）。`と等しい`・`と同じ` |
| `ではない` | `でない`・`と等しくない`・`と同じではない` |
| `より大きい` | `を超える`・`超`・`より多い` |
| `より小さい` | `未満`・`より少ない` |
| `空ではない` | `空でない` |
| `nullではない` | `nullでない` |
| `かつ` | `且つ` |
| `または` | `又は` |

- `より大きい`・`以上` などの後に `である` を付けてもよい（`{a}は10以上である`）。
- 言い方の前後と途中の空白、`かつ`・`または` の前の `、` は無視する。
- この表と上の表に無い言い方は、似ていても読み替えず、生成せず【確認事項】に載せること。

**書けない条件**

次のものは、生成せず【確認事項】に載せること。

- 計算（`{total}は{count}*2より大きい`）
- 件数・長さ（`{list}の件数は5以上`）
- メソッド呼び出し（`{name.length()}は10以下`・`{list.contains("a")}`）

**生成**

- **条件全体を1つの `${…}` に入れる**（`th:if="${a ge 10 and a le 20}"`）。
- 比べる記号と結ぶ記号は **`gt`・`lt`・`ge`・`le`・`and`・`or`・`not`** で書く。属性の中に `<`・`>`・`&` を書かないためである。
  `==`・`!=` はそのまま書く。
- `{…}` の中の式は、値と同じくそのまま使う（`{m.age}` → `m.age`）。
- `th:object` のフォームの中で、**条件の中の変数がすべてフォームオブジェクトのフィールド**（`{memberForm.kind}`）なら、
  オブジェクト名を除いて `*{…}` の中に条件全体を書く（`*{kind == 'general'}`）。ほかの変数が混ざる場合は、条件全体を `${…}` に入れ、
  フィールドも `memberForm.kind` と書く（`*{…}` と `${…}` を1つの条件に混ぜない）。
- 同じ要素に `th:each` があってもよい（`th:each` が先に評価される）。

**入力項目を条件で消すとき**

- **条件で消えた入力項目は、HTML に出ないので送信されない。** フォームオブジェクトのそのフィールドは、値が入らないまま
  （多くは `null`）になる。そのフィールドに `必須` の検証があると、送信のたびに検証エラーになるが、エラー表示も一緒に消えているため、
  画面には理由が出ない。
- **フォームクラスの SPD が分かり（同時に生成する場合や、ワークスペースにある場合）、条件で消える入力項目（④ の子を含む）の
  フィールドに `必須` がある場合は、生成したうえで【確認事項】に載せること**（`springboot-java` の `## 20.6`）。

## 30.5 フォーム

### フォームの形

`［フォーム］[<オブジェクト名>] → [<HTTPメソッド>] <パス>` と書く。

| SPDの記述 | 生成 |
|---|---|
| `［フォーム］memberForm → POST /members` | `<form th:object="${memberForm}" th:action="@{/members}" method="post">` |
| `［フォーム］→ POST /members/{m.id}/delete` | `<form th:action="@{/members/{id}/delete(id=${m.id})}" method="post">` |
| `［フォーム］→ GET /members` | `<form th:action="@{/members}" method="get">` |

- **オブジェクト名は、フォームクラスの型名の先頭の1文字を小文字にしたもの**（`MemberForm` → `memberForm`）とし、
  `受け取り` にも同じ名前で書く。コントローラーが渡す属性名がこの名前になるためである（`## 11.3`）。
- **オブジェクト名を省略したフォーム**は `th:object` を持たない。削除（`POST`）や画面の移動（`GET`）のボタンだけを
  置くほか、簡単な入力テストのように、入力した値をコントローラーの `@パラメータ` でそのまま受け取るときにも使う
  （下記「フォームオブジェクトを使わない入力項目」）。
- HTTPメソッドを省略した場合は `post` とする。
- フォームの中に別のフォームを置いてはならない（HTMLでは入れ子にできない）。

### 入力項目

フォームの中の入力項目は、**`ラベル＜種類＞：フィールド名`** と書く。
- `ラベル` は画面に表示する項目名、`種類` は `<input>` などの種類（下の対応表）、`フィールド名` は入力した値を送る名前
  （生成する `id`・`name`）である。
- **`＜種類＞` は省略できない。** 1行の文字入力も `＜text＞` と書く。
- `フィールド名` は名前であり、値ではない。`{…}` で囲まない（`名前＜text＞：{name}` と書かれていた場合は生成せず、【確認事項】に載せること）。
- `ラベル：{…}` と書いた項目は入力項目ではなく、表示だけの項目になる（下記「フォームの中の表示だけの項目」）。
- **フォームの中に、`＜種類＞` が無く、値がフィールド名の形（英字で始まる英数字と `_` だけ）の `ラベル：値`
  （`名前：name` など）が書かれていた場合は、推測で入力項目にも表示だけの項目にもせず、【確認事項】に載せること。**
  `＜種類＞` の書き忘れであることが多いためである。値が空のもの（`空欄：`）や、それ以外の文字（`注意：半角で入力`）は、
  そのまま表示する。

この節の規則は、オブジェクト名を書いたフォーム（`th:object`）のものである。オブジェクト名を省略したフォームの
入力項目は、下記「フォームオブジェクトを使わない入力項目」に従う。

```
テンプレート：member/form
│
├─目的：会員を登録する
├─タイトル：会員登録
├─css：css/style.css
│
├─受け取り
│  └─入力内容：MemberForm memberForm
│
└─構成
     ├─［見出し］会員登録
     ├─［フォーム］memberForm → POST /members
     │    ├─［表（行）］
     │    │    ├─名前＜text＞：name
     │    │    ├─入会日＜date＞：joinedOn
     │    │    ├─会員種別＜radio＞：kind
     │    │    │    ├─一般：general
     │    │    │    └─学生：student
     │    │    └─メディア＜checkbox＞：mediaTypes
     │    │         ├─印刷本：print
     │    │         └─電子書籍：ebook
     │    ├─番号＜hidden＞：id
     │    └─登録する＜submit＞
     │
     └─［フォーム］→ GET /members
          └─戻る＜submit＞
```

**種類の対応表**

| SPDの種類 | 生成 |
|---|---|
| `＜text＞` | `<input type="text" th:field="*{f}">` |
| `＜number＞`・`＜date＞`・`＜time＞`・`＜datetime-local＞`・`＜email＞`・`＜password＞`・`＜tel＞`・`＜url＞` | `<input type="…" th:field="*{f}">` |
| `＜hidden＞` | `<input type="hidden" th:field="*{f}">`（ラベルもエラー表示も付けない） |
| `＜textarea＞` | `<textarea th:field="*{f}"></textarea>` |
| `＜checkbox＞`（子なし） | `<input type="checkbox" th:field="*{f}">`（`boolean` のフィールド） |
| `＜checkbox＞`（子あり） | 選択肢ごとに `<label><input type="checkbox" th:field="*{f}" value="…"> 表示名</label>` |
| `＜radio＞`（子あり） | 選択肢ごとに `<label><input type="radio" th:field="*{f}" value="…"> 表示名</label>` |
| `＜select＞`（子あり） | `<select th:field="*{f}">` ＋ 選択肢ごとに `<option value="…">表示名</option>` |

- **選択肢は、子の枝に `表示名：値` と書く。** `＜radio＞`・`＜select＞` は選択肢が必須である。
- 選択肢をコントローラーから受け取ったリストから作る場合は、下記「リストから作る選択肢」の書き方をする。
- 表に無い種類は、推測せず【確認事項】に載せること。
- ボタン（`＜submit＞`・`＜reset＞`）は入力項目ではない（下記「ボタン」）。

**入力項目に共通の規則**

- **`th:object` を指定したフォームの中では、フォームオブジェクトのフィールドに必ず `*{…}` を使う。** `${memberForm.name}` と書かない
  （SPD の `{memberForm.name}` も `*{name}` で生成する。下記「フォームの中の表示だけの項目」）。
- **`th:field` は `id`・`name`・`value` を自動生成する。** これらを手で書いてはならない
  （選択肢の `value` は例外。`th:field` はチェックボックス・ラジオボタン・選択肢の値を作らないため）。
- **`＜hidden＞` 以外のすべての入力項目に、エラー表示を付ける。** 入力欄（選択肢がある場合は最後の選択肢）の直後に置く。
  ```html
  <span class="error-msg" th:if="${#fields.hasErrors('name')}" th:errors="*{name}">エラー</span>
  ```
  検証アノテーションが無いフィールドでも、型変換のエラー（日付・数値の変換失敗）は起こるためである。
  `class="error-msg"` は固定で付ける（`## 30.7` の「CSSクラスを勝手に付けない」の例外）。見た目は CSS で定める。
- ラベルは書かれたとおりに出す（`：` などを補わない）。
- 入力項目とボタンにも条件を付けられる（`({flag}) 名前＜text＞：name`）。条件で消えた入力項目は送信されないので、
  `必須` の検証があるフィールドでは報告する（`## 30.4` の「条件表示」の「入力項目を条件で消すとき」）。
- 選択肢の無い入力項目は、`<label for="<フィールド名>">` でラベルを付ける（`th:field` が作る `id` はフィールド名と同じ）。
  選択肢のある `＜checkbox＞`・`＜radio＞` と、子の無い `＜checkbox＞` は、`th:field` が `id` に連番を付けるため
  `for` を使わず、選択肢ごとに `<label>` で入力を包む。項目のラベルは文字だけで出す。

### 表（行）

**`［表（行）］`** は、**子の各枝が1つの行**を表す表である。繰り返しは無い。
フォームの入力項目を、左にラベル・右に入力欄の形で並べるときに使う。フォームの外で、詳細画面のように
左に項目名・右に値の形で並べるときにも使う（下記「行の書き方」）。

```html
<form th:object="${memberForm}" th:action="@{/members}" method="post">
  <input type="hidden" th:field="*{id}">
  <table>
    <tr>
      <td><label for="name">名前</label></td>
      <td>
        <input type="text" th:field="*{name}">
        <span class="error-msg" th:if="${#fields.hasErrors('name')}" th:errors="*{name}">エラー</span>
      </td>
    </tr>
    <tr>
      <td><label for="joinedOn">入会日</label></td>
      <td>
        <input type="date" th:field="*{joinedOn}">
        <span class="error-msg" th:if="${#fields.hasErrors('joinedOn')}" th:errors="*{joinedOn}">エラー</span>
      </td>
    </tr>
    <tr>
      <td>会員種別</td>
      <td>
        <label><input type="radio" th:field="*{kind}" value="general"> 一般</label>
        <label><input type="radio" th:field="*{kind}" value="student"> 学生</label>
        <span class="error-msg" th:if="${#fields.hasErrors('kind')}" th:errors="*{kind}">エラー</span>
      </td>
    </tr>
    <tr>
      <td>メディア</td>
      <td>
        <label><input type="checkbox" th:field="*{mediaTypes}" value="print"> 印刷本</label>
        <label><input type="checkbox" th:field="*{mediaTypes}" value="ebook"> 電子書籍</label>
        <span class="error-msg" th:if="${#fields.hasErrors('mediaTypes')}" th:errors="*{mediaTypes}">エラー</span>
      </td>
    </tr>
  </table>
  <button type="submit">登録する</button>
</form>

<form th:action="@{/members}" method="get">
  <button type="submit">戻る</button>
</form>
```

- 入力項目の行は `<tr><td>ラベル</td><td>入力欄とエラー表示</td></tr>` とする。
- **`［表（行）］` には「〜の各要素を〜とする」を書かない。** 書かれていた場合は生成せず、【確認事項】に載せること。
- `＜hidden＞` の項目は行を作らない。`［表（行）］` の中に書かれていても、`<table>` の直前に置く。
- `［表（行）］` を使わず、入力項目を `［フォーム］` の直下に書いた場合は、1項目を1つの `<div>` にまとめる
  （`<div><label …>…</label> 入力欄 エラー表示</div>`）。

**行の書き方**

**`：` がある行は2マス、`：` が無い `［ノード］` の行は1マス**である。

| SPDの記述 | 生成 |
|---|---|
| `日付：{birthday}` | `<tr><td>日付</td><td th:text="${birthday}">生年月日</td></tr>` |
| `空欄：`（子なし） | `<tr><td>空欄</td><td></td></tr>` |
| `：左マスは空欄` | `<tr><td></td><td>左マスは空欄</td></tr>` |
| `参考図：［画像］/images/sample.png <<50px>>` | `<tr><td>参考図</td><td><img th:src="@{/images/sample.png}" alt="" width="50"></td></tr>` |
| `：［リンク］戻る → /end` | `<tr><td></td><td><a th:href="@{/end}">戻る</a></td></tr>` |
| `［空］：［リンク］戻る → /end` | `：［リンク］戻る → /end` と同じ |
| `操作：` ＋ 子 | `<tr><td>操作</td><td>子を書かれた順に</td></tr>` |
| `［空］：` ＋ 子 | `<tr><td></td><td>子を書かれた順に</td></tr>` |
| `┬─…` ＋ `├─…`・`└─…` | `<tr><td colspan="2">要素を書かれた順に</td></tr>`（下記「1つのマスに複数の要素を並べる」） |
| `［段落］これは段落`（`：` が無い） | `<tr><td colspan="2"><p>これは段落</p></td></tr>` |
| `［リンク］戻る → /end`（`：` が無い） | `<tr><td colspan="2"><a th:href="@{/end}">戻る</a></td></tr>` |
| `備考＜text＞：memo` | 入力項目の行（上記） |

```
├─受け取り
│  └─会員：Member member
│
└─構成
     ├─［見出し］会員詳細
     └─［表（行）］
          ├─番号：{member.id}
          ├─名前：{member.name}
          ├─写真：［画像］/images/{member.photo} "{member.name}の写真" <<120px .写真枠>>
          ├─紹介：
          │    ├─［文字］{member.name}さんのページは
          │    └─［リンク］こちら → /members/{member.id}/profile
          ├─操作：
          │    ├─［リンク］編集 → /members/{member.id}/edit
          │    ├─［文字］|
          │    └─［フォーム］→ POST /members/{member.id}/delete
          │          └─削除＜submit＞
          └─［リンク］一覧へ戻る → /members
```
```html
<table>
  <tr>
    <td>番号</td>
    <td th:text="${member.id}">番号</td>
  </tr>
  <tr>
    <td>名前</td>
    <td th:text="${member.name}">名前</td>
  </tr>
  <tr>
    <td>写真</td>
    <td><img th:src="@{/images/{photo}(photo=${member.photo})}" th:alt="|${member.name}の写真|" alt="" width="120" class="写真枠"></td>
  </tr>
  <tr>
    <td>紹介</td>
    <td>
      <span th:text="|${member.name}さんのページは|">nameさんのページは</span>
      <a th:href="@{/members/{id}/profile(id=${member.id})}">こちら</a>
    </td>
  </tr>
  <tr>
    <td>操作</td>
    <td>
      <a th:href="@{/members/{id}/edit(id=${member.id})}">編集</a>
      |
      <form th:action="@{/members/{id}/delete(id=${member.id})}" method="post">
        <button type="submit">削除</button>
      </form>
    </td>
  </tr>
  <tr>
    <td colspan="2"><a th:href="@{/members}">一覧へ戻る</a></td>
  </tr>
</table>
```

**2マスの行（`：` がある行）**

- 左のマスはラベル、右のマスは値である。ラベルが無い（`：値`）ときは左を、値が無い（`ラベル：`）ときは右を、空の `<td></td>` にする。
  ラベルが無いことは、`［空］：値` とも書ける（`## 30.1`）。`：値` と同じ HTML を生成する。
- 値は `## 30.3` の「値の書き方」のとおりに書く。値の位置には `［画像］`・`［リンク］`・`［文字］`・`［通知］` を書ける
  （`## 30.3` の「値の位置に書くノード」）。
- **値を書かず `ラベル：` の子に並べた行**（上の例の `紹介：`・`操作：`）は、子ノードの内容を、書かれた順に2つ目の `<td>` の中に置く。
  子に書けるノードは、`［表（列）］` の子に並べた列と同じである（`## 30.4`）。
  **フォームの中の表では、ボタン（`＜submit＞`・`＜reset＞`）も子に書ける**（下記「1つのマスに複数の要素を並べる」）。
  入力項目は子に書けない。1行に複数の入力欄を並べる書き方は、この規約に無い。
- 要素が1つだけのときは、子に置かず値の位置に書く（`写真：［画像］…`）。子を1つだけ置いた場合も、値の位置に書いたときと
  同じ HTML を生成する。
- **値と子の両方を書いた行は、生成せず【確認事項】に載せること。**

**1マスの行（`：` が無い行）**

- `［ノード］` の行は、2つのマスを結合した1マスの行（`<tr><td colspan="2">…</td></tr>`）にする。
- 1マスの行に書けるのは、`［段落］`・`［画像］`・`［文字］`・`［通知］`・`［リンク］`・`［フォーム］`（ボタンだけのフォーム）である。
  それ以外のノード（`［見出し］`・`［表（行）］`・`［改行］` など）が書かれていた場合は生成せず、【確認事項】に載せること。
- **フォームの中の表では、ボタン（`送信＜submit＞`・`消去＜reset＞`）を1つだけ書いた行も1マスの行にする。**
  `┬─送信＜submit＞` と書いたときと同じ HTML（`<tr><td colspan="2"><button type="submit">送信</button></td></tr>`）を生成する。
  ボタンを入力欄の列（右のマス）にそろえたいときは、`［空］：` の子に置く（下記）。
- `：` も `［…］` も無い文字だけの行（`操作`）は、生成せず【確認事項】に載せること（`## 30.1`）。
- 1マスの中に複数の要素を並べるときは、`┬` でまとめる（下記）。

**条件を付けた行**

- 表（行）の子の行頭に書いた条件（`({flag}) 備考：…`・`({flag}) ［リンク］…`・`({flag}) 送信＜submit＞`）は、`<tr>` に付ける。
  値の先頭に書いた条件（`備考：({flag}) …`）は、マスの中の `<span>` に付ける（`## 30.4` の「条件表示」）。
- 複数の行をまとめて消すときは、`(条件)` だけの行の子に並べる。`<th:block th:if="…">` が `<tr>` を囲む。

**1つのマスに複数の要素を並べる**

ボタンやリンクなどを1つのマスに並べる書き方は2つある。

| 書き方 | 並べる場所 |
|---|---|
| `［空］：`（または `ラベル：`）の子に並べる | 2マスの右のマス（入力欄の列にそろう） |
| `┬` でまとめる | 2つのマスを結合した1マス（`colspan="2"`） |

```
├─［フォーム］→ POST /select
│    └─［表（行）］
│          ├─都市＜select＞：city
│          │    ├─東京：東京
│          │    └─大阪：大阪
│          └─［空］：
│                ├─送信＜submit＞
│                ├─消去＜reset＞
│                └─［リンク］キャンセル → /list
│
└─［フォーム］→ POST /select
      └─［表（行）］
            ├─都市＜select＞：city
            │    ├─東京：東京
            │    └─大阪：大阪
            └─┬─送信＜submit＞ <<.中央揃え>>
               ├─消去＜reset＞
               └─［リンク］キャンセル → /list
```
```html
<form th:action="@{/select}" method="post">
  <table>
    <tr>
      <td><label for="city">都市</label></td>
      <td>
        <select id="city" name="city">
          <option value="東京">東京</option>
          <option value="大阪">大阪</option>
        </select>
      </td>
    </tr>
    <tr>
      <td></td>
      <td>
        <button type="submit">送信</button>
        <button type="reset">消去</button>
        <a th:href="@{/list}">キャンセル</a>
      </td>
    </tr>
  </table>
</form>

<form th:action="@{/select}" method="post">
  <table>
    <tr>
      …（上と同じ）
    </tr>
    <tr>
      <td colspan="2" class="中央揃え">
        <button type="submit">送信</button>
        <button type="reset">消去</button>
        <a th:href="@{/list}">キャンセル</a>
      </td>
    </tr>
  </table>
</form>
```
```css
/* css：に書いたファイルに定義する */
.中央揃え {
  text-align: center;
}
```

- **`┬` の右に1つ目の要素を書き、2つ目からは `┬` の下に `├─`・`└─` で並べる。** すべての要素を、書かれた順に1つの `<td colspan="2">` の中に置く。
- `┬` でまとめた要素に書けるのは、1マスの行に書けるノード（上記）と、`［改行］`、ボタン（`＜submit＞`・`＜reset＞`）である。
  ボタンはフォームの中の表でだけ書ける（`## 30.1`）。入力項目・`ラベル：値`・`［見出し］` などが書かれていた場合は生成せず、【確認事項】に載せること。
- **`┬` の行の末尾の `<<…>>` は、`<td colspan="2">` に付ける**（1つ目の要素には付かない）。書けるのはクラス名だけである（`## 30.4` の「CSSクラスの指定」）。
  書式・サイズが書かれていた場合は生成せず、【確認事項】に載せること。サイズなどの `<<…>>` を付けた `［画像］` や、クラス名を付けた `［リンク］` は、2つ目以降に置く。
- クラス名を書かない場合は、`class` を付けない。中央揃えなどの配置は、クラス名を付けて CSS で定める（`style` 属性にしない）。
- 要素が1つだけのときは `┬` を使わず、1マスの行（`［リンク］戻る → /end`・`送信＜submit＞`）として書く。
- `┬` は `［表（行）］` の子にだけ書ける。`［表（列）］` の列、`［フォーム］` の直下、`構成` の直下などに書かれていた場合は生成せず、【確認事項】に載せること。
- `┬` でまとめた要素には、1つずつ条件を付けられる（`┬─({flag}) 送信＜submit＞`）。条件はその要素だけに付く。
  `┬` の行全体を消すときは、`(条件)` だけの行の子に `┬` の行を置く（`## 30.4` の「条件表示」）。

**フォームの中の表（行）**

- フォームの中でも外でも使える。入力項目の行と、表示の行・1マスの行を混ぜてよい。
- フォームの中の `［表（行）］` には `［フォーム］` を書けない（フォームの入れ子になるため。上記「フォームの形」）。
- フォームの中では、`{memberForm.…}` を `*{…}` で生成する（下記「フォームの中の表示だけの項目」）。

### フォームの中の表示だけの項目

フォームの中でも、**`<ラベル>：<値>[<<書式・クラス名>>]`** と書いた項目は、入力欄を作らず値を表示するだけである
（編集画面の会員番号など）。値は送信されない。

```
├─［フォーム］memberForm → POST /members/update
│    ├─［表（行）］
│    │    ├─会員番号：{memberForm.id}
│    │    └─名前＜text＞：name
│    ├─番号＜hidden＞：id
│    └─更新する＜submit＞
```
```html
<tr>
  <td>会員番号</td>
  <td th:text="*{id}">会員番号</td>
</tr>
```

- **値の `{…}` は、フォームの中でも `受け取り` の名前から始める**（`## 30.3` の「値の書き方」）。フォームオブジェクトの
  フィールドは `{memberForm.id}` と書き、`{id}` とは書かない。`{id}` は `受け取り` の `id` を指すことになるためである。
- `th:object` のフォームの中では、フォームのオブジェクト名で始まる式を、オブジェクト名を除いて `*{…}` で生成する
  （`{memberForm.id}` → `th:text="*{id}"`、文字と混ざる場合は `{memberForm.id}番` → `th:text="|*{id}番|"`）。
  `${memberForm.id}` とは書かない。
- フォームオブジェクト以外の値（`{departmentName}` など）は、フォームの中でも `${…}` で生成する。
  オブジェクト名を省略したフォームの中では、すべて `${…}` で生成する。
- 入力項目のフィールド名（`名前＜text＞：name`・`番号＜hidden＞：id`）は、値ではなく送る名前なので、
  オブジェクト名を付けずに書く（`## 30.5` の「入力項目」）。**`{…}` で書くのは画面に出す値、`：` の後にそのまま書くのは送る名前**である。
  `th:field="*{id}"` が送る名前と今の値の両方を決めるため、`番号＜hidden＞：{memberForm.id}` とは書かない。
- 値がフィールド名の形の `ラベル：値`（`名前：name`）は、`＜種類＞` の書き忘れとして報告する（上記「入力項目」）。
- `<label>` もエラー表示も付けない。
- `［表（行）］` の中では上記「行の書き方」のとおりに生成する。
  `［フォーム］` の直下では `<div>ラベル <span th:text="…">ダミー</span></div>` とする。値の位置のノード（`戻り先：［リンク］…`）は、
  `<span>` の代わりにそのノードの要素を置く（`<div>戻り先 <a …>…</a></div>`）。
- 値の書き方は `## 30.3` の「値の書き方」、書式とクラス名（`<<…>>`）は `## 30.4` の「値の書式」「CSSクラスの指定」と同じである。
- 値を送信もしたい場合は、この項目とは別に `＜hidden＞` の項目を書く（上の例の `番号＜hidden＞：id`）。

### フォームオブジェクトを使わない入力項目

簡単な入力テストのように、入力した値をコントローラーでそのまま受け取るだけの場合は、
**オブジェクト名を省略したフォーム**に入力項目を置く。書き方は上の「入力項目」と同じ `ラベル＜種類＞：名前` であるが、
`名前` はフォームのフィールド名ではなく、**リクエストパラメーターの名前**である。

```
テンプレート：test/input
│
├─目的：入力した値を送信する
├─タイトル：入力テスト
│
├─受け取り：なし
│
└─構成
     ├─［見出し］入力テスト
     └─［フォーム］→ POST /test
          ├─名前＜text＞：name
          ├─年齢＜number＞：age
          ├─会員種別＜radio＞：kind
          │    ├─一般：general
          │    └─学生：student
          └─送信する＜submit＞
```
```html
<form th:action="@{/test}" method="post">
  <div><label for="name">名前</label> <input type="text" id="name" name="name"></div>
  <div><label for="age">年齢</label> <input type="number" id="age" name="age"></div>
  <div>会員種別
    <label><input type="radio" name="kind" value="general"> 一般</label>
    <label><input type="radio" name="kind" value="student"> 学生</label>
  </div>
  <button type="submit">送信する</button>
</form>
```

**種類の対応表**（`n` はパラメーター名）

| SPDの種類 | 生成 |
|---|---|
| `＜text＞` | `<input type="text" id="n" name="n">` |
| `＜number＞`・`＜date＞`・`＜time＞`・`＜datetime-local＞`・`＜email＞`・`＜password＞`・`＜tel＞`・`＜url＞` | `<input type="…" id="n" name="n">` |
| `＜textarea＞` | `<textarea id="n" name="n"></textarea>` |
| `＜checkbox＞`（子なし） | `<input type="checkbox" name="n" value="true">` |
| `＜checkbox＞`（子あり） | 選択肢ごとに `<label><input type="checkbox" name="n" value="…"> 表示名</label>` |
| `＜radio＞`（子あり） | 選択肢ごとに `<label><input type="radio" name="n" value="…"> 表示名</label>` |
| `＜select＞`（子あり） | `<select id="n" name="n">` ＋ 選択肢ごとに `<option value="…">表示名</option>` |

- **初期値は常に空（`""`）である。** `value`（選択肢の `value` を除く）・`th:value`（選択肢の `th:value` を除く）・
  `checked`・`selected` を付けない。
  送信後に同じ画面を返すと、入力した値は消える。値を残したい画面は、フォームオブジェクトを使うこと。
- **`id`・`name` は手で書く。** `th:field`・`*{…}` は使わない（`th:object` が無いため）。`id` は、`<label for>` を使う
  選択肢の無い入力項目と `<select>` にだけ付ける。
- **エラー表示を付けない。** 検証の結果（`BindingResult`）が無く、`#fields` を使えないためである。
- **`＜hidden＞` は生成せず、【確認事項】に載せること。** 初期値が常に空なので、送る値が無いためである。
- 表に無い種類も、推測せず【確認事項】に載せること。
- ラベルの付け方、`［表（行）］` の中での配置、`［フォーム］` の直下に書いた場合の `<div>` は、上の規則と同じである
  （エラー表示が無いだけが異なる）。
- 下記「リストから作る選択肢」も使える。`th:field` の代わりに `name`（`<select>` には `id` も）を書き、エラー表示を付けない。
- 同じフォームの中に、`th:field` を使う入力項目と混ぜることはできない（`th:object` が無いため）。
- **受け取る側**は、送信先のハンドラーメソッドの `@パラメータ` の引数である。変数名はパラメーター名と一致させ、
  既定値（`= ""` など）を付けることを推奨する（`## 11.4`）。

### ボタン

ボタンは、入力項目と同じ形で **`キャプション＜種類＞`** と書く。`キャプション` はボタンに表示する文字である。

| SPDの記述 | 生成 |
|---|---|
| `登録する＜submit＞` | `<button type="submit">登録する</button>` |
| `クリア＜reset＞` | `<button type="reset">クリア</button>` |

- ボタンには `：` 以降を書かない（送る値を持たない）。書かれていた場合は生成せず、【確認事項】に載せること。
- **ボタンはフォームの中にだけ書ける**（`## 30.1`）。フォームの外（`［リンク］` の子など）に書かれていた場合は生成せず、
  【確認事項】に載せること。
- フォームの中の `［表（行）］` では、ボタンとリンクを1つのマスに並べられる（`［空］：` の子・`┬`。上記「表（行）」）。
  ボタンを1つだけ書いた行は、2つのマスを結合した1マスの行になる（上記「表（行）」の「1マスの行」）。
- 上記以外の種類（`＜button＞` など）は、JavaScript が無いと動かないため生成せず、【確認事項】に載せること。

### リストから作る選択肢

`＜select＞`・`＜radio＞`・`＜checkbox＞` の選択肢を、コントローラーから受け取ったリスト（部署の一覧など）から作る場合は、
入力項目の子に **`<リスト>の各要素を<変数>とする`** の枝を置き、その子に **`{表示名の式}：{値の式}`** を1行書く。

```
├─受け取り
│  ├─入力内容：MemberForm memberForm
│  └─部署リスト：List<Department> departments
…
│    ├─所属＜select＞：departmentId
│    │    └─departmentsの各要素をdとする
│    │         └─{d.name}：{d.id}
```
```html
<label for="departmentId">所属</label>
<select th:field="*{departmentId}">
  <option value="">選択してください</option>
  <option th:each="d : ${departments}" th:value="${d.id}" th:text="${d.name}">name</option>
</select>
<span class="error-msg" th:if="${#fields.hasErrors('departmentId')}" th:errors="*{departmentId}">エラー</span>
```

| SPDの種類 | 生成（`L` はリスト、`x` は変数、`f` はフィールド名） |
|---|---|
| `＜select＞` | `<option value="">選択してください</option>` ＋ `<option th:each="x : ${L}" th:value="${x.値}" th:text="${x.表示名}">表示名</option>` |
| `＜radio＞` | `<label th:each="x : ${L}"><input type="radio" th:field="*{f}" th:value="${x.値}"> <span th:text="${x.表示名}">表示名</span></label>` |
| `＜checkbox＞` | `<label th:each="x : ${L}"><input type="checkbox" th:field="*{f}" th:value="${x.値}"> <span th:text="${x.表示名}">表示名</span></label>` |

- 書き方は `［表（列）］` の「〜の各要素を〜とする」と同じである（`## 30.4`）。変数名は自由に付けてよい。
  ただし、入力項目の子なので `［…］` で囲まない。
- **`{表示名の式}：{値の式}` は、固定の選択肢と同じ「表示名：値」の順**である。式は変数から始める（`d.name`）。
- **固定の選択肢とは、`{…}` の有無で見分ける。** `一般：general` は固定の選択肢、`{d.name}：{d.id}` はリストから作る選択肢である。
  固定の選択肢（入力項目の直下）に `{…}` があった場合、リストから作る選択肢（「〜の各要素を〜とする」の下）に `{…}` が
  無かった場合は、生成せず【確認事項】に載せること。
- 表示名は、文字と変数を混ぜて書いてよい（`{d.code} {d.name}：{d.id}` → `th:text="|${d.code} ${d.name}|"`。`## 30.3` の「値の書き方」）。
  `：` の左に `{…}` を書けるのは、ここだけである。値は `{…}` 1つだけとする。
- **リストの名前は、`受け取り` に書かれていなければならない**（`## 30.2`）。無い場合は推測で補わず、
  `## 0.8` の報告の【見つからない名前】に載せること。
- `＜select＞` には、先頭に `<option value="">選択してください</option>` を必ず付ける。`＜radio＞`・`＜checkbox＞` には付けない。
- `＜radio＞`・`＜checkbox＞` では、`<label>` に `th:text` を付けない（中の `<input>` が消えるため）。表示名は `<span>` で出す。
- 固定の選択肢と、リストから作る選択肢を、同じ入力項目の中に混ぜてはならない。
  「〜の各要素を〜とする」の子が `{表示名の式}：{値の式}` の1行でない場合も含めて、生成せず【確認事項】に載せること。
- `［表（行）］` の中に書いた場合の配置、ラベルの付け方、エラー表示は、上の「入力項目」と同じである。
- オブジェクト名を省略したフォームでは、`th:field` の代わりに `name="f"`（`<select>` には `id="f"` も）を書き、エラー表示を付けない。

## 30.6 レイアウトの共通化

`レイアウト：layout/base` と書かれた場合、`templates/layout/base.html` の
フラグメントを使う形で生成する。

**レイアウト側（`layout/base.html`）**

```html
<!doctype html>
<html xmlns:th="http://www.thymeleaf.org" lang="ja" th:fragment="page(title, content)">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title th:replace="${title}">タイトル</title>
</head>
<body>
  <header>
    <a th:href="@{/}">ホーム</a>
  </header>
  <main th:replace="${content}"></main>
</body>
</html>
```

**画面側**

```html
<!doctype html>
<html xmlns:th="http://www.thymeleaf.org" lang="ja"
      th:replace="~{layout/base :: page(~{::title}, ~{::main})}">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>会員一覧</title>
</head>
<body>
  <main>
    <!-- ここに「構成」の内容を置く -->
  </main>
</body>
</html>
```

- **`レイアウト：なし` の場合**（`レイアウト` の行が無い場合も含む。`## 30.2`）は、フラグメントを使わず、`<head>`・`<body>` を持つ
  完全なHTMLとして生成する。`構成` の内容は `<body>` の直下に置く。
- レイアウトを使う画面の `css` は生成しない（`## 30.2`）。CSS はレイアウト側の `<head>` に書く。
- レイアウトファイルそのものを生成するのは、SPDに `テンプレート：layout/base` が
  与えられた場合だけである。**存在しないレイアウトを勝手に作ってはならない。**
  参照先が見つからない場合は `## 0.8` の報告の【見つからない名前】に載せること。

## 30.7 テンプレート生成規約

### HTMLの骨格

- `<!doctype html>` から書く。
- `<html>` に `xmlns:th="http://www.thymeleaf.org"` と `lang="ja"` を付ける。
- `<meta charset="UTF-8">` を必ず入れる。
- その直後に `<meta name="viewport" content="width=device-width, initial-scale=1">` を必ず入れる。
  スマートフォンで縮小表示されないためである。`構成` に書かれていなくても生成する。
- `css` があれば、その後に `<link rel="stylesheet" …>` を置く（`## 30.2`）。
- インデントは半角スペース2つとする。

### エスケープ

- **出力は必ず `th:text` を使う。`th:utext` を生成してはならない。**
  SPDに「HTMLとして出力する」と書かれていた場合も生成せず、
  `## 0.8` の報告の【確認事項】に載せること（XSSの原因になるため）。

### 生成しないもの

- **CSSフレームワーク（Bootstrap等）のクラス名を勝手に付けない。**
  SPDに `<<.クラス名>>` の指定がある場合だけ付ける（`## 30.4` の「CSSクラスの指定」）。
  例外は、エラー表示の `class="error-msg"`（`## 30.5`）と通知の `class="message"`（`## 30.3`）だけである。
- **JavaScriptを勝手に追加しない。**
- `構成` に書かれていない要素（ナビゲーション・フッター・装飾用の `<div>`）を追加しない。

### SPDの残し方

**テンプレートSPD全体を、テンプレートの冒頭（`<!doctype html>` の直前）に
Thymeleafのコメントとして残す。**

```html
<!--/*
テンプレート：member/list
├─目的：会員の一覧を表示する
…
*/-->
<!doctype html>
```

- `<!--/* … */-->` は Thymeleaf がレンダリング時に取り除くため、ブラウザには出力されない。
  通常のHTMLコメント（`<!-- … -->`）では出力されてしまうので使わない。
- `spd-core` の `## 9.10` と同じく、**分割して各要素の直前に配ってはならない。**

## 30.8 生成時のチェックリスト（Thymeleaf）

- [ ] テンプレートを `templates/<テンプレート名>.html` に生成したか。テンプレート名をそのまま使ったか（`## 11.1`）
- [ ] 規約に無い書き方（v7 までの `［一覧］`、v6 までの `［条件表示］`・`［そうでなければ］`、v5 までの `見出し：…`・`表＜列定義＞`・`［…］` の書式、それより前の `⇒`・`ボタン：` など）を読み替えずに、生成せず報告したか（`## 30.1`）
- [ ] `［…］` で始まる行だけをノードとして読んだか。`［…］` も `：` も `＜…＞` も無い行、表とフォームの外の `ラベル：値`、表に無いノードの種類を報告したか（`## 30.1`・`## 30.3`）
- [ ] `ラベル：値` を表示、`＜種類＞` の付いた項目を入力として生成したか。フォームの中の `ラベル：{…}` を入力欄にしていないか。フォームの中の、値がフィールド名の形の `ラベル：値`（`名前：name`）を推測で生成せず報告したか。フォームの外の入力項目・ボタンを報告したか（`## 30.1`・`## 30.5`）
- [ ] 値の `{…}` だけを変数として `th:text` で出力し、`{…}` の無い値は本文にそのまま書いたか。文字と変数が混ざった値を `|…|` で生成したか。ラベルの `{…}`・全角の `｛…｝` を報告したか（`## 30.1`・`## 30.3`）
- [ ] 値の位置のノードを `［画像］`・`［リンク］`・`［文字］`・`［通知］` だけにしたか。文字と混ぜた `［…］`、値と子の両方がある行・列を報告したか（`## 30.3`〜`## 30.5`）
- [ ] 子に並べた `［段落］` を、子を間に空白も改行も入れずに続けた1つの `<p>` にしたか。子が `［文字］`・`［リンク］`・`［画像］`・`［改行］` だけであるか。値と子の両方がある・値も子も無い `［段落］` を報告したか。`［改行］` を、要素を並べる場所（`［段落］` の子・マスの子・`┬`）にだけ `<br>` で生成したか（`## 30.3`）
- [ ] `受け取り` の名前と、コントローラーの「〜をテンプレートに渡す」の名前が一致しているか。型を生成に使っていないか（`## 11.2`・`## 30.2`）
- [ ] `css` を `<head>` に `th:href="@{…}"` で読み込んだか。レイアウトを使う画面では生成せずに報告したか（`## 30.2`）
- [ ] 静的な文字列に `th:text` を付けていないか。`th:text` にプレビュー用のダミーを残したか。ダミーを、受け取りの名前そのものなら受け取りのラベル、`ラベル：{…}` ならそのラベル、それ以外は式の最後の名前で決めたか。見本の値（`2026年01月01日`・`1,000`）を作っていないか（`## 30.3`）
- [ ] すべてのパスを `@{…}` で囲んだか。素の `href`／`action` を書いていないか（`## 30.3`）
- [ ] パス変数を `{名前}` + `(名前=${式})` の形にしたか。文字列連結にしていないか（`## 30.3`）
- [ ] リンク・フォームのパスが、コントローラーの `ベースパス` ＋ `マッピング` と一致しているか（`## 11.4`）
- [ ] `［表（列）］` に「各要素」の句があり、`［表（行）］` に無いことを確かめたか。`th:each` を `<tr>`／`<li>` に付けたか（`## 30.4`・`## 30.5`）
- [ ] 値の書式を表のとおりに生成し、`null` のとき空欄にしたか。表に無い書式（`通貨表示` など）を推測で作っていないか（`## 30.4`）
- [ ] 入力項目・`［リンク］`・`［画像］`・`┬` の行・ボタンに書かれた書式を報告したか。フォームの中でフォームオブジェクトのフィールドに付けた書式を、`*{…}` の中に式全体を書いて生成したか（`## 30.4`）
- [ ] 型が分かるとき、書式と型が合うかを確かめたか（日付・時刻のパターンは `java.time` の型と時刻・日付の文字、`3桁区切り`・`円表示` は整数、連結は `List`・`Set`・配列で式を使い分ける）。合わないものを報告したか（`## 30.4`）
- [ ] パターンの `YYYY`・`D`、時の文字が無いパターンの `mm` を、生成したうえで報告したか。全角の引用符を `'…'` にしたか。パターンや区切りの中の `'`・`"` を報告したか（`## 30.4`）
- [ ] 書式を、`{…}` が1つだけの値にだけ付けたか。`<<…>>` の `.<クラス名>` を、`{…}` を含む値の要素と `<img>`・`<a>` に `class` として付けたか。`style` 属性にしていないか。それ以外の項目のクラス名を報告したか（`## 30.4`）
- [ ] `［画像］` を `th:src="@{…}"` で生成したか。`/` で始まらないパス・外部のURL・順序の違う書き方・`px` の無いサイズを報告したか。サイズを `width` 属性にしたか。代替文字列が無いときに `alt=""` を付けたか（`## 30.3`）
- [ ] 表（行）で、`：` がある行を2マス（ラベルか値が無ければ空の `<td>`）、`：` が無い `［ノード］` の行と、フォームの中のボタンを1つだけ書いた行を `colspan="2"` の1マスにしたか。表（列）の `：` の無い列を報告したか（`## 30.4`・`## 30.5`）
- [ ] 子に並べた列・行の子と、1マスの行が、書けるノードだけであることを確かめたか。ボタンを子に置いたのが、フォームの中の表（行）だけであるか（`## 30.4`・`## 30.5`）
- [ ] `［空］：` を `：` と同じ（左のマス・列見出しが空）に生成したか。`：` の左以外の `［空］` を報告したか。`┬` でまとめた要素を、書かれた順に1つの `<td colspan="2">` に置き、`┬` の行の `<<.クラス名>>` をその `<td>` に付けたか。表（行）以外の `┬` を報告したか（`## 30.1`・`## 30.5`）
- [ ] 行の先頭・値の先頭の `{…}` を含む `(…)` を条件として読んだか。`{…}` を含まない括弧と、値の途中の括弧を文字のままにしたか（`## 30.4`）
- [ ] 条件の `th:if` を、付いたものに合わせて付けたか（値だけはマスの中の `<span>`、表（行）の行頭は `<tr>`、フォームの直下の項目は `<div>`、ノードはその要素、`(条件)` だけの行は `<th:block>`）。`<td>` に付けていないか。`th:unless` を生成していないか（`## 30.4`）
- [ ] 条件を除くと正しくない行（`({flag}) 在庫あり` など）、表（列）の列の行頭の条件、表（列）の列と `［箇条書き］` の子の `(条件)` だけの行、子の無い `(条件)` だけの行、値の無い `ラベル：` とフィールド名に付けた条件を報告したか（`## 30.4`）
- [ ] 条件の言い方を表（表記の揺れを含む）のとおりに式にし、`gt`・`lt`・`ge`・`le`・`and`・`or`・`not` で1つの `${…}`（フォームのフィールドだけなら `*{…}`）に生成したか。表に無い言い方、`かつ` と `または` を混ぜた条件、計算・件数・メソッド呼び出し、引用符を含む文字列を報告したか（`## 30.4`）
- [ ] 「空」の式を型（`String`・`List`・`Set`・`Map`・配列）で決めたか。型が分からないものを `#strings` で生成して報告したか。`boolean` でないと分かる変数の `true`／`false` の条件を報告したか（`## 30.4`）
- [ ] 条件で消える入力項目のフィールドに `必須` があるとき、生成したうえで報告したか。`※任意` の受け取りを条件なしで使っているときに報告したか（`## 30.2`・`## 30.4`）
- [ ] `th:object` の中で、フォームオブジェクトのフィールド（SPD の `{memberForm.…}`）に `*{…}` を使ったか。`${memberForm.…}` と書いていないか。フォームオブジェクト以外の値を `*{…}` にしていないか（`## 30.3`・`## 30.5`）
- [ ] `th:field` があるのに `id`／`name`／`value` を手で書いていないか（選択肢の `value` を除く）（`## 30.5`）
- [ ] `th:object` のフォームの、`＜hidden＞` 以外のすべての入力項目に、`class="error-msg"` のエラー表示を付けたか（`## 30.5`）
- [ ] オブジェクト名を省略したフォームの入力項目に、`id`・`name` を手で書いたか。初期値・エラー表示・`th:field` を付けていないか。`＜hidden＞` を生成せずに報告したか（`## 30.5`）
- [ ] 選択肢を `表示名：値` から生成し、`<label>` で入力を包んだか（`## 30.5`）
- [ ] リストから作る選択肢を、「〜の各要素を〜とする」の下の `{表示名の式}：{値の式}` から `th:each` で生成したか。リストの名前が `受け取り` にあるか。`＜select＞` にだけ「選択してください」を付けたか（`## 30.5`）
- [ ] ボタンを `キャプション＜submit＞`・`＜reset＞` から `<button>` で生成したか（`## 30.5`）
- [ ] フォームを入れ子にしていないか。フォームの外にボタンを置いていないか（`## 30.1`・`## 30.5`）
- [ ] `th:utext` を生成していないか（`## 30.7`）
- [ ] 存在しないレイアウトを勝手に作っていないか（`## 30.6`）
- [ ] `構成` に無い要素・CSSクラス・JavaScriptを追加していないか（`## 30.7`）
- [ ] `xmlns:th`・`lang="ja"`・`<meta charset="UTF-8">`・`<meta name="viewport" …>` を入れたか（`## 30.7`）
- [ ] テンプレートSPD全体を `<!--/* … */-->` で冒頭に残したか（`## 30.7`）

## 30.9 完全な変換例

### 与えられたSPD

```
テンプレート：member/list
│
├─目的：会員の一覧を表示する
├─レイアウト：なし
├─タイトル：会員一覧
├─css：css/style.css
│
├─受け取り
│  ├─会員リスト：List<Member> memberList
│  └─メッセージ：String message　※任意
│
└─構成
     ├─［見出し］会員一覧
     ├─({message}は空ではない) ［通知］{message}
     ├─({memberList}は空である) ［段落］会員が登録されていません。
     ├─({memberList}は空ではない) ［表（列）］memberListの各要素をmとする
     │  ├─番号：{m.id}
     │  ├─名前：{m.name}
     │  ├─入会日：{m.joinedOn} <<"yyyy年MM月dd日">>
     │  └─操作：
     │        ├─［リンク］編集 → /members/{m.id}/edit
     │        ├─［文字］|
     │        └─［フォーム］→ POST /members/{m.id}/delete
     │              └─削除＜submit＞
     └─［リンク］新規登録 → /members/new
```
