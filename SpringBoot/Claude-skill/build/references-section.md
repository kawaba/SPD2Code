# references の構成

詳細な規約は、`references/` フォルダーに節ごとのファイルで置いてある。**必要な節のファイルだけを開いて読む。** フォルダーのファイルをまとめて読んだり、関係のないファイルを開いたりしない。

**ファイルを読んでいる間は、何も書かない。** 「規約を読み込んでいます」「〜を確認してから生成します」のような途中経過や予告を出力しない。出力は、必要なファイルをすべて読み終えてから、`未記入判定:` の1行で始める。出力してよいのは `## 0.5` の6つだけである。**コードの中のコメントに書いたこと（補った引数など）を、コードの外でもう一度説明しない。**

- 規約の中で `## 20.7` のように節番号だけで参照しているときは、下の表でその番号のファイルを開く。`## 0.8`・`### 9.4.2` のような下位の節は、上位の節（`## 0`・`### 9.4`）のファイルにある。
- `## 1`〜`## 8` は `references/01-general.md` にある。`## 4`（キーボード入力）と `## 9.7`（Javaコード生成規約）は欠番である。後者は `## 20.7` に置き換えてある。
- 「共通規約」は `00`〜`11` で始まるファイル、「Spring Boot 規約」は `20-` で始まるファイル、「Thymeleaf 規約」は `30-` で始まるファイルを指す。
- `references/pom.xml` は依存ライブラリの見本である。チャットに `pom.xml` が添付された場合は、そちらを優先する。
- 規約は GitHub Copilot 用の規約から作っているため、次のように読み替える。
  - 「ワークスペース」「プロジェクト内」→ チャットに貼られたSPD、チャットに添付されたファイル、同じ会話でそれまでに出力したコード。
  - `spd-core` → 共通規約の `## 9`。`springboot-java` → Spring Boot 規約。`thymeleaf` → Thymeleaf 規約。
  - 「ファイルを編集するとき」「読み込まれる」→ そのSPDからコードを生成するとき。
  - 「このファイル」「この文書」→ その節が書かれている規約（共通規約・Spring Boot 規約・Thymeleaf 規約）。
