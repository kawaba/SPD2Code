## 20.8 生成時のチェックリスト（Spring Boot 固有）

`spd-core` の `## 9.9` に加えて、次を確認する。

### 共通（`## 20.1`）

- [ ] 規約に無い書き方（以前の版の `依存`・`基底パス`・`フォームへ詰め替え`・`フォームに詰め替え → F`・`詰め替え ← F`・`@桁数(N)`、マーカーの無い `パス変数：`・`パラメータ：` など）を読み替えずに、生成せず報告したか
- [ ] 全角 `＠` のマーカー・検証も読み落としていないか。生成したアノテーションを半角の `@` にしたか
- [ ] `インジェクション` を**コンストラクタインジェクション**で注入したか。フィールドに `@Autowired` を付けていないか
- [ ] コントローラーからリポジトリを直接呼び出していないか
- [ ] REST API の指定があった場合、生成せずに報告したか
- [ ] データが見つからないときの画面の切り替え（404 の画面・一覧へ戻すなど）や `@ExceptionHandler` が書かれていた場合、推測で生成せず報告したか

### コントローラー（`## 20.2`）

- [ ] `マッピング` を `メソッド` の子としてだけ扱ったか。パスが省略または `/` だけのとき、マッピングの引数を `{"", "/"}` とし、行末に理由の行コメントを付けたか
- [ ] パスを明示した `マッピング` に、末尾に `/` を付けた別名（`{"/books", "/books/"}` など）を加えていないか
- [ ] `マッピング` のパスが `ベースパス` と同じ文字列で始まるとき、パスを直さずにSPDのとおり生成し、URL が重なることを【確認事項】で知らせたか
- [ ] `マッピング` の HTTPメソッドが `GET`・`POST` 以外のとき、生成せずに報告したか。パスの `{…}` と `@パス変数` の引数の名前が食い違うとき、名前を直さずに報告したか
- [ ] `戻り値` が省略されたハンドラーメソッドを `String` で生成し、`@return` の説明を `処理` の終わり方から決めたか。`引数：なし` でも補う引数を補ったか
- [ ] 引数の種類を、マーカー（`@検証`・`@パス変数`・`@パラメータ`）と型で決めたか。ハンドラーメソッドのマーカーの無い単純な型の引数を、推測で `@RequestParam` などにしていないか
- [ ] フォームの変数名を型名の先頭を小文字にしたもの（`memberForm`）にし、`@ModelAttribute` を付けていないか。違う名前を勝手に言い換えていないか
- [ ] `@Valid` を付けた引数の**直後**に `BindingResult` を置いたか。`BindingResult result`・`Model model`・`RedirectAttributes redirectAttrs` を条件どおりに補い、それぞれ行コメントで明示したか。書かれた名前があればそれを使ったか
- [ ] `検証結果にエラーがある` を、そのメソッドの `BindingResult` の引数の `hasErrors()` にしたか。`@検証` の引数が無い・2つ以上ある場合と、`検証エラーがある` などの言い回しを報告したか
- [ ] 「〜をテンプレートに渡す」の名前を**言い換えずに**そのまま `addAttribute` の第1引数にしたか（`## 11.2`）
- [ ] サービスのメソッド名が省略されているとき、サービスに実在するメソッドから1つに決めたか。決められない場合に推測でメソッドを作らず報告したか
- [ ] `処理` の「"…"を返す」の文字列を**そのまま** `return` したか。`.html` を付けていないか。`/` で始まるテンプレート名を報告したか（`## 11.1`）
- [ ] `ベースパスにリダイレクトする` を `ベースパス` の値へのリダイレクトにしたか。`ベースパスの<パス>にリダイレクトする` を、`ベースパス` の値にパスを続け、`{名前}` を変数の連結にしたものにしたか
- [ ] フラッシュメッセージの名前が省略されたとき `message` にしたか。`addFlashAttribute` を、リダイレクトと**組で**使ったか
- [ ] 「詰め替える」を、サービスの `copyEntityToForm` の呼び出しにしたか。コントローラーでフィールドをコピーしていないか
- [ ] `エンティティ<変数>をフォームに詰め替える` のフォーム型を、変数の型を対象にするサービスの `詰め替え` から決め、変数名をフォーム型の先頭を小文字にした名前にしたか。決められないときと、フォームからエンティティへの詰め替えを報告したか

### サービス（`## 20.3`）

- [ ] サービスに `Model` や `HttpServletRequest` を持ち込んでいないか
- [ ] `トランザクション` ノードが無い `メソッド：` に、`@Transactional` を勝手に付けていないか。`@Transactional` を `org.springframework.transaction.annotation` から取ったか
- [ ] `自動生成` は、書かれた項目だけを表どおりのシグネチャ・トランザクションで生成したか。リポジトリが `インジェクション` にあることを確かめたか
- [ ] フォームの型を省略した `新規作成`・`更新`・`詰め替え` を「エンティティ名＋Form」にしたか。`新規作成`・`更新` で、同名・同型でないフィールドを推測で詰め替えていないか
- [ ] メソッドをSPDの順に並べ、自動生成のメソッドを `自動生成` の枝の位置に置いたか
- [ ] `検索メソッド` の移譲を、リポジトリのSPDに書かれたメソッドだけについて、同名・同シグネチャ・`readOnly = true` で生成したか
- [ ] `詰め替え` を、書かれていないのに暗黙に生成していないか。`詰め替え` の1項目から `copyFormToEntity` と `copyEntityToForm` の2つを生成したか
- [ ] `copyFormToEntity` は `private void`・主キーを除いてコピー、`copyEntityToForm` は `public void`・主キーも含めてコピーとし、同じフォーム型の `詰め替え` があるとき `新規作成`・`更新` からそれを呼び出したか

### リポジトリ（`## 20.4`）

- [ ] リポジトリを `interface` として生成し、`@Repository` を付けていないか
- [ ] 命名規約に合わない `検索メソッド` に、推測で `@Query` を補っていないか。メソッド名に含まれるフィールド名がエンティティにあることを確かめ、無いものを報告したか。`主キー` の型をエンティティの主キーの型と照合したか
- [ ] `メソッド：` の `JPQL` から、必ず `@Query` を生成したか。すべての引数に `@Param` を付けたか。更新・削除の JPQL を報告したか
- [ ] JPQL の条件のフィールドを、名指しされたフィールド（説明またはフィールド名）か、名指しが無ければ引数名と同じフィールドとして読んだか。引数の型がそのフィールドの型と一致することを確かめたか
- [ ] 部分一致を `LIKE %:x%` ではなく `CONCAT` で生成したか

### エンティティ（`## 20.5`）

- [ ] エンティティに `@主キー` があったか。引数なしコンストラクタを補い、行コメントで明示したか
- [ ] `@自動採番` を `@主キー` の `Long`・`Integer` だけに付けたか。`@文字数(N)` を `String`、`@精度(P, S)` を `BigDecimal` だけに付け、ほかを報告したか
- [ ] 主キーを対象とするエンティティの `等値判定` を、id が `null` でないときだけ等しいとする `equals` と、一定の値を返す `hashCode` で生成したか
- [ ] `多対一`・`一対一` の関連に `fetch = FetchType.LAZY` を付けたか
- [ ] `@値コレクション` のフィールドに `@ElementCollection` だけを付けたか
- [ ] 日付・時刻のフィールドに `@Temporal` を付けていないか。`Date`・`Calendar` が書かれていた場合、生成せずに報告したか

### フォーム（`## 20.6`）

- [ ] フォームに永続化アノテーションを付けていないか
- [ ] フォームの検証を、フィールドの行末と、その下の枝の無い `@` の行から読んだか。検証ごとに `@` が付いているか（1つの `@` の後に2つ以上書かれていたら報告したか）。行末と下の行の両方に書かれていたら報告したか。引用符の中の `@`・`、`・空白で区切っていないか。`検証` の枝が書かれていた場合、生成せずに報告したか
- [ ] 検証の対応表に無い表現を、推測でアノテーション化していないか
- [ ] フォームの検証を、フィールドの型と照らし合わせたか。型に合わない検証（`Integer` の `N文字以内`、コレクションの `N文字以内` など）を生成せず報告したか。コレクションの個数を `N個以内` などから `@Size` にしたか
- [ ] コレクションの `必須` を `@NotEmpty` にしたか。メッセージはSPDに明示された場合だけ付けたか
- [ ] 小数を含む範囲を `@DecimalMin`・`@DecimalMax` に、`超`・`より大きい`・`未満` を `inclusive = false` にしたか。`String` の `値なし` を生成せず報告したか。`@URL`・`@CreditCardNumber`・`@ISBN` を `org.hibernate.validator.constraints` から取ったか
- [ ] フォームの `java.time` のフィールドに、型に合った `@DateTimeFormat` を付けたか
- [ ] フォームの数値の基本型、主キーのフィールドの `必須`、`ゲッター`・`セッター` の無い `自動生成` を、生成したうえで報告したか
- [ ] 複数のフィールドを比べる検証・検証グループ・入れ子のフォームを、生成せず報告したか

### 共通の生成規約（`## 20.7`）

- [ ] `System.out` / `System.err` / `Input` クラスを使っていないか。`コンソールに表示する` を読み替えずに報告したか
- [ ] `処理` にログの行があるとき、ロガー（`private static final Logger log`）をフィールドの先頭に補ったか。メッセージの `{…}` を SLF4J の `{}` と後ろの引数にし、文字列の `+` でつないでいないか。`例外<変数>とともに` の例外を最後の引数にしたか。`"…"` で囲まれていないメッセージを報告したか
- [ ] SPDに無い `catch` を補っていないか。利用者が入力した値で `主キーで検索` を呼ぶ `処理` を、生成したうえで報告したか
- [ ] インデントを半角スペース4つにし、アノテーションを付く宣言と同じ深さに置いたか。`クラス:` などのタイトルの型に、Web 層のアノテーションを付けていないか
- [ ] パッケージ名を、SPDのタイトル行の前の `※` の行から取り、そのまま `package` 文にしたか。無い場合に `package` 文を書かずに生成し、パッケージの分からない同じプロジェクトのクラスの import を推測で書かなかったか（`## 10.4`）。表に無い型（`クラス:` など）のパッケージを推測で作っていないか
- [ ] import を1クラスずつ書き（ワイルドカードなし）、使わないものを書かず、`java` → `javax` → `org` → `com` → そのほか の順に、グループの間を空行にして並べたか。`javax.*` ではなく `jakarta.*` を使ったか
- [ ] 各Javaファイルの先頭（`package` 文・`import` 文より前）に、**その型のSPDだけ**をブロックコメントとして残したか

### 設定ファイル（`## 20.10`）

- [ ] 設定ファイルのSPDを、`application.properties` の先頭に各行 `# ` を付けて原文のまま残し、項目をSPDの順に、対応表のキーで出力したか。見出し・`データベース`・ドライバークラス名・dialect を出力していないか
- [ ] 書かれていないオン・オフを出力せず、「〜しない」を `false`、`パスワード：なし` を空の値にしたか。値を言い換えていないか
- [ ] 値が空の項目を未記入とし、`DB名` が無い・大文字や `-` などを含む `DB名`（生成したうえで）・対応表に無い項目名・そのデータベースに無い接続URLの項目・H2 以外の `H2コンソール`・`スキーマ自動生成` の値に無いもの・プロファイル別のファイル名を【確認事項】で報告したか。ドライバーの依存関係が `pom.xml` に無いことを知らせたか
