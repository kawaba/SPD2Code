## 11. コントローラーとテンプレートの対応規約

**この章は、Javaコードとテンプレートのどちらを生成するときも必ず適用する。**
両者の食い違いは、コンパイルが通っても実行時に画面が壊れる原因になる。

### 11.1 テンプレート名

- コントローラーのハンドラーメソッド（`マッピング` を持つ `メソッド`）の `処理` に書かれた
  `"…"を返す` の文字列を、**そのまま**戻り値の文字列にする。これがテンプレート名である。
- テンプレートSPDのタイトル（`テンプレート：…`）には、同じ文字列を書く。
- テンプレートの実ファイルは `src/main/resources/templates/<その文字列>.html` に置く。
- 拡張子 `.html` は SPD にも戻り値にも書かない。
- **テンプレート名は `/` で始めない**（`"book-list"`。`"/book-list"` としない）。先頭に `/` があると、
  実行可能 jar で動かしたときにテンプレートが見つからないことがある。`/` で始まっていた場合は生成せず、
  `## 0.8` の報告の【確認事項】に載せること。

```
コントローラー側                            テンプレート側
└─処理                                      テンプレート：member/list
      └─"member/list"を返す
```
```java
return "member/list";   // → templates/member/list.html
```

### 11.2 Model属性名

- コントローラーの `処理` に書かれた「`<名前>`をテンプレートに渡す」「`<式>`を`<名前>`としてテンプレートに渡す」
  「`<式>`を`"<名前>"`という名前でテンプレートに渡す」の `<名前>` を、**変えずに** `model.addAttribute` の第1引数にする（`## 20.2`）。
- フラッシュメッセージの名前を省略した場合は `message` である（`## 20.2`）。
- テンプレート側は `受け取り` ノードに同じ名前を書き（`<説明>：<型> <名前>`）、`${名前}` で参照する。
- **名前の言い換え・複数形化・キャメルケース化を勝手に行ってはならない。**

```
コントローラー側                                         テンプレート側
└─処理                                                   ├─受け取り
      └─…の結果をmemberListとしてテンプレートに渡す      │    └─会員リスト：List<Member> memberList
```
```java
model.addAttribute("memberList", ...);
```
```html
<tr th:each="m : ${memberList}">
```

### 11.3 フォームオブジェクト

- **フォームオブジェクトの名前は、型名の先頭の1文字を小文字にしたものに統一する**
  （`MemberForm` → `memberForm`）。コントローラーの引数の変数名、Model の属性名、
  テンプレートの `受け取り` の名前が、すべてこの名前になる。
- コントローラーの引数は `入力内容：@検証 MemberForm memberForm` のように書き、`@ModelAttribute` を付けずに
  `@Valid MemberForm memberForm` として生成する（`## 20.2`）。Spring は、クラス型の引数を自動的に Model に入れ、
  その属性名を型名の先頭を小文字にしたものにする。
- 初回表示で `空のMemberFormを作ってテンプレートに渡す` と書いた場合も、属性名は `memberForm` になる（`## 20.2`）。
- テンプレート側は `受け取り` に `入力内容：MemberForm memberForm` と書き、`th:object="${memberForm}"` とする。
  各項目は `th:field="*{フィールド名}"` で書く（`## 30.5`）。
- **画面を返すすべての経路（初回表示・入力エラー時の再表示）で、フォームオブジェクトを
  Model に入れること。** フォームの引数は自動的に Model に入るため、明示的な `addAttribute` は不要である。

### 11.4 リンクとフォームの送信先

- SPD に書かれたパスは、テンプレートでは必ず `@{…}` で囲む（`th:href="@{/members}"`）。
  コンテキストパスの付加を Thymeleaf に任せるためである。素の `href="/members"` は使わない。
- **テンプレートのリンク・フォームのパスと HTTP メソッドは、コントローラーの `ベースパス` ＋ `マッピング` と
  一致していなければならない。** リンク（`<a>`）は `GET` であり、`POST` のマッピングにはフォームで送る。
  一致しない場合は、推測で合わせずに `## 0.8` の報告の【確認事項】に載せること。

```
コントローラー側                               テンプレート側
├─ベースパス：/members                         └─［フォーム］→ POST /members/{m.id}/delete
└─メソッド：delete
      └─マッピング：POST /{id}/delete
```

**フォームオブジェクトを使わない入力項目**（`## 30.5`）

- オブジェクト名を省略したフォームの入力項目の `<名前>`（`name` 属性）は、送信先のハンドラーメソッドの
  `@パラメータ` の引数の**変数名と一致していなければならない。** 一致しない場合は、推測で合わせずに
  `## 0.8` の報告の【確認事項】に載せること。
- この引数には、**既定値（`= ""` など）を付けることを推奨する。** パラメーターが送られない場合
  （初回表示・チェックしなかった `<checkbox>`・選ばなかった `<radio>`）に `400 Bad Request` にならないためである。
  付いていない場合も、書かれたとおりに生成し、【確認事項】に載せること。

```
コントローラー側                               テンプレート側
└─メソッド：receive                            └─［フォーム］→ POST /test
      ├─マッピング：POST /test                        └─名前＜text＞：name
      └─引数
            └─名前：@パラメータ String name = ""
```

### 11.5 対応が取れないときの扱い

- テンプレートが参照する名前が、対応するコントローラーの「テンプレートに渡す」に無い場合は、
  **推測で補わず**、`## 0.8` の報告の【見つからない名前】に載せること。
  フォームオブジェクト（`## 11.3`）は、引数の変数名が渡した名前になる。
- 逆に「テンプレートに渡す」にあってテンプレートが使っていない名前は、報告の対象としない
  （将来の拡張のために置かれている場合があるため）。
