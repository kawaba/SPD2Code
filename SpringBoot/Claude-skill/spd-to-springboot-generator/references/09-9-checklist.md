### 9.9 生成時のチェックリスト

- [ ] **コードより先に `未記入判定:` の1行を出力したか（`◇判定:` を出す場合はそれより先か。`## 0.3.6`）**
- [ ] **未完成のSPD単位（条件A＝空／条件B＝`★` などのマーカー）を、コメント1行だけに置き換え、コード・雛形・仮の実装を一切生成しなかったか（`## 0.3`・`## 0.4`）**
- [ ] クラス・抽象クラスの骨格を、`フィールド`・`自動生成`・`クラス変数` の**3つとも1つずつ**確認したか（`クラス変数` の確認を飛ばしていないか。`## 0.3.5`）
- [ ] `フィールド：なし`・`引数：なし`・`戻り値：なし` を記入済みとして扱ったか。枝がそもそも無いことを未完成としていないか（`## 0.3.3`）
- [ ] `抽象メソッド:` を、`処理` が無いことだけを理由に未完成としていないか（条件Bだけで判定したか。`## 0.3.3`）
- [ ] SPDブロック内の `※【課題】`・`※【仕様】`・`※【例】`・`※【ヒント】` を、原文のまま残し、実装の根拠にせず、`//` コメントに転記しなかったか（`## 0.1`）
- [ ] SPDそのものを書く・埋める・補う・清書することをしていないか（`## 0.2`）
- [ ] 識別子の修正を、「実在」＋「1〜2文字違いまたは大文字・小文字だけの違い」の**両方**を満たす場合だけに限ったか（`## 0.7`）
- [ ] 生成後の報告ブロックを、該当がある見出しだけ・固定順で1つだけ置き、`【…】` の前後に空行を1行入れたか。3つとも空ならブロックごと省いたか（`## 0.8`）
- [ ] **元のSPDが細切れにされず、そのまま漏れなくコード内のコメントとして残されているか**
- [ ] **SPD全体が1つのブロックコメント（`/* ... */`）として、ソースコードの冒頭（`import` 文の直後・型定義の直前）に配置され、その下にコードが生成されているか（SPDを消してコードだけにしていないか）**
- [ ] 複数のSPDが与えられた場合も、分割せず**冒頭の1か所**にまとめて置いたか（メソッド用・クラス用のSPDをそれぞれの定義の直前に配っていないか。`## 9.10`）
- [ ] SPDの全ノードがコードに反映されているか
- [ ] 制御構造の入れ子関係がSPDと一致しているか
- [ ] 生成した**すべての `else if`** について、対応するSPD行の `◇` の左が `│`（または行頭）であることを確認したか。それ以外の文字（`─` `├` `└` など）が先行していたものは独立した `if` に直したか（`## 9.4`）
- [ ] `◇` が `if` か `else if` かの判定に、桁位置（字下げ）の一致を使っていないか（`## 9.4`）
- [ ] 変数名・型がSPDの指定通りか
- [ ] 出力書式（"〇〇=△△"等）が忠実に再現されているか
- [ ] 例外処理がSPDの指示通りか（握りつぶしになっていないか）
- [ ] try-with-resourcesが使えるリソースで使われているか
- [ ] 不要なフィールドやメソッドを追加していないか
- [ ] Java 21以降の現代的な構文で書かれているか
- [ ] インポート文がpom.xmlの依存ライブラリまたはJava標準ライブラリの範囲内か
- [ ] アクセス修飾子（`+ # ~ -`）・`static`・`final` がSPDの記法通りか
- [ ] 継承（`─⊳`）・実装（`---⊳`）が宣言に反映されているか。インタフェースの `─⊳` を `extends` にしたか。クラスの `─⊳` に2つ以上の型、インタフェースの `---⊳`、レコードの `─⊳` を不整合として指摘したか（`## 9.2`・`## 9.5.2`）
- [ ] getter/setter/toString/等値判定（equals・hashCode）は記載があるものだけ生成したか
- [ ] スーパークラス（`─⊳`）のメソッドのオーバーライド、実装インタフェース（`---⊳`）のメソッドの実装、Objectメソッド（toString/equals/hashCode）のオーバーライドに `@Override` を付けたか（通常の getter/setter は対象外）
- [ ] 等値判定/ゲッター/セッター/移譲メソッドの対象フィールドが `←` の指定（省略時は全フィールド）通りか（`## 9.6.4`）
- [ ] `等値判定` の記載で `equals` と `hashCode` の**両方**を生成したか（`## 9.6.4`）
- [ ] `自動生成` に7種類（コンストラクタ：全引数/コンストラクタ：引数なし/ゲッター/セッター/toString/等値判定/移譲メソッド）以外が書かれていた場合、不整合として指摘したか（`## 9.6.4`）
- [ ] クラス定義で `目的`／`フィールド`／`自動生成` が2回以上書かれていないか（複数あれば指摘。`## 9.5.1`）
- [ ] 旧表記（`属性`／`自動生成のリスト`／`コンストラクタ：オーバーロード`／`equals ←`・`hashCode ←`／`自動生成` 内の種別なし `コンストラクタ`）を、`## 9.2` の別名表どおり黙って読み替えたか
- [ ] `メソッド:`（＝`インスタンスメソッド:`）＝インスタンスメソッド、`クラスメソッド:`＝static の区別が正しいか（`## 9.6.6`。インタフェース・抽象クラスの抽象メソッドは `抽象メソッド:`、`## 9.5.2`・`## 9.5.4`）
- [ ] タイトルが `抽象クラス：` のSPDから `public abstract class` を生成したか（`## 9.5.4`）
- [ ] `抽象メソッド:` を `abstract` 付き・本体なしで生成したか。`処理` を勝手に補っていないか（インタフェース内では修飾子・`abstract` を書かない。`## 9.6.9`）
- [ ] `自動生成` の各行に書かれたアクセス修飾子（例：`# コンストラクタ`）を生成コードに反映したか（`## 9.6.4`）
- [ ] クラス変数・クラスメソッドをクラス定義内ノードまたは独立SPD（`## 9.6.1`・`## 9.6.6`）から生成し、クラス変数をクラス先頭に配置したか
- [ ] 自動生成のコンストラクタは、記載された種類（`：全引数`／`：引数なし`）だけを生成したか。全引数版では継承フィールドを引数に含め、スーパークラス分を `super(...)` に渡したか（`## 9.6.3`）
- [ ] スーパークラスに引数なしコンストラクタが無い場合、`コンストラクタ：引数なし` を生成せず、警告を行コメントとして埋め込んだか（`## 9.6.3`）
- [ ] 自動生成と同シグニチャーの `コンストラクタ`／`メソッド:` 定義がある場合、**自動生成側を抑制してノード定義だけ**を生成したか（`## 9.6.4`）
- [ ] ノード定義同士が同シグニチャーで重複する場合は、生成せずエラーを報告したか（`## 9.6.5`・`## 9.6.6`）
- [ ] `移譲メソッド` の記載がある場合、自作クラス型フィールドの公開メソッド（継承分を含む、Objectメソッド・staticは除く）を移譲したか。自クラスの既存メソッドと重複するものは抑制したか（`## 9.6.8`）
- [ ] メソッド・コンストラクタのヘッダに書かれた `throws <例外型>` をシグネチャに出し、Javadocに `@throws` を書いたか（`## 9.6.6`）
- [ ] `（例外型）を投げる` を `throw new （例外型）(…)` として生成し、子ノードのメッセージを引数にしたか。例外クラスを勝手に作っていないか（`## 9.4`）
- [ ] 受ける `catch` が無い**検査例外**について `throws` を補い、その旨を宣言の直前に行コメント1行で明示したか（非検査例外は補わない。`## 9.6.6`）
- [ ] `※` コメントを構造・処理として解釈せず、対応する位置に `//` コメントとして転記したか（引用符・鉤括弧内の `※` はコメントではない。`## 9.3` ルール6）
- [ ] `λ(引数並び)：式` を、引数1つ（型なし）は括弧なし・0個は `()`・2つ以上または型明記は括弧付きで生成したか（`## 9.4`）
- [ ] `λ(…)：┬` のブロック形式で `{ }` を付け、最後の「〜を返す」処理を `return` 文にしたか。式形式に `return` や `;` を付けていないか（`## 9.4`）
- [ ] メソッド参照への書き換えを、パターンGの4種類に**完全一致する場合だけ**行ったか。演算子を含む本体・引数の順序が違う本体・ブロック形式・型が確定できない `型::メソッド` を書き換えていないか（`## 9.4`）
- [ ] `▽─stream:（コレクション）` を `（コレクション）.stream()` として生成し、子ノードを上から順に1ノード＝1操作のメソッドチェーンにしたか（`## 9.4`）
- [ ] `変数←▽─stream:…`／`変数=▽─stream:…` の代入先の型を、要素型と終端操作から推測して**明示的に**書いたか（`var` で済ませていないか）。変数名はSPDどおりか（スネークケースのみキャメルケースに読み替え。`## 9.4`）
- [ ] `▽─` の右がストリームを返す式（`Files.lines(path)`・`Files.walk(path)` など）の場合、その式をそのままストリーム源として生成したか。SPDに `〇` が無いのに try を足さず、囲んでいるメソッドに `throws IOException` を付けたか。`〇─try:▽─式` の形は try-with-resources にし、`変数←▽─式` の代入文も `try` の中に置いたか（`## 9.4`）
- [ ] `▽` ノードに終端操作が無い場合、不整合として指摘したか。`Collectors` のメソッドを静的インポートしたか（`## 9.4`）
- [ ] `Optional` からの値の取り出しを `get()` ではなく引数なしの `orElseThrow()` にしたか（SPDの「`get` メソッドで取り出す」も読み替える。`## 9.4`）
