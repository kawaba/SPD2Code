### 9.3 読解の基本ルール

**ルール1：先頭行はタイトル**
SPDの最初の行はプログラム名・メソッド名・型名・処理の概要のいずれかである。

**ルール2：階層はインデントで表現**
インデントが深い項目は、直上の親項目に従属する。階層は罫線の縦線（`│`）の位置で判定する。

**ルール3：`└─` は詳細・具体化**
ある処理項目に対する `└─` の子要素は、その項目の**具体化情報**を表すことが多い。

```
├─整数のリストを作成して、変数listに代入する
│    └─要素は(10, 20, 30)
```
→ `var list = List.of(10, 20, 30);`

**ルール4：横方向の `─` 連結は処理の合成**
`├─結果を表示する─ ◇─ numberは6である` のように、`─` で項目をつなぐ場合は、**左の文脈の中で右の制御構造を実行する**意味になる。

**ルール5：明示されていない情報の補完**
SPDに書かれていない以下の事項は、生成側が常識的に補う：
- `import` 文
- `public static void main(String[] args)` などの定型骨格
- 外部リソース（ファイル・DB接続など）のクローズは try-with-resources を優先する
- 例外の再スローや握りつぶしの判断は、SPDの記述に厳密に従う

**ルール6：`※` による1行コメント**
`※` からその行末までは**コメント**であり、SPDの構造・処理内容としては解釈しない。

- コメントは、生成コードの対応する位置に行コメント（`// …`）として転記する。
- **引用符（`"…"`）・鉤括弧（`「…」`）内の `※` はコメント開始とみなさない。**
- 行頭（または縦線の途中）に `※` だけの行を書いた場合、その行は**構造解析上は存在しないものとして扱う**
  （縦線の連結を切らない）。
- コメント自体は、その位置の独立した行コメントとして生成コードに転記する。

```
├─変数int priceにform.getPrice()の値を代入する ※税抜き価格
│  ※ここからは税込み価格の計算
└─priceに1.1を掛けて整数に丸め、変数int taxIncludedに代入する
```
```java
int price = form.getPrice(); // 税抜き価格
// ここからは税込み価格の計算
int taxIncluded = (int) Math.round(price * 1.1);
```
